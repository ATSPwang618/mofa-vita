# 架构总览

## 帧链

```
脚本逻辑分辨率 1920×1080
      │
      ├─ 场景链（默认 480×270，scene_divisor=4）
      │    ├─ 组像素面   (layer group pixel surface)
      │    ├─ 组遮罩面   (layer group mask surface)
      │    ├─ 舞台 stage
      │    └─ 场景 scene（舞台的拷贝 + 转场/幽灵特效）
      │
      ├─ 合成/UI 画布（默认 720×405，CANVAS_SCALE=3/8）
      │    └─ 文字、UI、菜单都画在这一层
      │
      └─ 扫描输出 960×544（内容 960×540，上下各 2 px 黑边，不拉伸）
```

场景链尺寸只由 `scene_divisor` 决定，与画布缩放解耦：画布降到 720×405 时，场景仍按 480×270 渲染。
这样文字清晰度（画布）与场景开销可以分别调节。

## 渲染目标与 pass

Vita 的 GXM 每次只能绑定一个颜色面（`sceGxmBeginScene` 只有一个 `SceGxmColorSurface`），
所以多目标合成必须拆成多个 pass：

| pass 类型 | 作用 |
|---|---|
| `pixel` | 组内图层画进组像素面 |
| `mask` | 组的遮罩形状画进组遮罩面 |
| `composite` | 像素面 × 遮罩面合成到舞台 |
| `stage` | 舞台图层（组外图层直接画） |
| `scene` | 舞台拷贝 + 转场/幽灵效果 |
| `canvas` | UI、文字、菜单 |
| `present` | 画布放大到扫描输出 |

每个 pass 以 `sceGxmBeginScene` 开始、`sceGxmEndScene` 结束。**切换目标前需要一次
`sceGxmFinish`**：实测约 2 ms/次，是重场景的主要成本（见性能文档）。

## 图层组

脚本里的裁剪父节点（STCH 等）对应一个「组」：

1. 组内图层画进 `组像素面`（带各自的混合与规则）；
2. 遮罩形状画进 `组遮罩面`；
3. `fs_group_composite` 采样两张面，按 `group_alpha(pixel.a, mask.a)` 合成到舞台。

因为合成作用于「整组结果」，逐层乘遮罩在数学上不等价（见已放弃方案）。

## 平台层

- `knife-platform-vita/src/gxm.rs`：Rust 侧 FFI 与句柄生命周期。
- `knife/vita/*.c`：GXM 后端实现，编入 `knife-platform-vita` 静态库；
  `effects_backend.inc` 在 `gxm_backend.c` 末尾以单编译单元方式包含，以便访问内部结构。
- 显示：三个扫描缓冲、`sceGxmDisplayQueueAddEntry` + sync 对象做翻页。
- 时钟：启动时请求 ARM/BUS/GPU 444/222/222 MHz，返回值写进日志头（`clock_rc`）。

## 线程与资源

- 主线程：脚本 VM、输入、命令录制与提交。
- 后台读档线程：从归档读取原始字节进 24 MiB 环形缓冲（`ByteStage`），主线程做解码与上传。
  纹理准备从 670 ms/条降到 6 ms/条。
- 内存：`_newlib_heap_size_user = 192 MiB`；ATTRIBUTE2=0x0C 让 MAIN 预算到 365 MiB；
  CDRAM 由后端自行分配并受 64 MiB 上限约束。

## 命令录制与提交

`knife-render/src/vita.rs` 的 `CommandEncoder` 把一帧记录成命令流
（`Begin` / `Draw` / `Copy` / `End`），提交时逐条执行：

- 同目标、无 clear 的连续绘制合并进同一个 pass；
- 绘制前按 (着色器, 混合, 纹理, 参数, 首顶点 haze) 合并相同状态的四边形；
- 执行前根据「谁写过谁采样过」计算每个 pass 是否需要 drain（当前仅用于统计，`pass_need`）。
