# 架构与运行机制

引擎基于 AuroraWright/knife 0.9.4。Vita 使用原生 GXM，桌面保留 WGPU。
场景与合成画布为 960×540，显示到 960×544 屏幕时上下各留 2 像素；
脚本布局坐标保持 1920×1080，纹理物理尺寸由素材头和离线策略决定。

## 模块与执行链

| 目录 | 职责 |
|---|---|
| `knife/knife/src` | VM、舞台、UI、字体、资源与存档 |
| `knife/knife-core` | MZX/MZP、NX、KATL/KIMG 等格式解析 |
| `knife/knife-render`、`knife-render-api` | 绘制命令、共享材质和渲染后端 |
| `knife/knife-platform-vita`、`knife/vita` | 平台接口、原生 GXM、输入、音视频、存储和生命周期 |
| `knife/knife-audio`、`knife-perf` | 混音、计时、优化配置和共享预算 |
| `vita_asset_pipeline` | 离线资源制作、验收及编译元数据同步 |

主执行链为归档/脚本 → VM 与 motion → Stage 绘制列表 → 资源准备与命令录制
→ GXM 提交 → display queue。资源读取/解码与渲染提交分离；请求就绪、GPU 提交和
显示完成是不同事件。入口见 [vita_entry.rs](../knife/knife/src/vita_entry.rs)、
[game.rs](../knife/knife/src/game.rs)、[stage.rs](../knife/knife/src/stage.rs)。

## 渲染与回退

Rust 录制 Begin/Draw/End/Copy，准备成功后执行兼容批次。
双槽顶点 arena、表面读写依赖和 GPU 完成前沿共同保护资源退休与槽位复用；
CPU 更新可以有界更换 owner，旧 owner 在 GPU 完成后释放。

按材质选择专用 shader，覆盖普通混合、完整 PS 操作、Fill/NoAlpha/Haze 和 Group 路径。
当前内嵌 85 个离线 GXP，来源与身份由
[offline_vita_shaders.py](../tools/offline_vita_shaders.py) 检查。
部分程序仍需运行时编译；能力、材质或编译不满足要求时保留完整材质、native fetch
或 snapshot 回退。Fill 仍读取源 alpha，混合顺序和 RGBA8 量化不可随意改变。

Group 的 Pixel/Mask 表面跨写入保留；合并、复用和区域裁剪均要求内容、版本及覆盖条件成立。
Tiled 仅用于通过探针的合格 RGBA8 离屏目标，存储 padding 为 960×544，失败回 Linear。
有限混合融合保持中间量化，不扩展为任意层数合成。

完整开关名称、默认组合和解析以
[optimizations.rs](../knife/knife-perf/src/optimizations.rs) 为准，
交付构建组合见 [配套打包入口](../vita_asset_pipeline/packaging/build-companion.sh)；
不在文档中重复维护逐 bit 表。运行后实际启用和命中需看[诊断日志](06-性能采集与分析.md)。

## 图片、图集与缓存

剧情资源采用 KIMG codec9 原生 UNORM DXT/PVRTC，离线变体按原条目、grade、
亮度/对比度位模式和语言分段匹配。原始顺序与逻辑坐标保留。
raw、未覆盖的调色和特殊材质仍可能展开 RGBA。

KQTL 大图块使用 504 像素核心和 4 像素边缘保护，按可见区域延迟注册；
复杂 Haze、mask 或 UV 组合可能使用低内存 fallback。70% 及固定 PVRTC 选择见
[资源制作](10-Switch原版资源提取.md)，不对所有图片统一缩放。

选定 UI 使用 raw KATL 成员范围读取，避免整图集解压；名字保留 NXZ 后缀时也可能是直接布局。
ByteView 共享 owner，活跃请求和 GPU 在途引用受到保护。
预取窗口、转场前瞻、调色结果、Stage 前缀、Group、UI pass 和电影帧均受版本与字节预算约束。
字形使用有界 R8 页，排队绘制引用在退休前不能覆盖。

预算唯一来源为 [memory_budget.rs](../knife/knife-perf/src/memory_budget.rs)：

| 项目 | 预算 |
|---|---:|
| CPU 源 / 调色结果 / 声音缓存 | 64 / 32 / 16 MiB |
| 音频单准备任务 / 已准备音频 | 40 / 16 MiB |
| GPU 资源 / 源纹理 / 文字 | 56 / 32 / 12 MiB |
| Group / Stage 前缀 / Target ring / Movie | 12 / 3 / 6 / 3 MiB |
| CPU 压力 / 回收目标余量 / GPU 压力余量 | 32 / 48 / 8 MiB |

这些是准入或回收门槛，不能相加当作常驻内存。堆余量、CDRAM 读数和最大连续空闲块
也不能互相替代。基础剧情条目的整图 RGBA 离线预算为 1 MiB；
新增变体和分块另按其合同检查。

## 音频与失败恢复

音频是 Ogg Opus，封装在 `voice.mrg`、`bgm.mrg`；
索引负责成员范围读取，流式解码与混音分离。BGM 预读及预备首段 PCM 后交接，
配合 `M10.bgmstart.mrg`，不进行整包 AT9 迁移。
存档预览由独立 `savethumb` 归档提供。

类型化分配压力触发有界回收与重试，同时保护当前帧、必要剧情层和在途 owner。
缺文件、损坏数据及非内存错误不会伪装为成功。
最终失败时，若存在最近成功显示且可保存的节点，尝试事务写入自动槽 122；
手动/快速槽保留。只有日志 `resource_checkpoint.status=saved` 才代表保护成功。
持续超预算、写盘失败或设备故障仍可能无法恢复，见[验证边界](07-已知限制与未验证项.md)。

阅读字号在逻辑坐标内重排当前页，复用文字预算，不缩放整张画布。
操作和持久化规则统一见[安装与设置](08-素材与安装.md)。
