## 1. 项目定位与上游基线

mofa-vita 是《魔法使之夜》（Witch on the Holy Night，Switch 版）引擎的 **PS Vita 移植**：Rust 引擎 `knife` + Vita 原生 **GXM** C 后端；桌面调试使用 WGPU 后端。项目基于 [AuroraWright/knife](https://github.com/AuroraWright/knife) 0.9.4，本地在上游基础上加入了 KIMG/KATL 纹理、Ogg Opus、960×540 画布、native 540p MP4 与 Windows 构建/QA 支持（`knife/UPSTREAM.txt:1-6`）。

正式发布形态（`README.md`、`knife/README.md:16`）：

| 项 | 值 | 依据 |
|---|---|---|
| TITLE ID | `KNIF00540`（540p 唯一正式包；270p 遗留档位 `KNIF00270` 已移除） | `knife/knife/src/vita_entry.rs:41-44` |
| 语言 | 固定中文 ID2 | `vita_entry.rs:325` |
| 分辨率 | scene/composite 固定 960×540；scanout 960×544（上下各 2 px letterbox） | `knife/knife-render/src/vita.rs:31-35`、`knife/vita/gxm_backend.c:32-36` |
| 素材 | native540 codec9 全剧情图库清晰度更新 + 开机感谢页；清单 SHA-256 `97e0ebd7…879a` | `README.md`、`knife/knife-platform-vita/src/asset_profile_540p.rs:2`、`tools/credit-intro/` |
| 编译无需素材 | 素材由使用者自行准备，不入库 | `README.md,36` |

原 270p 变体（`KNIF00270`、`assets-540p` feature 关闭分支、`asset_profile_270p.rs` 与相关工具）已在本次移除，当前代码只有 960×540 一条构建/素材链；旧 270p 素材与 540p 素材不能混用（见 [08-素材与安装](08-素材与安装.md)）。

## 3. Vita 运行入口与帧循环

Vita 的 `main()` 直接转到 `vita_entry::run()`（`knife/knife/src/main.rs:922-925`）。启动顺序（`vita_entry.rs:319-416`）：

1. 安装 panic hook、固定中文语言、读取开发帧数限制；
2. 请求标准频率 **ARM 444 / BUS 222 / GPU 222 MHz** 并记录返回码（`:329-338`）；
3. 读取 `optimization-profile.txt` 或默认全部已实现优化（`:342-349`）；
4. 可选打开性能日志、启动 watchdog（`:353-361`）；
5. 校验素材 profile（37 个关键文件、4,554,933 B 读取；`:362-378`）；
6. 打开归档/语言、创建 GXM、Renderer、字体、Game、UI、输入（`:379-408`）；
7. 进入无限帧循环（`:419-522`）。

每帧按固定阶段推进（阶段名供 watchdog/审计使用，`knife/knife/src/vita_watchdog.rs:5-15`）：

| 阶段 | 动作 | 依据 |
|---|---|---|
| 记录/计时 | frame 计数、上一帧 wall、性能窗口 begin | `vita_entry.rs:420-427` |
| INPUT | 轮询 Vita 手柄/前触屏 | `vita_entry.rs:428-431`、`vita_input.rs:1-45` |
| STORY_INPUT | 推进消息/选择/快进 | `vita_entry.rs:439-442` |
| GAME_UPDATE | 脚本、舞台、过场、影片 | `vita_entry.rs:443-446` |
| UI_UPDATE | 系统菜单/存档/回想等 | `vita_entry.rs:448-451` |
| AUDIO_FLUSH | 把已解码 PCM 交给混音/AudioOut | `vita_entry.rs:452-455` |
| RENDER | 记录并提交整帧命令、present | `vita_entry.rs:460-463`、`game.rs:6665-6915` |
| CACHE_MAINTENANCE | 图像/调色/组缓存维护 | `vita_entry.rs:465-466` |
| PERF_LOG | 每 5 s 汇总输出 | `vita_entry.rs:467-481` |
| PACER | 以 16.667 ms 为目标的睡眠 | `vita_entry.rs:518-521` |

更新与绘制是分离的：更新阶段只改游戏状态（`step` 被限制 ≤100 ms，`:426`），绘制阶段由 `Game::render` 统一录制（`game.rs:6665`）。桌面入口用 winit 事件循环实现同样的 `frame()` 顺序（`main.rs:449-612`）。

## 4. 线程模型

GXM 上下文只能由创建它的**主线程**使用：`Gxm` 用 `PhantomData<Rc<()>>` 禁止跨线程（`knife/knife-platform-vita/src/gxm.rs:138-146`），Renderer 的 `Device` 注释明确“owner 与 texture 都不得离开创建线程”（`knife-render/src/vita.rs:328-330`）。其余工作线程只做 I/O、解码与观测：

| 线程 | 职责 | 边界 | 依据 |
|---|---|---|---|
| 主线程 | 输入、脚本/更新、命令录制、GXM 提交、present | 唯一 GXM 使用者；`begin_batch`/`plan_scene`/draw/present 都在此 | `vita_entry.rs:419-522`、`gxm.rs:138-146` |
| image worker | 单线程有界 CPU 工作：读归档、解压、软件解码 | 请求只含 locator/名字，不含已解码像素或 GPU 句柄；窗口上限 32 | `knife-platform-vita/src/image_worker.rs:1-15` |
| audio stream worker | 每条流独立线程（≤8 通道），解码/文件所有权留在 worker | 混音只轮询就绪 PCM，不 join 活动 IO | `knife-audio/src/stream_pump.rs:9-15,54-64` |
| AudioOut worker | 唯一的 SceAudio 端口；阻塞 SDK 调用不占 GXM 线程 | 48 kHz、960 帧/块、4 块队列 | `knife-platform-vita/src/audio_output.rs:1-18` |
| console worker | 有界日志传输；渲染线程只交批 | 单批 ≤96 KiB、队列 ≤192 KiB/3 批；printf 只在此线程 | `knife-platform-vita/src/console_worker.rs:1-7,21-44` |
| watchdog | 每 500 ms 观测阶段/帧/脚本进度与 native 状态 | 只读 relaxed 原子，不碰 GXM/锁 | `knife/knife/src/vita_watchdog.rs:1-3,131-186` |

SDK 自带的解码器（SceJpeg、SceAvPlayer）和 JPEG 临时 CDRAM 由 native 侧串行管理（`knife/vita/jpeg_hw.h:7` 预留 3 MiB；`movie.rs:1-3` 说明 AvPlayer 帧仍是原生 GXM YUV 表面）。资源 worker、缓存与预算详见 [04-资源调度与缓存](04-资源调度与缓存.md)。

## 5. 渲染目标与坐标系

代码同时存在 5 套坐标/尺寸，不能混用：

| 空间 | 尺寸 | 用途 | 依据 |
|---|---|---|---|
| 脚本坐标 | 480×272，中心 (240,136) | 原引擎脚本/舞台指令 | `knife/knife/src/stage.rs:11-20` |
| 图像度量 | 640×362 单位 | 图片显示尺寸/中心（`Image`） | `stage.rs:14-16`、`knife/knife/src/assets.rs:50-57` |
| 画布 | 1920×1080 | 所有 `Quad` 的布局坐标 | `knife-render-api/src/lib.rs:5-6`、`ui.rs:23-24` |
| 物理 scene/composite | 960×540（正式版） | 实际渲染目标像素 | `vita.rs:3324-3334`、`gxm_backend.c:32-36` |
| 扫描输出 | 960×544，内容 540 + 上下各 2 px | Display 帧缓冲 | `gxm_backend.c:32-36`、`README.md` |

转换关系：`script_to_px()` 把脚本 480×272 映射到画布 1920×1080（`stage.rs:18-20`）；`scene_size()` 用 `CANVAS_W / RENDER_W = 2` 把画布折半为 960×540（`vita.rs:3330-3334`）；`composite_physical()` 同样取一半（`:3326-3328`）；present 只把内容区画进 960×544 的 (0,2) 起点（`effects_backend.inc:795-812`）。`Quad`/画布的布局坐标始终是 1920×1080（`vita.rs:31-35` 注释；脚本坐标只是绘制内容的前端单位）。

渲染目标（`Game` 初始化，`game.rs:1160-1195`；组目标按需创建 `:6571-6580`）：

```
stage_rt(960×540) ──draw stage layers──► optional group pixel/mask targets
      │                                        │（组融合：一次全屏 draw 写回）
      ├─ direct-stage（无 ghost/focus/trans）──► canvas? ──► blit/transition
      └─ copy ─► scene_rt(960×540) ───────────► canvas_rt(960×540)
                                                   │ + UI/text/menu blur/freeze
                                                   ▼
                                         present_canvas → 960×544 scanout
```

源纹理物理尺寸独立于上述画布：长图可保留画面外像素，单边最多 2048，总像素最多 1,036,800。详见 [素材与安装](08-素材与安装.md) 与 [quality540](../tools/quality540/README.md)。

## 6. Pass 模型

一帧由若个 render pass 组成；切换 target 的成本远大于 draw 本身（代码注释记录单 pass 约 8–20 ms，`game.rs:6362-6364`、`vita.rs:1987-1989`），因此所有 pass 级优化都围绕“减少 Begin/End 与中间 copy”。

| pass/操作 | 目标 | 内容 | 依据 |
|---|---|---|---|
| previews | 缩略图目标 | 存档/回想预览 | `game.rs:6686`、`:7519` |
| snapshot/old frame | `old_rt` | FADS 转场捕获旧帧 | `game.rs:6687-6695` |
| noise | `noise_rt` | 噪点层 | `game.rs:6696-6706` |
| stage | `stage_rt` | 舞台图层；可整体复用或 direct-stage | `game.rs:6715-6735`、`:6270-6283` |
| group | `group_rt`（pixel/mask 双目标） | 图层组 pixel/mask 表面 + 合成 | `game.rs:6347-6560`、`vita.rs:2225-2271` |
| PS | 当前目标 | 24 种目标色读取混合；snapshot 或 fetch | `vita.rs:1951-1973`、`:2049-2068` |
| copy | 任意纹理 | 同 context 的 GPU 纹理复制 | `vita.rs:828-832`、`effects_backend.inc:746-793` |
| scene | `scene_rt` | stage→scene 复制/转场/ghost/focus | `game.rs:6726-6773` |
| canvas | `canvas_rt` | scene 上交、UI、文字缓存、菜单模糊、冻结 | `game.rs:6761-6904` |
| present | 扫描输出 | 最终 960×544 letterbox 显示 | `effects_backend.inc:795-812`、`gxm_backend.c:616-654` |

`CommandEncoder` 会把相邻、状态完全相同的 `Draw` 合并（`vita.rs:874-925`）；同一目标连续绘制共用一个未关闭 pass（`:704-706`、`:808-812`）。
