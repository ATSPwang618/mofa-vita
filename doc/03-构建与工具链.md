## 常规入口

```bash
python3 tools/build-vita.py --check
python3 tools/build-vita.py game release
```

Windows 本机使用直接 WSL 入口；包装器的 Windows 路径转义曾失败，不将其作为已验证入口：


## 产物与构建行为

- 正式交付固定为 `release/mofa-vita.vpk`、`release/eboot.bin`。包检查通过且两份 EBOOT 一致后才替换交付文件。
- `.work/vita/game-release-540p/` 保留 ELF/map、SFO、内部 VPK 和构建收据。最近旧程序回退在 `.work/package-large-image-20261117/previous/`。
- 当前游戏包通过 `vita-make-fself -s -c` 生成压缩 SELF；压缩程序不改变纹理编码或分辨率。
- `KNIF00540`、`ATTRIBUTE2=12`；newlib 堆为 256 MiB。扩展 MAIN 属性不等于整个 365 MiB 都可用作堆。
- release 无运行帧数上限，使用生产存档，默认日志开启；DEV 探针具有独立用途，不覆盖正式游戏 EBOOT。
- 构建会检查离线 GXP 与依赖身份；实际资源在设备外部读取，编译不要求整套游戏数据。
- `KNIFE_VITA_OFFLINE=1` 禁止下载；缓存缺失时应明确补依赖。ARM 缓存缺省在 WSL `~/.cache/knife-vita`，不属于仓库占用。

宿主测试需要桌面依赖，不能代替 GXM 像素检查。原生池/压缩/复制、材质输入等变更还应跑相应 `tools/test-vita-*.sh`；固定回放生产入口已移除，不能要求新包读取 `gpu-replay.txt`。

`generate_vita_asset_profile_540.py --assets <配套assets> --check` 已支持直接读取 `voice.mrg/bgm.mrg` 成员，无需解包散装stream。默认输入仍为100%包，最终包必须显式指定 `dist/Witch-on-the-Holy-Night-Chengkong-540p-Vita-70pct-PVRTC2-4bpp/assets`。此检查只覆盖启动关键文件和音频代表项，不代替完整清单SHA核验；制包顺序与验证区别见 [10 提取教程](10-Switch原版资源提取.md)。

## GitHub Actions

`.github/workflows/vita-release.yml` 在分支 push、`v*` 标签或手动触发时构建；标签流程发布，普通构建上传产物。它收集 `release/` 下两个正式文件及收据。

2026-11-17修正：工作流显式传入上文完整R10配置，默认启用55项、mask `0xcffffcfdfffffff`，同时开启性能控制台日志并关闭quiet。版本号采用`r10-ci-运行ID-重试次数-提交SHA`，避免所有日志都只标为`main`。打包后、上传前对照收据48校验profile、mask、完整开关集合、版本号及日志状态；任一不一致即失败，不上传配置不匹配的包。

此配置修正不改变通用本地构建脚本的`hardware-test`默认值。设备上的`optimization-profile.txt`仍会覆盖程序默认值，实机比较前需核对启动日志中的有效配置。修正前的Actions运行`44061620294`产物仍为40项基础配置，不会因修改工作流自动更新；新配置须由包含修正提交的新运行生成，是否成功以对应云端记录为准。
