# 构建与工具链

从仓库根目录执行。Vita 引擎构建需要 VitaSDK、Rust `nightly-2026-05-28`、
`rust-src` 和匹配的原生依赖；Windows 通过 WSL 构建，本机发行版为 `pocket-ubuntu`。
资源转换在 Windows Python 下执行，依赖见[资源制作](10-Switch原版资源提取.md)。

## 按交付清单构建 VPK

完整资源发布后会自动同步实际清单及三个编译索引。构建前可单独检查：

```powershell
python vita_asset_pipeline/build_binding.py --check
```

配套入口采用当前交付的完整优化组合，复用主分支编译、链接和 SELF 签名流程：

```powershell
wsl -d pocket-ubuntu -- bash /mnt/d/AI-CODEX/mofa-vita/vita_asset_pipeline/packaging/build-companion.sh
```

其他检出位置需相应调整路径。入口见
[build-companion.sh](../vita_asset_pipeline/packaging/build-companion.sh) 和
[finish_companion.py](../vita_asset_pipeline/packaging/finish_companion.py)。
它要求默认交付目录已有通过验收的资源，输出：

| 路径 | 内容 |
|---|---|
| `dist/mofa-vita.vpk`、`release/mofa-vita.vpk` | 同一份安装包 |
| `release/eboot.bin`、`dist/ux0/app/KNIF00540/eboot.bin` | 同一份程序 |
| `dist/companion-binding.json` | 清单、VPK 和程序身份 |
| `.work/vita/game-release-540p/` | ELF/map、SFO、内部包和构建收据 |

标题 ID 为 `KNIF00540`，`ATTRIBUTE2=12`，压缩 SELF 由 `vita-make-fself -s -c` 生成。
配套 VPK 不内置 Sony 着色器编译模块，保留现有嵌入 shader 和设备外部编译器查找路径。

## 引擎开发与验证

```bash
python3 tools/build-vita.py --check
python3 tools/build-vita.py game release
python3 tools/offline_vita_shaders.py --check
```

通用构建不要求完整游戏数据，但仍检查提交中的清单绑定、shader 和工具依赖。
它默认使用 `hardware-test`，不等同于配套入口的完整组合，打包策略也独立维护。
复现指定交付时使用配套入口；新版本设置唯一 `KNIFE_BUILD_TAG` 并保存构建收据。
`KNIFE_VITA_OFFLINE=1` 禁止下载，依赖未缓存时需先补齐。

宿主回归按改动选择，完整 Rust 检查为：

```bash
RUST_TEST_THREADS=1 CARGO_TARGET_DIR="$HOME/.cache/mofa-vita-host" cargo +nightly-2026-05-28 test --manifest-path knife/Cargo.toml --locked -p knife -p knife-render -p knife-perf -p knife-core -p knife-audio -p knife-platform-vita
```

GPU 内存、上传或复制逻辑变更还需相应原生测试及实机检查。
历史 `gpu-replay.txt` 生产回放入口已删除。
Actions 配置以 [vita-release.yml](../.github/workflows/vita-release.yml) 为准；
其构建策略不能自动套用到本机配套入口。

## 工作目录与维护

- `dist/`、`release/`、`.work/` 和流水线 `.runtime/` 不入 Git。
  保留当前交付、相应 ELF/map，以及仍需续跑的阶段缓存。
- 源码、锁文件、编译元数据、shader、许可和生产配方是必要输入；
  `source_replay` 的历史编码差分不属于可随意清理的缓存。
- 原始 NSP、MOD、密钥、固件及用户存档由使用者保管，清理临时产物不涉及这些文件。
- 清理前确认绝对路径、文件身份、引用与保留需要；不使用全库 `git clean -fdx`。
  新流水线保留工作目录供续跑，没有旧入口的自动清理约定。
- 改动默认留在本地；提交、推送和改写远端历史按用户当次授权执行。
