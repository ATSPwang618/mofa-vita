# 构建与工具链

本文档记录在 `mofa-vita` 目录中实际验证过的构建、打包和校验流程，以及当前产物身份。最近一次更新为 **2026-10-29 的 LiveArea 图片更新**；构建和包检查通过，新版 LiveArea 的实机显示尚未验证。

## 环境

| 组件 | 要求 | 检查方式 |
|---|---|---|
| WSL2 Ubuntu | 用于 Rust/C 编译与打包 | `wsl -d <distro> -- bash -lc 'uname -a'` |
| vitasdk | 提供 `arm-vita-eabi-gcc`、`vita-elf-create`、`vita-make-fself`、`vita-mksfoex`、`vita-pack-vpk` | `ls /opt/vitasdk/bin` |
| Rust 工具链 | Vita 构建脚本显式使用 `nightly-2026-05-28`；`knife/rust-toolchain.toml` 的桌面默认工具链为 `1.99.0` | `rustc +nightly-2026-05-28 -vV` |
| Cargo 依赖缓存 | 构建使用 `--offline --locked`，缓存缺失会直接失败 | 先联网构建一次，或提前 vendor |
| psp2cgc（Windows） | 仅在修改着色器时需要 | `Test-Path D:\unity\PSVITA\sdk\host_tools\bin\psp2cgc.exe` |

## 构建命令

```bash
# GXM 开发探针（无游戏数据，可用于验证工具链）
bash tools/build-vita.sh gxm dev

# 540p 正式引擎包（外部游戏资源另行准备）
KNIFE_VITA_VARIANT=native540 KNIFE_BUILD_TAG=<tag> bash tools/build-vita.sh game release
```

可用变体只有两个：`270p`（旧资源档）与 `native540`（本工程主线）。
没有 `engine` 模式；`game release` 是唯一允许的 release 组合，其它模式只有 dev。

### 关键环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `KNIFE_VITA_VARIANT` | `270p` | 选择打包变体，主线用 `native540` |
| `KNIFE_BUILD_TAG` | 变体名 | 写入性能日志头 `build_tag`，用于区分实机日志来源 |
| `KNIFE_VITA_ATTRIBUTE2` | `12`（540p）/ `0`（270p） | SFO 的 ATTRIBUTE2；`12` = 0x0C，MAIN 预算 256 → 365 MiB |
| `KNIFE_VITA_CACHE` | `/root/.cache/knife-vita` | Cargo 目标目录（与其它构建共用可加速） |
| `KNIFE_VITA_SCENE_PIXELS` | `960,540`（540p） | 编译期场景尺寸 |

### 发布到 release/

构建脚本在自检通过后自动执行：

```bash
RELEASE_DIR="$ROOT/release"
mkdir -p "$RELEASE_DIR"
cp -f "$OUTPUT/$VPK" "$RELEASE_DIR/$VPK"
sha256sum "$RELEASE_DIR/$VPK"
```

实测输出：

```
published knife-vita-game-540p.vpk -> …/mofa-vita/release/knife-vita-game-540p.vpk (4921694 bytes)
c40dcc5922a0d7ae266cab528f2c42772f137698054574887fd4fd03bf81121b  …/release/knife-vita-game-540p.vpk
```

约定：`release/` 只放可安装的 VPK；`eboot.bin`、`elf`、`param.sfo`、构建收据都在

## 图标与 LiveArea 图片

源目录为 `knife/vita/sce_sys/`。`build-vita.sh` 用 `-a "$ROOT/knife/vita/sce_sys=sce_sys"` 将整个目录打进 VPK，`param.sfo` 另行生成。当前模板为 `style="psmobile"`。

| 路径（相对 `sce_sys/`） | 尺寸 | 字节 | 用途 |
|---|---|---:|---|
| `icon0.png` | 128×128 | 11,539 | 应用图标 |
| `livearea/contents/bg.png` | 840×500 | 121,639 | LiveArea 背景 |
| `livearea/contents/startup.png` | 280×158 | 7,043 | 启动按钮 |
| `pic0.png` | 960×544 | 200,610 | 系统启动背景 |
| `livearea/contents/template.xml` | — | 712 | 布局及图片文件名引用 |

四张图片均为索引色 PNG（color type 3），保留为 PNG，由系统界面使用。它们不走游戏的 DXT/GXT 纹理转换，也不受 `scene-mode.txt` 的画布档位影响。

本次修正：

- 模板原来引用 `background.png`，目录中实际为 `bg.png`；现已统一为 `bg.png`。
- 原始 `startup.png` 为 290×164，现按打包契约改为 280×158。只裁去左右各 5 px、上下各 3 px 的全透明空白，保留所有可见像素、alpha 和原调色板，没有缩放或重新量化图片。
- 修改前文件备份位于 `.work/livearea-update-20261029/before/`，原启动图为其中的 `knife/vita/sce_sys/livearea/contents/startup.png`。修改前哈希保存在同级 `before.json`。

启动图尺寸及模板写法参考 VitaSDK 的 [hello_world 示例](https://github.com/vitasdk/samples/tree/master/hello_world/sce_sys/livearea/contents) 和 [psmobile 布局示例](https://github.com/vitasdk/samples/blob/master/pretty_livearea/sce_sys/livearea/contents/template.xml)。

后续只更新系统图片时，重新运行上面的 `game release` 命令并安装新 VPK 即可，无需重新转换 `assets/` 或生成 `asset_profile_540p.rs`。

### 包内容与收据检查

`tools/check-vita-package.py` 检查 SELF 标头、SFO、包路径、图片尺寸与索引色，并核对 XML 的 `image` / `startup-image` 引用是否真的存在。可选的 `pic0.png` 存在时，也必须满足 960×544 的索引色要求。

`tools/vita-build-receipt.py` 的 `source_files` 现包含整个 `knife/vita/sce_sys/`；`package_contents` 记录 VPK 每个文件的未压缩字节数和 SHA-256，`build_tag` 记录本次构建标记。再次构建时，旧收据不会作为新产物收进自身的哈希清单。

本次发布包已核验 ZIP CRC，全部 5 个 `sce_sys/` 源文件与包内成员逐字节一致，包内 `eboot.bin`、`param.sfo` 也与构建目录一致。有效包检查通过；不存在的背景引用、非索引色的 `pic0.png` 两项负向检查均被拒绝。该校验不替代安装后的实机 LiveArea 显示检查。

## 着色器

着色器编译在 Windows 侧（需要 `psp2cgc`），产物是随源码提交的 C 头文件：

```powershell
.\tools\compile-vita-effects.ps1    # effects.cg（17 个入口）-> generated/effects.h
.\tools\compile-vita-shaders.ps1    # 显示/四边形探针 -> generated/shaders.h
```

每个入口编译两次并比对 SHA-256，不一致即失败。**改了 `effects.cg` 却没重编**，
实机仍会使用旧 GXP，症状是「代码改了但画面没变」。

## 故障对照

| 现象 | 原因与处理 |
|---|---|
| `arm-vita-eabi-gcc: not found` | `VITASDK` 未设置或 vitasdk 未安装；脚本默认 `/opt/vitasdk` |
| Cargo 报 `--offline` 找不到 crate | 依赖缓存缺失：联网构建一次，或配置 vendor 源 |
| `ASSETS REQUIRED` | 设备侧资源目录不完整，日志会列出缺失路径 |
| 启动黑屏 | 检查 present 路径的 `sceGxmFinish` 是否被删（必须保留） |
| 着色器改动无效 | 未重编 `generated/effects.h` |
| LiveArea 背景缺失 | `template.xml` 的图片引用必须与 `sce_sys/livearea/contents/` 内的文件名一致；本工程使用 `bg.png` |
| `invalid indexed LiveArea image` | 检查报错图片的尺寸和 PNG color type；启动图 280×158，`pic0.png` 960×544，均要求索引色 PNG |
| VPK 装不上 | `param.sfo` 的 TITLE ID/APP_VER 与设备已有版本冲突，卸载旧包再装 |
