# 构建与工具链

[项目根 README](../README.md) 是当前安装与运行入口。本文说明换电脑后如何编译，以及维护着色器和素材元数据所需的依赖。所有命令均在仓库根目录执行。

## 本地环境检测与构建

先安装 Python **3.9 或更新版本**，再运行：

```bash
python3 tools/build-vita.py --check
python3 tools/build-vita.py game release
```

`--check` 只读检查环境，不安装工具或编译。普通构建会自动安装缺失的 rustup、固定 nightly 及 `rust-src`；先准备 Rust 而不编译可使用 `python3 tools/build-vita.py --setup`。VitaSDK 核心及原生构建工具仍需在本机准备。

Linux 和 macOS 使用可在当前宿主运行的 VitaSDK。Windows 可使用 `py -3` 代替 `python3`；入口检测 WSL 并转换项目路径。使用 WSL 时，Rust、VitaSDK 和原生构建工具均须位于所选 WSL 环境。

| 用途 | 配置 |
|---|---|
| Vita Rust | `nightly-2026-05-28` 与 `rust-src`，缺失时自动安装 |
| 目标平台 | `armv7-sony-vita-newlibeabihf` |
| SDK 核心 | 可执行的 GCC、newlib、平台头文件及 stubs、VitaSDK 打包工具 |
| 原生构建工具 | CMake ≥ 3.20、Ninja、Python ≥ 3.9、Bash、Git |
| 随仓库提供的目标端依赖 | png、jpeg、z、opusfile、opus、ogg、taihen 七个静态库与头文件 |
| shader 运行时 | 仓库中的 `knife/vita/vendor/shacccg/libshacccg.suprx` |
| shader 扩展 | 仓库中的 `knife/vita/vendor/shacccg-ext/` 静态库与头文件 |

七个静态库位于 `knife/vita/vendor/dependencies/lib/`，对应头文件位于同目录的 `include/`；构建使用这些仓库文件，**无需向 SDK 另行安装 png、jpeg、ogg、opus 或 taihen 等库**。这些依赖不代替 GCC、newlib 和平台 stubs。

可通过 `VITASDK` 或 `--sdk /absolute/path/vitasdk` 指向本机 SDK。Vita 构建显式选择 nightly，并通过 `-Z build-std=std,panic_abort` 构建标准库；工作区的 Rust 1.99.0 是桌面默认工具链，不是额外的 Vita 编译要求。首次 Rust 安装与 Cargo 构建需要联网；已有完整工具链及 Cargo 缓存时才使用 `KNIFE_VITA_OFFLINE=1`，该选项也会禁止下载缺失的 Rust 工具链。

需要明确指定环境时，可使用：

```bash
python3 tools/build-vita.py --native --sdk /absolute/path/vitasdk --check
python3 tools/build-vita.py --setup
```

Windows 选择指定 WSL 发行版的例子：

```powershell
py -3 tools/build-vita.py --wsl Ubuntu --sdk ${VITASDK} game release
```

已配置好的 Linux shell 也可直接调用底层脚本：

```bash
bash tools/build-vita.sh game release
```

## 构建选项与产物

正式包默认选择 native540，并持续运行。开发游戏包使用独立存档目录且默认限制运行帧数，日常运行使用 `game release`。

| 选项 | 用途 |
|---|---|
| `--check` | 只读检查工具链与仓库依赖，不安装、不编译 |
| `--setup` | 只安装缺失的 rustup、固定 nightly 与 `rust-src` |
| `--sdk PATH` / `VITASDK` | 指定 SDK；未指定时自动探测 |
| `--native` | 使用当前 Linux/macOS 环境 |
| `--wsl DISTRO` | Windows 指定 WSL 发行版 |
| `KNIFE_BUILD_TAG` | 自定义构建标记 |
| `KNIFE_VITA_OFFLINE=1` | 禁止 Cargo 联网，要求已有完整依赖缓存 |
| `KNIFE_VITA_QUIET=1` | 正式版默认值，关闭性能采集输出 |
| `KNIFE_VITA_QUIET=0` | 构建带控制台性能采集的版本；性能信息不写设备日志文件 |

例如在 Linux shell 中构建带标记的正式包：

```bash
KNIFE_BUILD_TAG=my-build python3 tools/build-vita.py game release
```

`KNIFE_VITA_QUIET` 是编译期选项，修改后需要重建并重新安装 VPK。

构建会把 Rust（包括标准库）及原生 C 的源码、缓存、工具链路径映射为 `/source`、`/cargo`、`/rustup`、`/build` 等虚拟路径，避免将个人目录写入 ELF 或 VPK。Python、Bash、CMake、Ninja、Rust 和兼容的 VitaSDK 核心仍是正常的工具链要求；项目不依赖指定用户名、WSL 发行版、Docker 镜像或仓库外的私有库。

签名前还会去除预编译 SDK 带入的调试段，并将继承的 C 断言源文件名脱敏；代码段、符号地址及设备路径保持不变。Cargo 缓存里的原始 ELF 仅供本机调试，不作为发布文件。

| 路径 | 内容 |
|---|---|
| `release/knife-vita-game-540p.vpk` | 正式安装包，TITLE ID `KNIF00540` |
| `.work/vita/game-release-540p/` | ELF、VELF、eboot、SFO、链接映射与构建收据 |
| `.work/logs/vita/` | 构建日志 |

成功打包前会检查 VPK 内容，并记录源码、生成文件和包内文件身份。保留对应 ELF 与构建收据，以便核对实际安装版本。`release/`、`.work/` 和游戏素材不属于源码提交内容。

## 仓库内的原生依赖

游戏 VPK 使用仓库中的 `libshacccg.suprx`。打包脚本检查其长度为 **1,776,523 字节**，SHA-256 为：

```text
0c58b5d3e1cc47d9837b8c59ab6f3c299bfe7adf55a83f547d553f9fbb776552
```

编译器模块打包至 `sce_module/libshacccg.suprx`，用于设备首次遇到缺失的 shader 缓存时编译，之后复用落盘缓存。普通构建无需手动提供插件路径。

SceShaccCgExt 扩展的来源和 GPLv3 许可保存在 [NOTICE](../knife/vita/vendor/shacccg-ext/NOTICE) 与 [LICENSE](../knife/vita/vendor/shacccg-ext/LICENSE)，构建脚本将声明一并打入 VPK。七个目标端静态库的来源和许可证随 `knife/vita/vendor/dependencies/` 保留，发布时应一同保留依赖文件及其声明。

## 修改着色器和系统图片

修改 `knife/vita/shaders/effects.cg` 后，先更新嵌入的运行时源码，再正常构建：

```bash
python3 tools/generate-runtime-shaders.py
python3 tools/build-vita.py game release
```

运行时缓存身份绑定精确源码与编译器版本，变更后会生成匹配的新缓存。

仓库同时保留基础和效果着色器的预编译 GXP 头文件，普通构建无需离线 Sony Cg 工具。若修改基础着色器或需要更新离线回退版本，须准备 `psp2cgc` 并在 PowerShell 中执行相应脚本：

```powershell
.\tools\compile-vita-shaders.ps1 -Compiler (Get-Command psp2cgc.exe).Source
.\tools\compile-vita-effects.ps1 -Compiler (Get-Command psp2cgc.exe).Source
```

[knife/vita/sce_sys/](../knife/vita/sce_sys/) 是系统图片与 LiveArea 模板的源目录。只更新这些文件后重建 VPK 即可，无需重新转换游戏素材；打包检查会验证图片格式、尺寸与 XML 引用。

## 更新素材元数据

编译所需 profile、图集索引和音频文件索引已在源码中，**普通构建不读取外部游戏素材**。当前匹配的素材清单、设备目录与安装要求见 [README](../README.md#素材与画面)。完整素材由使用者自行从游戏数据及相应汉化资源准备，不能用原始 Switch 文件或旧 codec8 素材替代当前 native540 codec9 包。

若自行修改素材，应先完成转换、更新 `vita-540p-assets.json` 中的大小及内容校验，再用完整最终 `assets/` 重新生成以下三项。将命令中的 `/absolute/path/assets` 换为实际目录；这些步骤需要素材，普通 VPK 构建不需要。

```bash
python3 tools/generate_vita_asset_profile_540.py \
  --assets /absolute/path/assets
python3 tools/generate-vita-atlas-index.py \
  /absolute/path/assets knife/knife/data/vita_atlas_index_540p.rs
python3 tools/generate-vita-stream-index.py \
  /absolute/path/assets/vita-540p-assets.json \
  knife/knife/data/vita_stream_index_540p.txt
```

重新构建 VPK，并将修改后的素材与对应 VPK 一起更新到设备。上述生成器仅写入元数据，不会把游戏图片、音频或字体嵌入源码。
