# 资源调度与缓存

## 图片与UI

当前剧情彩色纹理主要使用原生UNORM DXT1/DXT5（KIMG codec9，GXT封装）。合格路径直接上传压缩块；CPU调色、raw、语言strip等特殊路径仍可能展开RGBA，不能宣称所有图片永不展开。PNG/JPEG保留在部分UI等资源中。

离线预处理已对20,181个潜在RGBA大图实施尺寸限制（19,662 DXT、519 PNG）；另8,423个剧情彩色条目原本满足限额。完整RGBA按行距/页计费单图≤1MiB，保持逻辑坐标、条带、alpha与完整长图内容。此限制是单图合同，不是同时驻留总量保证。可编辑PNG工程保留较高分辨率输入，部署须重新应用限额。

r11把DISP/MENU/SAVE/CONF/TITLE及Extra等选中UI入口改为raw KATL成员读取，979个成员逐字节验证，18个原压缩入口改变外层布局；全部索引1043项。条目名可仍为NXZ，不能仅按扩展名判断是否压缩。DISP从必需申请16.75MiB整图集输出，变成读取约1MiB以内的单成员编码范围；这不是总解码/GPU峰值只有1MiB。存储代价58.93MiB，成员图像不重编码。

ByteView共享owner，首次worker数据移交上传不重复整块复制。临时分配/预算失败有类型、需求时冷缓存回收后有界重试；数据损坏与工作线程panic不伪装成功。活跃任务、被引用owner和未完成GPU资源不得强制删除。

## 缓存、预取、字体

- 共享源缓存按字节准入、按archive身份+索引定位；header/tiny读缓存只保存完整校验结果。
- 一个有界图像worker，真实需求优先于投机预取；generation隔离旧请求。动画只预取窗口，避免整段解码驻留。
- 调色kernel、基础灰度曲线与完整结果分别缓存，相同key复用；颜色域/grade参数/语言strip纳入身份。
- 静态Stage前缀、组producer、UI pass与电影帧缓存受内容版本和预算约束；不是无限增加缓存层。
- 字形使用有界R8页、保留排队绘制引用、仅上传有效行；文字run缓存减少重复排版/绘制。不能为释放旧页而覆盖GPU仍在采样的字形。
- old-frame、菜单捕获与缩略图目标按可选/必需用途处理分配失败，借备用目标、有限回收重试；失败不直接panic，也不保存半完成状态。

## 音频

当前运行资源为Ogg Opus，不是整包AT9迁移。流式解码和混音分离，BGM预读扩到约1秒以吸收500–700ms补充尖峰；每路比原约200ms多300KiB PCM载荷。通道数与并行类型影响总量；不能把一条BGM增量当作所有音频内存。语音保留原档，真实欠载检查看audio underrun计数。

## 预算

唯一源码基准：[memory_budget.rs](../knife/knife-perf/src/memory_budget.rs)。这些是上限/门槛，不是启动预分配，也不能简单全部相加当作常驻内存。

| 资源 | 上限/门槛 |
|---|---:|
| CPU源 / 调色结果 / 声音缓存 | 64 / 32 / 16 MiB |
| 声音单准备任务 / 已准备音频 | 40 / 16 MiB |
| GPU资源 / 源纹理 / 文字 | 56 / 32 / 12 MiB |
| Group缓存 / Stage前缀 / Target ring / Movie帧 | 12 / 3 / 6 / 3 MiB |
| CPU压力 / 回收目标余量 | 32 / 48 MiB |
| GPU压力余量 | 8 MiB |

CDRAM空闲、堆headroom、最大连续空闲块不是同一指标。r10失败曾发生在CPU NX输出申请阶段，即使headroom较大也不能保证连续大块申请成功。[优化证据](05-优化记录与实测数据.md)保留该故障与r11修复范围。
