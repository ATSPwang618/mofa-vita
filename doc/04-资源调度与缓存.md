## 1. 资源对象与生命周期

### 1.1 入口：Assets

`Assets`（`knife/knife/src/assets.rs:336`）持有归档、脚本表与全部资源侧缓存/线程：

- `byte_stage: Arc<ByteStage>`（`:350`）——旧路径的 24 MiB 后台读缓冲，仅在 `shared-atlas` 关闭或兼容路径使用；
- `atlas_cache: Arc<atlas_cache::AtlasCache>`（`:352`）——共享 atlas owner 缓存（见 §2）；
- `image_cache: ImageCachePolicy`（`:372`）——GPU 驻留淘汰策略（见 §6.1）；
- `image_worker: BoundedWorker<ImageJob, Option<Decoded>>`（`:374`）——单 CPU 解码 worker，实例化参数 `new(8, 2, ..)`（`:572`，pending 8 / ready 2）；
- `image_context: u64`（`:376`）与 `image_needed: Option<NeededRequest>`（`:378`）——场景/读取档代数与当前 VM 资源需求；
- `stream_resolver: StreamResolver`（`:339`）——语音/音频流名静态索引（见 §6.4）；
- `cpu_cache_pressure: Cell<bool>`（`:354`）——CPU 压力闩锁，阻止回收后立即回填（见 §6.5）。

`Image`（`assets.rs:48`）是主线程持有的纹理句柄 + 逻辑/物理尺寸 + 来源描述；`Assets.images` 以 `image_key(name, bake)`（名字、调色参数、语言 strip）为 key，返回 `Arc<Image>`。

### 1.2 归档 Archive

`Archive`（`knife/knife-core/src/format/archive.rs:122`）由 `.hed/.nam/.mrg` 三件套打开，扇区 0x800（`:27`）：

- 打开后三份文件是**不可变输入**（`:133-137`）；`cache_instance`（`:261`）是该实例的进程内唯一身份，供缓存 key 使用，避免路径/指针复用；
- 单个条目上限：Vita `ArchiveLimits::VITA` stored/unpacked 各 32 MiB（`:38-41`），桌面 256 MiB（`:44-54`）；
- 读取 API：`read`/`read_bounded`/`read_bounded_lengths`/`read_uncompressed_range`（`:326,349,355,380`）与只读 16 B NX 头的 `read_plan`（`:254`，见 §3）；
- Vita 后端统一 `Storage::File`：`File::lock` → `seek` → `read_exact`，分配与锁等待分别计时；桌面可选只读 mmap。

### 1.3 编码字节与像素所有权

- **`ByteView`**（`knife/knife-render/src/byte_view.rs:5-30`）：`Arc<Vec<u8>> + Range`，放进 Arc 只移动指针/长度/容量，不复制 payload；`allocation_len()` 按 `Vec::capacity()` 计费，`is_unpinned()` 用 `Arc::strong_count==1` 判断可淘汰。共享 atlas 的所有子图 range 共享同一个 owner。
- **`PixelOwner`**（`byte_view.rs:33-45`）：`Box<dyn AsRef<[u8]>>`，把任意分配器（含 C malloc）的像素交给渲染器同步上传，C 指针不伪装成 Rust `Vec`。
- **`PixelView`**（`byte_view.rs:47-70`）：`Arc<dyn AsRef<[u8]> + Send + Sync> + Range + allocation`，供调色结果缓存与 strip 视图共享整块像素；按完整分配计费。
- **`DecodedImage`**（`knife/knife-platform-vita/src/image.rs:157`）：C 解码器独占分配，`unsafe impl Send`（`:168`）允许 worker→渲染线程移交，但保持 `!Sync`；`freeze()`（`:246`）转成 `FrozenImage`（`:241`，`unsafe impl Sync`）后只暴露只读字节；析构调用 `kv_image_free`。
- **`Pixels`**（`assets.rs:71`）是 CPU→GPU 的路由枚举：`Bntx`、`Rgba`、`Baked`、`SharedBaked`、`Native{owner,range,srgb,baked}`、`Scaled`、`Reloadable`、`GxtNative`。`NativeSlice`（`:100`）为 owner+range 的 `AsRef<[u8]>` 适配器；`ImageReload`（`:110`）保存可重载 locator（archive/index/encoded_len/grade/strip/initial ByteView）。

### 1.4 DeferredBytes 四态

`knife/knife-render/src/vita.rs:487-560` 定义惰性纹理字节的来源，决定“首次准备”和“驱逐后重载”会不会重新读盘：

| 状态 | 语义 | 首次/重载行为 |
|---|---|---|
| `Retained(Arc<[u8]>)` | 渲染器自己保留编码字节 | 直接使用，不读盘 |
| `Shared{cached owner range}` | 共享 atlas 的 range 视图 | `load()` 向 atlas 缓存借 range，不复制 |
| `Ready{ready: Some(ByteView), load}` | worker 首次 payload 移交 | 先用移交的 payload；成功提交后才 `release_ready`；之后 miss 才走 `load` |
| `Reload{encoded_len, load}` | 只有 locator | 每次准备都按 locator 重读 |

`Retained/Ready` 的字节计入 `GPU_SOURCE_BYTES`（`vita.rs:53` 取 `memory_budget::GPU_SOURCE_BYTES`），`GPU_RESOURCE_BYTES` 另计已上传纹理（`:52`）。

### 1.5 生命周期与取消规则

- 归档/atlas owner/静态索引一经打开视为**不可变**；文件若被外部改写，`read_plan` 与 body 的头一致性校验会拒绝并按失败处理（`archive.rs:296-324`）。
- 所有可淘汰缓存都用**pin 计数**：`ByteView/PixelView::is_unpinned`、`Arc::strong_count==1`；被当前帧命令/队列引用的条目不会淘汰，并且继续占预算。
- 纹理依赖用 `Weak<GpuTexture>`/`Weak<TexRef>` 记录（组缓存、文字缓存、stage prefix），既能阻止“指针被复用后假命中”，又不会把旧动画页钉在 GPU 内存里。
- 异步请求用 generation（`image_context`、worker `context`、atlas job `generation`）：场景切换/读档/seek 后旧结果不得进入新代；失败表按 key 缓存并仅在同代内生效。
- 等待上限统一为 10 s；超时**不重放、不清理活跃 worker**，只把等待者报错（见 §9）。

## 2. 共享 atlas owner 缓存 [代码]

**目的**：UI/图集（`KATL`，内含多个 `KIMG` 成员）整条 NX 解压一次，所有子图以 range 借用同一 owner，避免“取一个 131 KiB 成员却解 20 MiB 整图集”。

**实现**（`knife/knife/src/atlas_cache.rs`；`ByteView` 见 `knife/knife-render/src/byte_view.rs`）：

- 单 worker `knife-atlas`（`:33`，256 KiB 栈），队列最多 4 个 locator（`PENDING=4`，`:11`），需求会把在途 job 提到队首（`:189-207`）。
- key = `(archive.cache_identity(), entry_index)`（`:16`）；容量 `CAP = memory_budget::CPU_SOURCE_BYTES`（`:10`，终版 64 MiB）、最多 512 条（`:12`）、UI 热页软优先 24 MiB（`:15`）。
- 解压前先 `read_plan` 拿到 `decoded_bytes`，只按**真实缺口**回收 LRU（`:50,137-145`）；预留额度后才 `read_bounded_lengths` 读 body（`:72`）；输出容量与 plan 不符则不发布条目（`:74`）。
- `seed()`（`:149-173`）把 worker 已解好的首块并入同一预算池；`prewarm_if_room()`（`:222-236`）只在“无 active/job、未命中、装得下”时排一个不淘汰的预热；`trim_lru(need, include_preferred)`（`:237-251`）供压力维护按“先普通、后 UI 优先”两阶段回收。
- `whole()`（`:266-282`）是唯一会阻塞调用者的入口（需求线程，10 s 上限）；渲染线程只走非阻塞的 `poll()`（`:189-215`）或 `range()`（`:258-262`）。
- 统计：`atlas_load`、`atlas_demand_wait`、`source_cache_hit/miss/seed/prefetch/dropped`，以及 `StageReadyBytes`/`SourceCacheBytes` gauge。

**atlas 元数据索引**：`vita_atlas_index.rs:1-23` 是“按 manifest SHA 绑定的静态表”，登记每个 atlas 的 entry、解压后字节数，以及每个成员的 `offset/len/logical/physical/encoding`（GXT 另带 layout/format/payload 元数据）。它由 `tools/generate-vita-atlas-index.py:1-68` 离线生成（只解析 KATL/KIMG 头与 GXT 封装，不解像素），生成物是 `knife/knife/data/vita_atlas_index_540p.rs`（216,761 B）。登记时只使用这张表，不读/不解压像素（`assets.rs:1574-1585` 校验成员区间后才注册）。
**[历史实测]** r3 同进度：卡读 492→58 次、读取字节 −90.42%、NX range 输出 −94.72%；r4 进一步降到 63 次/7,303,835 B，whole atlas 完成 9 次、淘汰 4 次。完整对照见 [05-优化记录与实测数据](05-优化记录与实测数据.md)。

## 3. archive IO 缓存与 read_plan [代码]

**问题**：每个条目都重读 NX 头；极小的运行文件（语言表、标记文件等）会反复读盘。

- `archive_cache.rs:7-10`：进程级缓存，64 条 header plan + tiny 条目（总 64 KiB、最多 64 项、单项 ≤4 KiB、FIFO）；key 为 `(Archive 实例序号, offset, stored_sectors, unpacked_sectors)`（`:16-19`），与路径/指针无关。
- 只有**完整校验成功**的 body 才允许进 tiny 缓存；CRC/长度/尾部字节失败会 `invalidate`（`archive.rs:333-341,364-371,413`）。tiny 命中会复制一份 ≤4 KiB 的 `Vec`，调用方保持原有 `Cow` 语义（`archive_cache.rs:39-48`）。
- 该缓存由优化开关 `resource-io-cache`（`knife/knife-perf/src/optimizations.rs:22`）控制；关闭时全部直读。

`read_plan`（`archive.rs:254-268`）只读 16 B NX 头，返回 `ArchiveReadPlan { stored_bytes, decoded_bytes }`；`entry_plan`（`:268-320`）先校验头/上限/文件 extent，再缓存 plan；`read_bounded_lengths`（`:355-375`）在执行 body 读取前**再校验一次**头与两个独立上限（压缩输入临时预算 ≠ 保留输出预算）。解压/子范围分别记 `nx_full`、`nx_range`、`range_select_copy`（`:329,360,391,449`）。

## 4. GXT 首用移交、codec9 与 C 解码 owner [代码]

**问题**：旧路径 worker 解码出 GXT 后只登记 reload descriptor 并丢弃 payload，首次 prepare 又回主线程重读一遍（历史实测 20 次/4.178 s，见 05）；灰度图还会扩成 RGBA8。

- **资产 ABI**：`compact.rs:8-20` 定义 `KIMG` 编码：`Jpeg=1`、`Png=2`、`Bc7Srgb/Bc7Unorm=3/4`、`PngUnorm=7`、`GxtAlterSrgb=8`、`GxtNativeUnorm=9`。codec9 的字节按 UNORM 采样（`compact.rs:16-19,79-81`），不能再走 Alter 色彩变换；`GxtNativeUnorm` 只在“非 CPU 调色、非语言 strip、非 raw”时走原生块上传（`assets.rs:2212-2214`）。
- **首用移交**：worker 输出 `Pixels::GxtNative { encoded, source, .. }`（`assets.rs:90`），`source` 是整块 atlas owner，`encoded` 是其中 envelope range；`upload_pixels` 在首用时调用 `defer_gxt_shared()`（`knife-render/src/vita.rs:1452-1457`，`ByteView` + `DeferredBytes::Shared`）或 `defer_gxt_ready()`（`:1444-1449`，worker payload 为 `Ready`）；GPU 淘汰后由 `defer_gxt_altered_reload()`（`:1420-1440`）按 locator 重载。
- **atlas 合并**：首用前调用 `atlas_cache.seed()`（`assets.rs:1402-1410`），之后 GPU 淘汰重载可直接借 range，而不是重解整 atlas。
- **C owner / R8**：PNG/JPEG 解码走 `DecodedImage::decode_bounded`（`image.rs:199-216`）或灰度 `decode_gray_bounded`（`:204-213`），输出 `Pixels::Native` 直接借用上传；语言 strip 用 `range` 视图代替 `copy_within`（`assets.rs:1348-1360`）；R8 仅用于 RAW 灰度源（`assets.rs:1320-1324`）。`DecodedImage` 跨线程移交后由 `FrozenImage` 提供只读共享（`image.rs:241-246`）。
- 统计：`gxt_reload`、`image_reload`、`image_first_upload`、`decoded_c_to_vec`、`language_crop`、`cpu_grade`、`gxt_cpu_decode`。

**[历史实测]** r3：`gxt_reload` 20→0、C→Vec 8,697,280→2,839,680 B（−67.35%）；R8 在 r3/r4 都没有实际样本，**[未验证]**。

## 5. 调色缓存：kernel 与完整结果 [代码]

**问题**：每次 `STEC/SNX*` 都重建 65,281 项灰度 LUT 并对每个像素做浮点插值 + sRGB 编码；一旦 GPU 驻留被驱逐或隐藏层需要重算，就重复 decode + grade。

- **kernel 缓存**（`knife/knife/src/grade_cache.rs`，容量 4 MiB，`:6`）：key 含 build（日/海/魔女）、grade mode、bright/contrast 的 f32 `bits`、raw、source sRGB、native 编码域、所选 table 行 20 个 f32 bit（`:8-33`）。灰度 LUT 复用；非灰度只保留 256 项通道映射。sRGB 编码器在**运行目标**上用原 `srgb_byte` 建立 255 个阈值并做边界校验（`:35-81`，失败则退回旧循环）。pin 中的 kernel 不淘汰（`:127-142`）。
- **完整结果缓存**（`knife/knife/src/graded_cache.rs`，容量 `CPU_GRADED_BYTES`=32 MiB，`:9`）：只缓存已完成的 CPU Bake（PNG/JPEG 含 KIMG），key 再含 archive 指针身份、index、image name、strip（`:18-20`）；保留原 C owner 的 `Freeze`/`PixelView`，不为缓存复制整幅像素。同 key 并发只解码一次，active 预留计费；10 s 等待上限（`:87-102`）；无可淘汰项时退回普通 bounded decode，不突破预算（`:104-109`）。
- 开关 `grade-cache` 关闭时 `Bake::apply` 直接走 `apply_uncached`（`knife/knife/src/grade.rs:331-345`）。

**[历史实测]** r3 有 8 次 CPU grade 共 3.749921 s；r4 日志未执行到 CPU Bake，缓存收益 **[未验证]**（见 [05](05-优化记录与实测数据.md)）。

## 6. 调度、音频与预算

### 6.1 图像 worker 与 demand 通道 [代码]

- `BoundedWorker`（`knife/knife-platform-vita/src/image_worker.rs:85`）只有一个 CPU 解码线程；队列窗口 32 个 key（`WINDOW_LIMIT=32`，`:15`），等待上限 10 s（`:13`）。
- `request_needed/poll_needed/release_needed`（`:204-249`）把“真实需求”和“投机预取”分开：需求插队首、ready 满时只丢投机结果、同一 context 内最多一个真实 demand；新 generation 不能消费旧 active 结果（`:252-288` 的测试覆盖）。
- 所有元数据锁都是 `try_lock`：拿不到就返回 pending，渲染线程不会被 worker 锁阻塞（`:73-75,148-193`）。
- `take_for_timeout`（`:250-288`）只服务于旧兼容调用；超时返回错误并保留活跃解码，不重复提交。

### 6.2 预取窗口 [代码]

`Game::prefetch_images`（`knife/knife/src/game.rs:6585-6651`）每帧组候选：

1. 存档/列表预览缩略图（只预取未缓存项）；
2. 活动 motion 层在 `[0, +1, +2]×FRAME_MS` 三个近未来时刻的 variant（`animation-window` 开启时；`:6613-6633`）；
3. 后续 24 条脚本内的 `STCH/SCH2` 图像（`:6634-6647`）。

候选截断到 32（`:6649`），交给 `Assets::prefetch_window`（`assets.rs:987-1010`）：只对缺失 key 入队，`retain_window` 按 context+窗口裁剪；共享 atlas 开启时对已缓存图像补 `request`（demand=false）。`cpu_cache_pressure` 为真时暂停这类补充（`:994-995`）。
VM 侧还有独立的非阻塞需求状态机 `image_needed.rs`：`poll_image_needed` 每帧推进 source→decode 两步，`Pending` 时调用方回退 pc 并冻结剧情推进，`Failed` 停在原指令；10 s 截止（`:14,55-124`）。

### 6.3 音频独立流通道 [代码]

- 混音在专用 `knife-audio-mixer` 线程（`knife/knife-audio/src/vita.rs:159-186`），命令队列 8 块（`OUTPUT_QUEUE_BLOCKS=8`，`:21`），最多 64 个 voice（`:19-20`）。
- 每条流由 `stream_pump::Pump` 起独立 worker（`knife/knife-audio/src/stream_pump.rs:54-131`）：worker 负责 `open` + 解码到预分配 block 池；mixer 只 `try_recv`（`:133-162`），从不等待文件 IO。
- 常量（`:9-15`）：`FRAMES=960`（48 kHz 下 20 ms）、`QUEUED=10`（≈200 ms 队列）、`BLOCKS=12`、`CHANNELS=8`（硬上限，超限报错）、每通道 92,160 B、8 通道合计上限 737,280 B（与启动头 `audio_stream_pool_ceiling_bytes` 一致，`vita_entry.rs:80`）。block 用后经 `recycle` 通道回送，形成有界环；`Pending` 时 mixer 跳过该流本块，其它轨继续。
- 解码器：`.ogg` 直接走验证型 `AudioStream::open_file`（`vita.rs:532-538`），其余按 magic 分流 Ogg Opus / Nintendo Opus（`:539-552`）。`StreamCursor`（`:582-620`）负责 seek/loop/mono，`StreamSound`（`:651-720`）只做 poll+pan/volume 混合。
- 既有底层：AudioOut worker 与 4 块队列/6 块池/23,040 B（`knife/knife-platform-vita/src/audio_output.rs:10-16`），本次提交未改。
- 统计：`audio_stream_open/prepare/decode/pending/starved/ready/cancelled/failed/limit`，gauge `AudioStreamChannels/AudioStreamBufferBytes`。

**[历史实测]** r4 的 `audio_stream_open` 2 次/142.095 ms 已发生在独立 mixer worker，不能加到主线程 message scope；underrun/长音频是否改善 **[未验证]**（见 05/07）。

### 6.4 流静态索引 [代码]

`vita_stream_index.rs`：编译期嵌入按素材 manifest SHA 绑定的 `# knife-stream-index-v1 <sha>` 名字表（`:6-10`，`knife/knife/data/vita_stream_index_540p.txt`，239,773 B/9,470 个 stream 名），解析时校验排序、`stream/` 前缀、路径段合法（`:13-23`）。`resolve()`（`:32-60`）：加速开启且索引命中时直接返回路径，不做 stat；未命中走 1024 项 memo（`:6`），每个候选最多 stat 一次，且语音复用同一存在性结果。生成器 `tools/generate-vita-stream-index.py:1-15` 只读取 manifest 文件名，不扫设备目录。
**[历史实测]** r4 `stream_resolve` 2 次/0.072 ms、`stream_index_hit` 2、无 `stream_stat`（索引命中已生效）。

### 6.5 预算与压力维护

统一上限集中在 `knife/knife-perf/src/memory_budget.rs:4-17`（单位 MiB，全部是**准入上限，不是预分配**）：

| 常量 | 值 | 用途 |
|---|---:|---|
| `CPU_SOURCE_BYTES` | 64 | 共享 atlas owner 池（含 seed/预热） |
| `CPU_GRADED_BYTES` | 32 | 完整调色结果缓存 |
| `GPU_RESOURCE_BYTES` | 56 | 渲染器已上传纹理的 deferred 预算 |
| `GPU_SOURCE_BYTES` | 32 | 渲染器保留的编码源（Retained/Ready） |
| `GPU_TEXT_BYTES` / `GPU_TEXT_ENTRIES` | 12 / 8 | 文字渲染缓存 |
| `GPU_GROUP_BYTES` / `GPU_GROUP_ENTRIES` | 12 / 6 | 组表面缓存 |
| `GPU_STAGE_PREFIX_BYTES` | 3 | 单个 stage 前缀结果 |
| `GPU_PRESSURE_HEADROOM` | 8 | 预留常量（当前仅渲染器 host 测试引用） |
| `GPU_CACHE_SPARE_BYTES` | 1 | 渲染器准入余量 / 资源维护 GPU 触发阈值 |
| `CPU_PRESSURE_HEADROOM` | 32 | CPU 回收触发阈值（heap_headroom） |
| `CPU_TARGET_HEADROOM` | 48 | CPU 回收目标 |

压力维护入口 `Game::vita_cache_maintenance`（`knife/knife/src/game.rs:8227-8272`，由 Vita 主循环每帧调用、内部每 **120 帧**执行一次）：

1. 查询内核/堆余量（`native.rs:47-60` 的 `kernel_main/kernel_cdram/heap_used/heap_headroom`）。
2. **CPU 压力**：`heap_headroom < CPU_PRESSURE_HEADROOM` 时，按 `need = CPU_TARGET_HEADROOM - headroom` 回收，顺序为 `ByteStage → atlas 非优先 → 调色结果 → 调色 kernel → atlas UI 优先`（`assets.rs:946-963`）；同时置 `cpu_cache_pressure`，回收期间不再补充预取。
3. **CPU 恢复**：余量高于 `48+2 MiB` 时清闩锁，并只对 DISP/NOISE 做 `prewarm_if_room` 的无淘汰预热（`assets.rs:966-985`）。
4. **GPU 压力**：`renderer.vita_cache_headroom() < GPU_CACHE_SPARE_BYTES` 时，依次 `text_cache.trim(0)`、`group_cache.trim(0)`、`vita_reclaim_idle()`，再做一次 0 字节准入探测，仍不通过才 `stage_prefix.clear()`，最后再回收一次空闲驻留（`game.rs:8252-8262`）。
5. 输出 `cpu_reclaim_request`、`cpu_reclaim_freed`、`cache_pressure_trim` 等指标。

**[未验证]** 压力回收的实机顺序/阈值行为没有单独 A/B 日志；文档中的 32 MiB atlas 数字属于 r3/r4 历史口径，终版常量已提升到 64 MiB（见 05 与 07）。

## 7. 文字缓存与字形图集 [代码]

- **文字 run 缓存**（`knife/knife/src/game/text_cache.rs`）：连续 `Text/RimText + Alpha + 无 clip/rule/soft/masked` 的 run，若 ≥8 且 ≤1024 glyph（`:14-15`），并且整段 quad 的 `render_key()` 与上一帧完全相同（`:120-123,138`），则渲染到一张 RGBA8 目标并用一次 `CoverageOver` 合成替代逐 glyph 绘制；最多 8 条/12 MiB（`:143-161`），600 帧 idle、当前帧读者不淘汰（`:16,55-67`）。揭示/淡入/抖动/图集变化/颜色变化都会改变 key；缺少合成 shader 或构建失败时回退原路径（`:132-141,165,178,181`）。接入点 `game.rs:6667,6786,6891`。
- **不可变字形页**（`knife/knife/src/text/atlas.rs`）：Vita 页 256² R8=64 KiB（`:5-8`）；CPU 池 2 MiB / 128 页；`prepare_r8()`（`:153-211`）只在私有零页上排版**缺失字形**，只上传已用行+透明保护行；页一旦发布不可变，排队 quad 各自持有纹理；淘汰按页 LRU 且保护本次请求的字符（`:118-123`）；超大字形/压力回退用独立小纹理（`:142-149`）；空白字形只登记不占纹理（`text.rs:461-512`）。
- **预取**：`FontAtlas::prewarm()`（`text.rs:425`）在页面布局完成后一次性准备整页字符，`prewarm_chars` 每批 ≤1024（`text.rs:461-512`）；`Game` 在消息绘制前对当前页（含隐藏的未来 reveal 字符）调用（`game.rs:5959-5972`）。失败会先 `trim_unrequested` 再重试一次（`text.rs:477-486`）。
- exfont run glyph 使用独立 sheet（`text.rs:218-230`）；字形 UV 使用 `Texture::uv_extent()` 而不是假定页宽（`text.rs:641-648`）。
- 统计：`glyph_page_bytes/entries`、`glyph_shadow_bytes`、`glyph_prewarm`、`glyph_raster`、`text_cache_*`。

**[未验证]** 缓存命中率/像素等价只在 host 测试里验证；r4 出现的整页 rename 复制不能唯一归因到字体页（见 [07-已知限制与未验证项](07-已知限制与未验证项.md)）。

## 8. 组缓存与 stage prefix [代码]

- **组表面缓存**（`knife/knife/src/game/group_cache.rs`）：对“完全 clear 的独立组 producer”做精确 key 记忆（目标 kind/宽高/physical + 每个 quad 的 `render_key()` 全 bit，`:90-99`），命中直接把 immutable 组表面换入 pair，不重放 producer；6 条/12 MiB（`memory_budget::GPU_GROUP_ENTRIES/BYTES`）、180 帧 idle（`:12`）、目标内容版本变化或 `Weak` 依赖失效即淘汰（`:70-83`）；no-clear 写入会 invalidate 对应结果，不能把缓存结果当持久 pair 用（`:178-191`）。预分配走 `prepare_retained`（`:104-162`），压力下优先回收旧 key/已淘汰 spare。
- **组批与调度**：`group_batch.rs:19-50` 只接受“全部 producer 带 clear、stage 写入与 producer 互不别名”的计划，最多 3 组（`groups*2 ≤ GPU_GROUP_ENTRIES`），否则回退原顺序；`group_schedule.rs:8-16` 定义“读写对方目标即屏障”的规则（rule sampler 也算读）。
- **stage prefix**（`knife/knife/src/game/stage_prefix.rs`）：只对 `clear alpha=1、≤64 quads、全部 Alpha/Ps、无 rule/mask、源为 immutable stage 纹理或 white` 的 stage 前缀（`:50-57`）做最长公共前缀记忆（`:59-71`）；结果 ≤3 MiB（`:91-100`），准入失败后 4 帧内不再重试；命中时用 `NoAlpha+Opaque` 全屏 quad 替换前缀（`:118-128`）。
- GPU 侧的 pass/PS fetch/组融合语义见 [02-渲染与GPU后端](02-渲染与GPU后端.md)。**[历史实测]** r4 组 scratch 3→0，但 PS fetch 未启用，EndScene 仍是大头（见 05/07）。

## 9. 错误、超时与回退

| 场景 | 行为 | 位置 |
|---|---|---|
| atlas 需求等待超 10 s | 返回错误；活跃 worker 与 owner 保留，不重放同一读 | `atlas_cache.rs:266-282` |
| atlas 输出超出 CAP / pin 占满 | 明确失败（可重试），不绕过预算逐子图解压 | `atlas_cache.rs:50-63,84-90` |
| ByteStage 兼容等待超 10 s | 返回错误；in_flight 不清、不重复卡读 | `assets.rs:287-310` |
| image worker 同步等待超 10 s | `Err` 并保留 active decode | `image_worker.rs:250-288` |
| VM 图像需求超 10 s | `Failed`，停在原指令并上报 `resource_event` | `image_needed.rs:14,80-82` |
| 调色结果等待超 10 s | 错误并保留 active owner | `graded_cache.rs:87-102` |
| 调色 encoder 边界校验失败 | 退回旧逐像素公式（不启用近似结果） | `grade_cache.rs:35-81,144-181` |
| `shared-atlas` 关闭 | 回退 ByteStage/逐子图路径 | `assets.rs:1474-1500,1638-1700` |
| `grade-cache` 关闭 / 结果 pin 满 | 走无缓存调色 / 普通 bounded decode | `grade.rs:331-345`、`graded_cache.rs:104-109` |
| 文字缓存不适用/构建失败 | 回退逐 glyph 原路径 | `text_cache.rs:132-141,165,178,181` |
| 组批/组缓存不适用 | 按原顺序原路径绘制（bypass 记数） | `group_batch.rs:58-77`、`group_cache.rs:181-191` |
| 启动素材校验失败 | `ASSETS REQUIRED` 错误屏 + 具体失败描述/路径 | `boot_error.rs:16-29`、`asset_check.rs:36-45` |

启动素材校验的 5 种失败描述：`MISSING FILE OR FOLDER`、`WRONG FILE SIZE`、`WRONG ASSET VERSION`、`FILE READ FAILED`、`ENGINE PROFILE ERROR`（`asset_check.rs:36-45`）。**[未验证]** 上述错误/超时路径在设备上的实际表现没有单独采集。
