## 1. 历史基线与问题（r2，固定窗口）

r2 捕获：`doc/evidence/12-hardware-render-evidence.json`（CatLog 324,358 B，SHA-256 `c16d1ac5…d3d`，频率 444/222/222 MHz，scene 480×270 + composite 720×404）。

重场景固定窗口（frame 2444–2467，scene=1/PC=246，24 帧）的核心账：

| 指标 | 数值 |
|---|---:|
| work | **208.331 ms/帧**（render 207.815） |
| 起帧间隔 | **4.686 FPS** |
| 等待合计 | 187.124 ms/帧（89.82%） |
| `finish_target` + `finish_copy` | 77.317 + 75.313 = **152.630 ms/帧** |
| present 相关 Finish/排空 | ≈34.074 ms/帧 |
| Begin/EndScene | 各 39 次/帧 |
| PS 目标快照复制 | 8.5 次/帧，62.999 ms/帧 |
| 组 scratch | 3 次/帧，10.576 ms/帧 |
| stage→scene 复制 | 1 次/帧，3.768 ms/帧 |

加载链 hotspot（同捕获，详见 [04](04-资源调度与缓存.md)）：

- UI 每个子图整条 NX 解压：range 146 次、处理 1,539,661,334 B、仅选中 58,347,540 B（放大 26.39×），首用约 780 ms；
- ByteStage 启动 130 个任务、峰值 63 在途、只消费 4 次；
- GXT 首用主线程重读：20 次/4.178 s，实际上传仅 62.475 ms；
- 无用 retain 41.907 MiB/647.706 ms；Vec→Arc 42.862 MiB/430.656 ms；C→Vec 8.294 MiB/76.525 ms。

这不是“CPU 反复上传纹理”问题：该窗口 upload/reload/eviction/readback 均为 0，瓶颈在离屏 pass 结构与同步边界。

## 3. 渲染/GPU 优化记录

### 3.1 批次 arena + 异步提交（r3）

- **问题**：r2 每帧在 present、Begin target、纹理 copy/销毁等路径调用 `sceGxmFinish`/`sceGxmDisplayQueueFinish`，target/copy Finish 152.630 ms/帧 + present 34.074 ms/帧。
- **改动**：basic/effect 顶点与 copy/clear 统一进两槽单调 arena（按最坏 112 B/effect 顶点 + 128 B/quad 预检，64 KiB 增长，单槽上限 4 MiB）；每个成功 EndScene 写 fragment notification 单调序号；CPU 只在真正复用/覆写/销毁/读回处等待；present 改有界显示队列（最多 2 pending），取消每帧无条件 Finish；纹理 destroy 改“逻辑 retire→完成回收”；容量不足时受控分段重开同一目标。
- **实现**：`knife/vita/gpu_lifetime.inc:194-290`、`knife/vita/gxm_backend.c:345-349,550-557,616-654`、`knife/knife-render/src/vita.rs:3012-3070`。
- **实测 r3**：Finish 计数被完成通知/背压替代，但主线程阻塞迁移到 `sceGxmEndScene`（r3 EndScene 87.092 ms/帧）；因此**不能用 152.630+34.074 ms 直接折算收益**。

### 3.2 每 scene 依赖图（r4，`dependency-graph`）

- **问题**：r2/r3 的 scene 全部串联 SET/VERTEX_WAIT（r4 全段 17,460 个 scene）。
- **改动**：每个纹理维护 `last_read/last_write/last_use`；Rust 提交 scene 实际读集，native 生成 RAW/WAR/WAW 计划，仅对未覆盖边加 `VERTEX_WAIT_FOR_DEPENDENCY`；缺 plan/漏读安全回退完整依赖。
- **实现**：`knife/vita/gpu_lifetime.inc:88-151`、`knife/knife-render/src/vita.rs:3012-3070`、`knife/knife-platform-vita/src/gxm.rs:257-269`。
- **实测 r4**：17,460 个 scene 中 4,866 个（**27.869%**）省掉 VERTEX_WAIT；重载 PC212 窗口 1,214/4,924（24.655%）；缺计划/容量溢出计数为 0。

### 3.3 r5：逐槽完成修正

- **问题**：r4 检查旧槽 `last_sequence`，等待的却是全局最新提交，慢旧槽会把另一槽新 batch 一起等完（r4 重窗 31 次 batch wait、均值 53.934 ms；复用帧平均 16.991 ms/帧）。
- **改动**：每槽独占 notification region 一个 word，只等该槽最后提交序号；全局退休用“未完成槽区间最早序号−1”的连续 frontier，回绕只在真实完成后重置。
- **实现**：`knife/vita/gpu_lifetime.inc:32-74,204-215`。
- **验证**：ASAN/UBSAN 169 项定向检查通过；**无新真机数据**（16.991 ms 不能当作已回收）[未验证]。

### 3.4 r6：删除被覆盖的 first-mask

- **改动**：`Stage::clip_draw` 在 first 且已有 replacement mask 时，第一条 mask 会被紧邻的第二次完整清除覆盖，删除之；mask=None/child/非 first/Pixel 路径保留。
- **实现**：`knife/knife/src/stage.rs:1651-1696`。
- **验证**：192 项定向对照（36 条冗余 mask 删除、156 条输出完全一致）；结构预测每重画 3 组场景数 **15→12**，无新真机数据 [未验证]。

### 3.5 PS 目标颜色读取（`ps-fetch`）——核心收益项，终版仍待实机确认

- **问题**：r2 每个 PS 绘制都要 `End(group pixel) → GPU copy 旧目标 → Begin → PS draw`；r4 实测 1,255 次快照/148 重画、逻辑 GPU copy 1,786,406,400 B。
- **改动**：`effects.cg` 新增 `__nativecolor __regformat unsigned char4 ... : FRAGCOLOR` 系列入口（通用 24-op、op19、op2、group op19、op11、op13、plain op19）；终版统一为 **encoded UNORM8 + UCHAR4** 输出契约；Rust 仅在 native capability 成立时省略 snapshot，否则回退旧链；op18 非 Fill 直接复用既有 NoAlpha/Opaque 程序。
- **实现**：`knife/vita/shaders/effects.cg:481-560`、`knife/vita/effects_backend.inc:279-319`、`knife/knife-render/src/vita.rs:1951-2068,2635-2666`。
- **关键障碍与修复**：r3/r4 的 fetch 程序实际未启用。r4 真机日志显示编译输出 **0 B / 4 条语法错误**，根因是 PSM 编译器默认不注册 `__nativecolor/__regformat`；终版新增 `knife/vita/shader_extensions.c`，在编译器就绪后调用 `sceShaccCgExtEnableExtensions()` 并按 NID 白名单校验模块。
- **结构预期**：fetch 全面生效后，r4 的 `4730 − 2×1255 = 2220 = 15 scene/重画`（再叠加 r6 为 12）——这是结构验收目标，不是 FPS 预测。
- **状态**：r4 实测失败；终版修复后**没有新真机日志**，是否真正编译/接纳、像素是否等价均 [未验证]。

### 3.6 组融合（`group-fused`）

- **问题**：每帧每组 `pixel→scratch`、`scratch` 上 MaskAlpha、`scratch→stage` 三次 pass。
- **改动**：一次读 pixel/mask 的最终合成，精确模拟旧链 HALF/RGBA8、sRGB encode/decode 与 MaskAlpha 量化；能力不足回退 scratch。
- **实现**：`knife/vita/effects_backend.inc`、`effects.cg` `fs_group_composite`、`knife-render/src/vita.rs:2245-2268`。
- **实测 r4**：组 scratch/重画 **3→0**、`group15=1`；但 PS 反馈链仍在，EndScene 仍 84.357 ms/帧（见 3.5）。

### 3.7 紧凑顶点流（`compact-stream`）

- **问题**：每顶点 112 B。
- **改动**：对 haze/soft 全零（或同一 draw 内 80 B 常量逐位一致）的顶点使用 32 B 流 + stride=0 常量属性，复用原 `vs_main`/varying ABI；不一致/驱动拒绝回 112 B，不改变混合顺序与数学。
- **实测 r4**：**174,597/174,597 次 draw 覆盖**，顶点输入字节 120,111,936→47,003,776（**−60.867%**），顶点复制 0.154 ms/混合帧。

### 3.8 纹理池与有条件清零（`texture-pool`）

- **改动**：纹理像素按 64 B 子分配到最小 256 KiB CDRAM 物理页，空页缓存 ≤2 MiB；逻辑收费与物理映射分开记账；上传只清 row padding/slice 尾部，`data=NULL` render target 仍完整清零。
- **实测 r3**：同进度 GXT 清零 15,466,496 B/24.531 ms→0；MAIN mapped −3,276,800 B、CDRAM mapped −2,883,584 B。

### 3.9 直接 stage 消费（`direct-stage`）

- 无 ghost/focus/transition 时 canvas 直接只读 stage，省每帧 1 次 stage→scene 复制。
- **实测 r3**：PC246 窗口 46/46 direct、stage→scene copy=0；全段 8,724 帧走 direct。

### 3.10 新增 pass 级缓存（16–19，终版新增）

- `stage-prefix`（`game/stage_prefix.rs`）：纯 stage 前缀（clear alpha=1、≤64 quad、Alpha/Ps、无可变源）记忆化为 ≤3 MiB 的 RGBA8 结果，命中用一次 Opaque/NoAlpha 全屏绘制替换前缀。
- `group-batch`/`group_cache`/`group_schedule`：完全清除的独立组生产提前执行并保留 RGBA8，按原顺序合成；12 MiB/6 项，180 帧 idle；规则读/pair 读是屏障。
- `coalesce-bake`：同一 dispatch 内仅合并 7 个源无关 stage setter（STEC/SNX2/SNX3/STBR/STZ4/STRT/SNX4），其余边界强制 materialize。
- 状态：host 合同测试通过；**无真机日志证明收益/像素等价** [未验证]。

### 5.4 ⚠️ 口径警告

- 三次捕获均为 **scene 480×270 + composite 720×404**；终版固定 **960×540 + 960×540**（scene 像素 ×4、composite ×1.78），**历史 FPS 不能当作终版成绩**。
- 不同窗口的 stage 复用/动画阶段不同；父作用域（PS copy、present、begin target 等）与 EndScene 互相包含，**不能相加**。
- 采集本身有约 3%–6% 观察开销（r4 记录），不要把它算进优化收益。

## 7. 如何在真机上验证终版

1. 构建带采集的包：`KNIFE_VITA_QUIET=0`（默认 release 为静音）；需要时用 `perf-enable.txt` 的显式开关。
2. 首次启动观察 `[knife-shader]` 日志：模块 SHA/导出 → `extensions enable` → 每条 cache/compile/metadata；确认 10 个程序与 capability，而不是只看“计划存在”。
3. 采集与 r4 相同的 scene/PC 窗口（当前素材/剧情需能走到对应 PC）；比较实际计数：
   - PS 快照/重画应从 8.486 向 0 下降；fetch 生效时 `copy_ps`/PS 重开 scene 相应减少；
   - 组 scratch/重画已为 0；r6 后每重画 3 组 scene 预期 15→12；
   - EndScene、`batch_slot_wait`、`work/wall`、FPS 同窗口对照。
4. 回归：PS 各 op 的 alpha=0/1、源/目标 alpha、彩色透明边缘、rule/haze/soft、组持久 mask、FADE/ghost、快进、存读档、退出。
5. 注意：终版固定 960×540，必须与其它 960×540 构建对比；不能拿 r4（480×270/720×404）的绝对 FPS 做验收线。
