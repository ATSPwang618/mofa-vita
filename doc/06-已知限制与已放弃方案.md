# 已知限制与已放弃方案

这份文档的目的：**避免后来者重复已证伪的路线**。每条都附实测结果或代数理由。

## 结构性限制

### 1. 重场景约 5 FPS

- 现象：逐帧动画场景（约占 5% 时间）帧时间约 190 ms。
- 实测构成：39 个 pass × 约 2 ms 的 `sceGxmFinish` ≈ 78 ms；绘制提交仅 0.2 ms；GPU 12 ms。
- 原因：GXM 每次切换渲染目标都需要一次 CPU↔GPU 同步，这是驱动往返，不是「等 GPU 干活」。
- 结论：在「多目标 + 组表面」结构下不可省。要突破只能重写为单 scene 全帧架构。

### 2. 文字放大

默认画布 720×405 放大到 960×544，文字略软。`full` 档位可换原生清晰度但慢约 1.5 倍。

### 3. BUS/GPU 频率

系统 API 只允许 ARM 提频；BUS/GPU 需要外部超频插件。日志中的 222 MHz 是请求值。

### 4. 断行的部分规则未生效

已对齐「不可行首」字符表；`no_end`（行末不能是开括号）、`hang`（悬挂标点）、`allow`
需要上游那套「按字节 + 标签（0x10/0x11/0x1A/0x1B）行走」的排版循环，当前实现是宽度驱动、逐字符放置。

## 已放弃方案

### 去掉每 pass 的 `sceGxmFinish`

三次尝试：全去 → 部分场景黑屏；按 RAW（采样本帧写过的纹理）→ 黑屏；再加 WAR（目标是本帧
被采样的纹理）→ 仍黑屏。说明存在未建模的依赖（可能是驱动对渲染目标重绑或线性/平铺转换的要求）。
**结论：保留每 pass 的 finish。**

### 图层组展平（丢弃遮罩）

把组内图层直接画进舞台、丢掉遮罩 pass。实测：祖父救猫的闪耀特效**露出精灵矩形边框**。
原因：遮罩把发光限制在形状内。组形状统计显示每一组都带遮罩（形状 2/2、3/2、5/1），
不存在「无遮罩的组」。

### 逐层乘遮罩（遮罩当纹理）

给每层加一个「遮罩采样 + alpha 相乘」。实测：背景整片变黑，只剩遮罩形状的竖条。
代数理由：原路径是 `m · Σ Li·∏(1-aj)`，逐层是 `Σ (Li·m)·∏(1-aj·m)`，二者不等价。

### 中性组直画

当组遮罩是「纯白全屏四边形」且组透明度为 1 时，逐层直画与组合成严格等价。
实测：全作 **0 命中**——本作遮罩都是真实的渐变/形状纹理。

### 纹理图集化

按纹理面积分桶实测：**94% 的绘制来自 >512×512 的纹理**（背景 960×540 一张就占满 1024×1024
图集页），只有 4% 小图 + 1% 中图。图集化最多影响 5% 的绘制，对绘制次数无实质帮助。

### 分段缓存静态图层

逐图层变化统计（3082 帧）：75% 的帧无任何变化（已被舞台复用覆盖），25% 有变化，
其中一半是单层、另一半多层且只有 40% 在 z 序中连续。高动画面出现「每帧 40 个图层变化」。
预期收益 <10%，需改合成结构，不划算。

### 降低材质分辨率

材质分辨率只影响 GPU 填充与显存；重场景 GPU 仅 12 ms，瓶颈在 pass 同步。实测无感。

## 维护提醒

- `kv_gxm_begin`（present 路径）的 `sceGxmFinish` **必须保留**：早期删除导致整屏黑。
- 顶点环在 pass 之间复用；如果将来允许跳过 finish，必须同时改成整帧增长，否则会覆盖 GPU 正在读的数据。
- 改 `effects.cg` 后务必重编 `generated/effects.h`。
