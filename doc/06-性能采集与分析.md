## 开关与连接

数据根为 `ux0:data/WitchontheHolyNight/`，不是 `assets/`。

| 文件 | 规则 |
|---|---|
| `perf-enable.txt` | 1开启、0关闭，覆盖性能日志编译默认 |
| `optimization-profile.txt` | 完整配置覆盖，重启生效 |
| `story-font-size.txt` | 50–150且为5的倍数，默认100 |
| `l2-r2-mode.txt` | 0关闭、1左右全区、2上半、3下半 |
| `rear-touch-debug.txt` | 0/1，默认关闭 |

R10编译默认仅自动升级代码识别的**完整R6～R9原厂字符串**；自定义配置保留。单独 `hardware-test`、`all` 不会在R10构建中自动补上新功能。要用本次默认，移走旧覆盖文件，或写入[构建文档](03-构建与工具链.md)中的完整R10字符串；做A/B时在完整配置后追加 `-某开关`。`rt-scenes-2`和4互斥，测4先减2。

游戏通过 `sceClibPrintf` 输出，CatLog把日志送到电脑，VitaDeck负责接收。FTP地址是实机IP，CatLog目标是电脑IP的TCP8080；换网络要分别核对。不要把历史172.17或10.195地址当作当前机器地址。CatLog配置修改后可能需重启实机重新加载；先保存游戏。PC接收器工具见[vitadeck](../tools/vitadeck/README.md)。

## 观测口径

- `sample`、`frame_window`、`frame_classes`：区分重绘/复用帧；窗口末PC不代表整个窗口处于相同演出相位。
- `gpu_work.program_counts`：实际成功执行的程序计数。能力ready只表示可选，不证明命中。
- `estimated_covered_pixels`：裁剪后几何的物理覆盖估计，重叠重复计，不是硬件fragment计数。
- GPU批次完成等待是CPU等待的观测，不能当独立GPU计时，也不能与嵌套耗时直接相加。
- `resource_event`、`resource_checkpoint`：区分资源失败、压力回收、重试与保护存档结果。`saved`才表示保护成功；`failed/unavailable`不是成功。
- `save_focus`：观察存读档焦点和纹理就绪，不等于最终屏幕像素正确。
- `console_dropped_batches`：记录窗口丢批；不能对缺失窗口插值生成帧率结论。
- `charge_entry_frame`、`frame_classes`中的 `live_charge`：scene38特定阶段的入场/运行计时，不能推广为全游戏相位。
- `audio_bank_mount`：音频布局和成员数；`bgm_handoff`：BGM预备耗时、预读帧及开头数据。卡顿还需结合欠载和读卡/解码耗时。
