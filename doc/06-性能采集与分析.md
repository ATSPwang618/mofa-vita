# 性能采集与分析

适用范围：Vita 版的性能观测框架、开关、采集方法、日志格式、分析工具与 A/B 测量约定。
代码基线：`perf/render` 提交 `a670193`（当前工作树为同一提交 + 文档重构，代码未改）；`path:line` 以该基线源码为准。
标记约定：**[代码]** 可在当前源码/脚本核对；**[历史实测]** 来自历史真机捕获（r2/r3/r4，捕获分辨率 480×270/720×404，不等于终版 960×540）；**[未验证]** 仓库内无证据或需实机/模拟器确认。
历史出处：旧 `doc/archive/` 已在本次重构清理；历史记录见 git 提交 `a670193` 的 `doc/archive/`（工作树已清理）。历史数值汇总见 [05-优化记录与实测数据](05-优化记录与实测数据.md)。

## 1. 设计概览

- 采集**默认关闭**：正式包编译期静音，不写任何日志文件，唯一写盘是渲染器启动时的 shader 缓存 [代码] `tools/build-vita.sh:30`、`knife/vita/runtime_shaders.c:183-201`。
- 输出只走 `sceClibPrintf` 控制台，按 JSON 行（schema 3）发送；没有逐帧文件、没有网络/插件依赖在采集路径上 [代码] `knife/vita/perf_audit.c:70-82`、`knife/knife/src/vita_entry.rs:70-105`。
- 采集按固定 5 秒窗口聚合：帧时间直方图 + 累计计数 + 本窗口热点 + 最慢帧 + 审计行 [代码] `knife/knife/src/vita_entry.rs:131-250`。
- 采集开关与优化开关**相互独立**：关闭采集不改变渲染行为；优化开关记录在每轮 header 里 [代码] `knife/knife-perf/src/optimizations.rs:1-2`、`knife/knife/src/vita_entry.rs:95-96`。

## 2. 开关分层

| 层 | 开关 | 作用 | 依据 |
|---|---|---|---|
| 编译期总闸 | `KNIFE_VITA_QUIET=1`（release 默认） | 采集入口直接短路（`PerfLog::open` 返回 None）、panic hook 置空、`kv_perf_console` 变空操作 | [代码] `tools/build-vita.sh:30`；`knife/vita/CMakeLists.txt:24-27`；`knife/vita/diagnostic_log.h:1-13`；`knife/knife/src/vita_entry.rs:60-63`、`:277-281`；`knife/knife-platform-vita/src/audit.rs:65-66` |
| 编译期默认值 | `KNIFE_PERF_CONSOLE=1` | 仅在 `QUIET=0` 时有效：决定没有 `perf-enable.txt` 时的默认状态 | [代码] `knife/knife/src/vita_entry.rs:62-63` |
| 运行时开关 | `perf-enable.txt` | 启动时读一次；显式 `0` 覆盖编译默认 | [代码] `knife/knife-platform-vita/src/perf_switch.rs:24-37` |

运行时开关的规则 [代码] `knife/knife-platform-vita/src/perf_switch.rs:2-22`、`:24-37`：

- 先找数据根目录 `ux0:data/knife-woh-540p/perf-enable.txt`，没有再找 `assets/perf-enable.txt`；只取第一个存在的文件。
- 内容去掉首尾空白后必须**恰好**是 `1`；支持 UTF-8 BOM，最多 512 字节；`0`、`1x`、空文件都视为关闭。
- 只在启动时读取；改完需重启游戏。
- 采集开启时才会启动运行时 watchdog [代码] `knife/knife/src/vita_entry.rs:357-361`。

## 3. 优化开关与 profile

20 个开关位定义在 `knife/knife-perf/src/optimizations.rs:5-37`（`shared-atlas`、`gxt-ready`、`batch-arena`、`group-fused`、`ps-fetch`、`async-submit`、`compact-stream`、`direct-stage`、`texture-pool`、`decode-owner`、`gray-r8`、`animation-window`、`dependency-graph`、`source-rename`、`grade-cache`、`stream-index`、`coalesce-bake`、`resource-io-cache`、`stage-prefix`、`group-batch`），当前构建全部已实现，`IMPLEMENTED` 为全部位的并集 [代码] `:39-43`。

配置文件：`ux0:data/knife-woh-540p/optimization-profile.txt`（270p 为 `ux0:data/knife-woh/`），启动时只读一次 [代码] `knife/knife/src/vita_entry.rs:19-21`、`:342-349`。

| 写法 | 结果 |
|---|---|
| 文件不存在 | 使用 `IMPLEMENTED`（等于全部开启）[代码] `:345` |
| `all` | 全部已实现开关 |
| `baseline` | 全部关闭（仅作对照，不代表复现旧版本缺陷）[代码] `optimizations.rs:54-79` |
| `名字1 名字2` 或逗号分隔 | 只开列出的项 |
| `-名字` | 在已有集合上关闭该项 |
| 未知名字 / 不满足依赖 | 启动直接报错退出，避免“默默测错配置” [代码] `optimizations.rs:60-79`、`vita_entry.rs:342-347` |

依赖规则：`async-submit` 与 `compact-stream` 必须同时保留 `batch-arena`；`dependency-graph` 与 `source-rename` 还要求 `async-submit` 也在集合内 [代码] `knife/knife-perf/src/optimizations.rs:71-77`。

**旧配置风险**：如果沿用旧版本留下的、只列了部分名字的 `optimization-profile.txt`，新加入的开关不会自动生效；要测新默认值请把文件内容写成 `all`，或直接删除该文件。当前选择会写入 header 的 `optimization_mask` / `optimizations` 字段 [代码] `knife/knife/src/vita_entry.rs:95-96`，并同步给原生侧（影响渲染路径分支）[代码] `:349`。

## 4. 指标框架

### 4.1 Rust 侧

- 167 个累计计数（`Metric` 枚举）：`knife/knife-perf/src/lib.rs:12-114`；每项 4 个 u64：`calls / us / bytes / aux` [代码] `:116-124`。
- 关闭时 `add()` 不取时钟、不加原子计数；`Scope` 在关闭时 `start=None` [代码] `:136-168`。
- 18 个 Gauge（当前值 + 峰值），如 staging 在途字节、驻留/编码缓存字节、文本缓存、glyph 页、音频流通道等 [代码] `:170-194`。
- 热点表：全局上限 128 行、同指标 16 行、标签截断 80 字节；每个窗口只输出 CPU 时间最高的 8 条，溢出/丢弃计数显式输出 [代码] `:196-226`、`knife/knife/src/vita_audit.rs:259`。

### 4.2 原生侧

- 108 个计数：`knife/vita/perf_counters.def:3-110`（CPU 拷贝按实际单向 payload、GPU 拷贝按逻辑 payload，`aux` 一般是对齐分配长度，见文件头注释）。
- ABI 通过 `_Static_assert(sizeof(KvPerfSample) == 32)` 钉死 [代码] `knife/vita/perf_audit.c:36-38`；Rust 侧名字表由 `build.rs` 从同一 `.def` 生成，长度不匹配即报“native performance ABI mismatch” [代码] `knife/knife-platform-vita/build.rs:9-22`、`knife/knife-platform-vita/src/audit.rs:21-27`。
- 原生还提供 GXM 阶段标记（begin/end scene、finish、transfer finish、display 等），供 watchdog 判断卡在哪个原生调用 [代码] `knife/vita/perf_audit.h:21-28`。

### 4.3 窗口与直方图

- 每 5 秒一个窗口 [代码] `knife/knife/src/vita_entry.rs:141`；窗口内累计帧时间、update/render/wall、`over_16ms`/`over_33ms`、最大 work。
- 直方图 25 个上界桶（1 ms→2 s，含 125/150/200/250/333/500/750 ms、1/1.5/2 s），输出 p50/p95/p99 的**桶上界**而非精确分位 [代码] `knife/knife-platform-vita/src/frame_timing.rs:1-6`、`:18-21`、`:44-64`。用它比较时只看同桶变化，不要把上界当精确值。
- 每窗口保留最慢一帧（frame/scene/PC + 该帧 probe 增量）[代码] `vita_entry.rs:137-140`；另发 `frame_classes`，按 redraw/reuse/other 分类统计 work/render/wall 与 probe [代码] `knife/knife/src/vita_audit.rs:181-217`。
- `work` 不含 pacer 与日志聚合 [代码] `knife/knife-platform-vita/src/frame_timing.rs:1`；`probe_snapshot_us`、`previous_console_us` 单独列出以便扣除采集开销 [代码] `vita_entry.rs:195`、`:227`。

### 4.4 记录类型与丢片检测

| 记录 | 时机/内容 | 依据 |
|---|---|---|
| `header` | 启动一次：schema 3、build_tag、时钟、堆/栈、scene/composite、资源清单 SHA、优化 mask、缓存预算、语言、sink 与各计数口径 | [代码] `vita_entry.rs:70-105` |
| `sample` | 每窗口：帧时间、update/render、`over_*`、p50/p95/p99、资源/音频/JPEG/GPU 同步等累计计数、console 传输计数 | [代码] `:160-238` |
| `frame_window` | 每窗口精简版帧时间（缺 `sample` 时的恢复路径） | [代码] `:239-243` |
| `frame_classes` | 每窗口 redraw/reuse/other 分类 | [代码] `vita_audit.rs:203-217` |
| `audit_bank` | 累计计数分 bank（每 8 项一包），只发改动项；每 6 个窗口或出现传输丢弃/失败时强制全量 | [代码] `vita_audit.rs:220-258` |
| `audit` | 每窗口结束标记：bank 数、热点数、gauge 值/峰值、最慢帧 probe | [代码] `vita_audit.rs:267-280` |
| `audit_hotspot` | 本窗口 CPU 时间最高的 8 条标签热点 | [代码] `vita_audit.rs:259-266` |
| `runtime_state` | watchdog 状态：phase、no_progress_ms、scene/PC、输入、页面状态等 | [代码] `knife/knife/src/vita_watchdog.rs:154-163` |
| `resource_event` | 资源请求 pending/ready/failed 及细节 | [代码] `knife/knife/src/game.rs:1246-1296` |
| `shader_capabilities` | 运行时 shader 实际可用位（不是用户选择） | [代码] `knife/vita/effects_backend.inc:302-316` |
| `compact_stream` | 32 B 紧凑顶点流 patch 是否启用 | [代码] `knife/vita/effects_backend.inc:151` |
| `limit` | 达到日志上限时最后一条 | 解析侧 `tools/read-vita-performance.py:141-144` |

传输层保证：单条 ≤900 字节，超长 JSON 切成 `audit_chunk`（`seq/part/total/payload`，payload 384 字节，>16 KiB 直接报错）[代码] `knife/knife-platform-vita/src/console_codec.rs:1-27`；后台线程队列上限 3 批 / 96 KiB 单批 / 192 KiB 总量，超限**整批丢弃**并计数 [代码] `knife/knife-platform-vita/src/console_worker.rs:5-7`、`:46-61`。因此分析器把“缺 bank/缺结束标记/重复片”判为数据缺口，而不是零值 [代码] `tools/read-vita-performance.py:136-146`。

### 4.5 watchdog

- 阈值：无进展 `idle ≥ 2000 ms` 判为 stalled；stalled 时每 2 s 汇报一次，否则每 5 s [代码] `knife/knife/src/vita_watchdog.rs:123`、`:154-163`。
- 只在采集开启时启动；它读 GXM 原生阶段快照，不调用 GXM 接口 [代码] `vita_entry.rs:357-361`、`knife/vita/perf_audit.h:20-25`。

## 5. 采集方法

### 5.1 构建诊断包

正式包默认静音，必须显式构建一个 `QUIET=0` 的包才能采集：

```bash
KNIFE_VITA_QUIET=0 KNIFE_PERF_CONSOLE=1 python3 tools/build-vita.py game release
```

`KNIFE_*` 变量在 Windows/WSL 模式会被转发到 WSL 环境 [代码] `tools/build-vita.py:258-269`。构建后包内 `param.sfo`/收据会体现同一 VPK 的身份，收据里的 `quiet_build`、`performance_console_default` 记录这两个值 [代码] `tools/vita-build-receipt.py:129-131`。若不想重编，只能对已是诊断版的包用 `perf-enable.txt` 控制开关。

### 5.2 设备/模拟器捕获

- 输出目标是设备控制台（`sceClibPrintf`），**不会生成 `performance.log`**；需要自备控制台捕获手段（历史做法是 taiHEN 日志转发插件，例如 CatLog，或 Vita3K 的终端控制台）。[未验证] 具体插件组合与当前固件兼容性未在本基线复测。
- 捕获文本可含控制台前缀；分析器的 `--console` 模式会去掉前缀并重组 `audit_chunk` [代码] `tools/read-vita-performance.py:41-53`。
- 单次捕获上限 16 MiB；多次启动请分开保存，不要把两个 header 拼进一个文件 [代码] `:45`。
- 设备侧不写文件、不做网络上报；采集中断只会丢窗口，不会影响游戏运行 [代码] `knife/knife-platform-vita/src/console_worker.rs:46-61`。

### 5.3 采集开销

[历史实测] r4 真机中每 ~5 s 窗口的 `previous_console_us` 为 169.107–309.293 ms，约占墙钟 **3%–6%**；`probe_snapshot_us` 末值 274.009 ms / 2201 帧 ≈ 0.124 ms/帧（历史记录见 `a670193` 的 `doc/archive/16-r4真机瓶颈与编译器扩展缺失.md:108-112`；捕获分辨率 480×270/720×404，不等于终版 960×540）。当前代码仍输出这两个字段 [代码] `vita_entry.rs:195`、`:227`，可用同样方式扣除；[未验证] 终版 960×540 下的开销比例未实测。

## 6. 分析工具

### 6.1 `tools/read-vita-performance.py`

```bash
python3 tools/read-vita-performance.py capture.log --console --environment hardware --out summary.json
```

- 参数：日志/捕获路径、`--environment {hardware,emulator,unspecified}`（必须由调用者声明，不从帧率推断）、`--out`、`--console` [代码] `tools/read-vita-performance.py:256-262`。
- 支持 schema 1/2/3；`--console` 走控制台分片重组；纯日志模式上限 256 KiB，控制台模式 16 MiB [代码] `:14`、`:41-53`、`:67-70`。
- 输出：窗口汇总（work/render/update、FPS、p95 上界、over_16/33）、末值累计计数、分阶段换算（card read / NX inflate / GPU 同步等待）、音频、JPEG 硬件回退、内存峰值、`frame_classes`、`runtime_stalls`、`resource_events`、`shader_capabilities`、`compact_stream`、warnings 与 `queue_and_jpeg_bound_violations` [代码] `:194-253`。

以下两个模块**未入库**，相关命令不能开箱即用：

## 7. A/B 实验方法

1. **固定包**：同一次构建出的诊断包内切换 `optimization-profile.txt`，不要跨构建比较。切换后必须重启游戏（只在启动读一次）[代码] `vita_entry.rs:342-349`。
2. **对照组**：`baseline`（全关）与 `all`（全开）是最小对照；单功能验证用 `all -功能名`。`baseline` 只关闭可选优化，不复制旧版本的缺陷 [代码] `knife/knife-perf/src/optimizations.rs:54-79`。
3. **固定场景**：用 `sample` 的 `scene`/`pc` 字段筛同一位置；窗口必须是完整 5 s 记录（缺 `sample` 时看 `frame_window`），不要拿半窗口或启动阶段对比。分析器要求 `elapsed_ms` 递增、`over_33ms ≤ over_16ms ≤ frames` [代码] `read-vita-performance.py:71-86`。
4. **固定环境**：分辨率、素材清单（header `asset_manifest_sha256`）、时钟、`build_tag`、`optimization_mask` 必须一致；终版固定 960×540（`scene_size`/`composite_size` 由代码决定）[代码] `vita_entry.rs:70-77`、`:339-340`。**历史捕获是 480×270/720×404，不能与终版数字直接比较。**
5. **不跨作用域相加**：`us` 是 CPU 墙钟且父子/跨线程会重叠；GPU 侧没有 busy 计时，`finish`/`end_scene` 只是 CPU 等待 [代码] `knife/knife-perf/src/lib.rs:1-2`、`vita_audit.rs:69-71`。
6. **扣除采集开销**：比较 `previous_console_us` 与 `probe_snapshot_us`，必要时用同一包 `QUIET=0` 与关闭对比（历史约 3%–6%，见 5.3）。
7. **看结构变化**：先看 `shader_capabilities`/`compact_stream` 是否真的启用，再看计数（如 `copy_ps_snapshot`、`draw_ps`、`upload_*`）是否按预期下降；只有计数与帧时间同向变化才能归因。
