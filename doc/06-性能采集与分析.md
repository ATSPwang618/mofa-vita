# 诊断与性能采集

先核对实际运行日志中的 `build_tag`、有效优化配置和素材身份。
交付文件与哈希读取配套收据，不根据历史截图或上传成功推断设备已运行新版本。

## 日志和配置

配置位于 `ux0:data/WitchontheHolyNight/`，与 `assets/` 同级。

| 文件 | 作用 |
|---|---|
| `perf-enable.txt` | 1 开启、0 关闭，覆盖编译时性能日志默认值 |
| `optimization-profile.txt` | 替换整个优化组合，重启生效 |

阅读与背板配置见[安装页](08-素材与安装.md)。
设备已有自定义优化文件会覆盖程序默认值，单独写 `hardware-test` 不等于完整交付组合。
比较前核对日志来源与有效 mask。做 A/B 时保持完整配置，只切换目标项；
`rt-scenes-2` 与 `rt-scenes-4` 互斥。

游戏经 `sceClibPrintf` 输出，CatLog 发送到电脑 TCP 8080，VitaDeck 接收。
FTP 地址是设备 IP，CatLog 目标是电脑 IP，换网络分别检查。
接收器安装与测试见 [VitaDeck](../tools/vitadeck/README.md)。

## 读日志

| 字段 | 含义与边界 |
|---|---|
| `sample`、`frame_window`、`frame_classes` | 区分重绘/复用帧，窗口末 PC 不代表全窗口同相位 |
| `gpu_work.program_counts` | 实际执行计数；能力 ready 不能代替命中 |
| `estimated_covered_pixels` | 几何覆盖估计，重叠重复计，不是硬件片元计数 |
| 批次完成等待 | CPU 等待观测，不是独立 GPU 计时，不能与嵌套耗时简单相加 |
| `resource_event`、`resource_checkpoint` | 失败、回收、重试和保护状态；仅 `saved` 表示保护成功 |
| `audio_bank_mount`、`bgm_handoff` | bank 布局及 BGM 预备，还需结合欠载、读卡和解码耗时 |
| `console_dropped_batches` | 日志丢批，缺失窗口不能插值成性能结论 |

固定相同存档、资源、演出相位、配置和时钟，比较重绘帧时间中位数及 p95/p99，
同时做画面对照。复用帧 FPS、静态 shader 指令数、一次缓存命中不能作为整帧因果收益。
崩溃必须使用同版本 ELF/map 解析。

## 专项与历史工具

- `tools/script_census.py` 用生产解析器盘点脚本；静态解析不是全场景运行证明。
- `tools/vita_gpu_replay.py` 可分析历史 ABBA 日志；
  当前程序已删除固定回放入口，`gpu-replay.txt` 不再触发回放。
- 历史 r3/r10 设备数据、优化撤回及资源失败记录见[证据索引](evidence/README.md)，
  不归属于最新交付，不在操作文档重复维护各轮帧率表。
- 源码开关与默认组合见[架构](01-架构总览.md)和[构建](03-构建与工具链.md)。
