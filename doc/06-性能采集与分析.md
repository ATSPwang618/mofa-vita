## 1. 设计概览

- 当前构建**默认开启控制台采集**：`KNIFE_VITA_QUIET=0`、`KNIFE_PERF_CONSOLE=1`；release 仍关闭同步诊断文件写入。显式设置 `QUIET=1` 或 `PERF_CONSOLE=0` 才生成静音包 [代码] `tools/build-vita.sh`。
- 输出只走 `sceClibPrintf` 控制台，按 JSON 行（schema 3）发送；没有逐帧文件、没有网络/插件依赖在采集路径上 [代码] `knife/vita/perf_audit.c:70-82`、`knife/knife/src/vita_entry.rs:70-105`。
- 采集按固定 5 秒窗口聚合：帧时间直方图 + 累计计数 + 本窗口热点 + 最慢帧 + 审计行 [代码] `knife/knife/src/vita_entry.rs:131-250`。
- 采集开关与优化开关**相互独立**：关闭采集不改变渲染行为；优化开关记录在每轮 header 里 [代码] `knife/knife-perf/src/optimizations.rs:1-2`、`knife/knife/src/vita_entry.rs:95-96`。

当前本地包 `stage-effect-r8-hardware-test-20261106` 使用 `KNIFE_VITA_QUIET=0`、`KNIFE_PERF_CONSOLE=1`，默认开启GPU测试组合，启动 `optimization_profile` 报告实际mask `0x4fdfffffff`；具体项目与回退见 [34](34-hardware-test-defaults.md)。它每 5 秒输出带版本身份的控制台窗口；VitaDeck/CatLog 在接收端保存日志，游戏不会自动在 `assets/` 生成 `performance.log`。r2 原实验已收到实机日志并因重场景收益不足撤回，见 [20](20-r2实机复核与回退.md)。此前r3增加 `ps_fetch7_29` 能力和 `draw_ps7` 实际执行计数，用户日志已确认29启用、目标PC1246全重绘窗口约6.08→7.03 FPS；这是历史实测，不能代替r8验收，边界见 [22](22-op7专用shader实机复核.md)。

Extra 页面新增 `ui_source_event`：build、page、pending/ready/failed、source/resident/heap 字节与具体错误链。raw 图集按成员延迟读取，因此页面 `ready` 表示必需来源已准备，不表示所有缩略图都预先上传。读取失败还保留 archive/index/offset/len/direct 诊断；详见 [17](17-书库与图录加载修复.md)。

2026-11-02 已恢复本机 VitaDeck 接收：原线程会被第一个长连接占住，修复后同时处理多个连接。实机数据根已设 `perf-enable.txt=1`；PC 自动保存 `VitaDeck/logs/vita-console.log`（8 MiB + 一份轮转备份），已收到本版本真实日志。程序本体未重编，详见 [13-VitaDeck日志接收修复](13-VitaDeck日志接收修复.md)。

从此修复版开始，图像需求失败的 `resource_event.detail` 保留具体注册、准入或原生上传错误，包含适用的纹理尺寸、GXM 阶段和返回码，不再统一折叠为 `image registration/upload failed`。`block_failed` 仍统计底层失败次数；恢复成功后该计数也不会清零，须同时检查是否出现后续 `ready` 事件及 PC 推进。旧日志未保存底层错误码时，不能仅凭失败后窗口中的空闲显存断言分配瞬间的原因。

targetfix 的分配压力日志含目标标签和被放弃的 owner 字节：`Required render target allocation pressure`；有限重试成功为 `Required render target recovered after cache release`；直接转交 ring 目标为 `Reusing target ring spare for required capture`。`released_bytes` 不能等同内核即时回收量；错误链和验证边界见 [15](15-读档与转场目标分配恢复.md)。

本次 bgmbuf header 同时记录普通流的 `audio_stream_queue_blocks=10` 与 BGM 的 `audio_bgm_queue_blocks=50`、`audio_bgm_prefetch_ms=1000`、`audio_bgm_pcm_pool_bytes=399360`；每路启动输出 `Audio stream PCM buffering`。`audio_stream_buffer_bytes` 表示池载荷，不是队列剩余声音时长。单流 starvation 与整体 AudioOut underrun 分开比较，详见 [16](16-BGM预读缓冲调整.md)。

## 3. 优化开关与 profile

开关使用独立的 `u64` 掩码，保留 bit0–29；原有开关之外，r5 增加 `ps-plain-material`、`group-bounds`、`half-color`、`tiled-targets`、`blur-weights`、`rt-scenes-2` 和 `rt-scenes-4`，r7增加位38 `ps-all-operations`。r8构建默认使用 `hardware-test`，包含上述候选并选择Scene容量2；`rt-scenes-2/4`互斥。`IMPLEMENTED` / 底层 `all` 保留原集合，默认测试组合单独命名，不把尚未实机验收的候选标成已准入。

配置文件：`ux0:data/WitchontheHolyNight/optimization-profile.txt`（270p 数据根已随变体移除），启动时只读一次 [代码] `knife/knife/src/vita_entry.rs:15`、`:345-349`。

| 写法 | 结果 |
|---|---|
| 文件不存在 | 使用构建环境的默认profile；r8为 `hardware-test`，实际mask `0x4fdfffffff` |
| `hardware-test` | all加全24OP、Group范围、Half、Tiled、Blur权重及Scene容量2 |
| 旧标准值 `all` / `all ps-all-operations` / `all ps-full-material` | 编译默认为hardware-test时，启动自动展开为测试组合；只去首尾空白后精确匹配，不重写文件 |
| 自定义 `all -half-color` 等 | 按文件解析，all仍为原集合；不做旧标准值迁移 |
| `baseline` | 全部关闭（仅作对照，不代表复现旧版本缺陷）[代码] `optimizations.rs:54-79` |
| `名字1 名字2` 或逗号分隔 | 只开列出的项 |
| `-名字` | 在已有集合上关闭该项 |
| 未知名字 / 不满足依赖 | 启动直接报错退出，避免“默默测错配置” [代码] `optimizations.rs:60-79`、`vita_entry.rs:342-347` |

依赖规则：`async-submit` 与 `compact-stream` 必须同时保留 `batch-arena`；`dependency-graph` 与 `source-rename` 还要求 `async-submit` 也在集合内 [代码] `knife/knife-perf/src/optimizations.rs:71-77`。

**配置覆盖**：r8兼容上述三个标准旧值，其他自定义配置仍覆盖构建默认。单独关闭某项可写 `hardware-test -group-bounds` 或 `hardware-test -half-color`；要保持r7组合可写 `all ps-all-operations -group-bounds`，冗余关闭项表示明确自定义。启动 `optimization_profile` 记录compiled_profile、source、legacy_expanded及有效mask/names；header继续写入 `optimization_mask` / `optimizations`，并同步给原生侧。Tiled还须查看探针是否实际通过，不能只凭开关判断存储布局。

### UI 离屏绘制复用

`ui-pass-cache` 默认随 `all` 开启；用 `all -ui-pass-cache` 可单独关闭作实机对照。它仅复用原有离屏目标的像素，不分配新显存。目标必须完整清屏，且输入四边形、纹理及遮罩内容版本、目标内容版本都与上次相同；无清屏的累积绘制和目标自采样走原路径。动画参数或前级目标变化会在同一帧使后级失效，最终淡入淡出和输入更新照常执行。

`plain-forcealpha` 为无扭曲、软裁剪、规则和预乘标志的 ForceAlpha 选择 shader 26，失败回退 shader 2。`archive-glow-bounds` 把书库最终加色裁到选中书本 RGB 范围，保留两个物理纹素的过滤余量；其加色保持目标 alpha。两者均不更改资源或 540p 分辨率。观察 `plain_forcealpha26`/patch status、`draw_plain_forcealpha` 与 `draw_forcealpha`，并对照同页 `batch_slot_wait`/`display_queue_enqueue`；draw 指标仍是 CPU 提交时间，不能当作 GPU 时间。`ui_glow_coverage.bytes/aux` 分别累计实际裁剪矩形的物理像素估计与未裁剪全屏像素数（不是实测总线流量）。分别用 `all -plain-forcealpha`、`all -archive-glow-bounds` 对照。

`ui-source-prefetch` 在 Extra 光标对应页有余量时预热图包，确认进入后以非阻塞 poll 等待整个图包组就绪，再开始原有淡出/切页；等待时返回键可取消。书库准备 ARCHIVE/ARCHTHUMB，CG 准备 EXTRA/CG，音乐准备 SOUND。复用既有单个 atlas worker、64 MiB 共享源池；机会预热不驱逐，并预留压缩输入 scratch、解压输出与 48 MiB 回收水位。失败或 10 秒超时返回 Extra 菜单，活动 worker 的 owner 保留。`ui_source_pending` 是等待帧计数，`ui_source_ready.aux` 是准备历时微秒（包含帧间隔，不是 CPU 耗时），另记 `ui_source_failed/cancelled`；`atlas_load` 仍反映后台工作，`atlas_demand_wait` 应检查是否仍在首绘阻塞。可用 `all -ui-source-prefetch` 对照。


日志新增 `ui_pass_cache_hit/build/bypass/invalidate/quads_saved/record`，以及 `ui_pass_cache_bytes/entries`。命中次数表示省去一次完整离屏绘制请求，`quads_saved.aux` 表示省去的四边形数，不是 GPU 执行时间。缓存只保留弱引用和比较键，负载上限 256 KiB、16 项，页面释放后不会被缓存继续持有。`sample.ui_at_window_end` 是窗口结束时的 UI 状态快照，不代表整个窗口都在同一页面。对应实现：`knife/knife/src/game/ui_pass_cache.rs`。

## 4. 指标框架

### 4.1 Rust 侧

- 232 个累计计数（`Metric` 枚举）：`knife/knife-perf/src/lib.rs:12-114`；每项 4 个 u64：`calls / us / bytes / aux` [代码] `:116-124`。
- 关闭时 `add()` 不取时钟、不加原子计数；`Scope` 在关闭时 `start=None` [代码] `:136-168`。
- 28 个 Gauge（当前值 + 峰值），如 staging 在途字节、驻留/编码缓存字节、文本缓存、glyph 页、音频流通道等 [代码] `:170-194`。
- 热点表：全局上限 128 行、同指标 16 行、标签截断 80 字节；每个窗口只输出 CPU 时间最高的 8 条，溢出/丢弃计数显式输出 [代码] `:196-226`、`knife/knife/src/vita_audit.rs:259`。

### 4.2 原生侧

- 112 个计数：`knife/vita/perf_counters.def:3-110`（CPU 拷贝按实际单向 payload、GPU 拷贝按逻辑 payload，`aux` 一般是对齐分配长度，见文件头注释）。

### 4.3 窗口与直方图

- 每 5 秒一个窗口 [代码] `knife/knife/src/vita_entry.rs:141`；窗口内累计帧时间、update/render/wall、`over_16ms`/`over_33ms`、最大 work。

## 5. 采集方法

### 5.1 构建诊断包

当前正式包默认保留控制台日志；复现时显式记录开关，避免外部环境覆盖：

```bash
KNIFE_VITA_QUIET=0 KNIFE_PERF_CONSOLE=1 python3 tools/build-vita.py game release
```

`KNIFE_*` 变量在 Windows/WSL 模式会被转发到 WSL 环境 [代码] `tools/build-vita.py:258-269`。构建后包内 `param.sfo`/收据会体现同一 VPK 的身份，收据里的 `quiet_build`、`performance_console_default` 记录这两个值 [代码] `tools/vita-build-receipt.py:129-131`。若不想重编，只能对已是诊断版的包用 `perf-enable.txt` 控制开关。

### 5.2 设备/模拟器捕获

- 输出目标是设备控制台（`sceClibPrintf`），**不会生成 `performance.log`**；需要自备控制台捕获手段（历史做法是 taiHEN 日志转发插件，例如 CatLog，或 Vita3K 的终端控制台）。[未验证] 具体插件组合与当前固件兼容性未在本基线复测。
- 捕获文本可含控制台前缀；分析器的 `--console` 模式会去掉前缀并重组 `audit_chunk` [代码] `tools/read-vita-performance.py:41-53`。
- 单次捕获上限 16 MiB；多次启动请分开保存，不要把两个 header 拼进一个文件 [代码] `:45`。
- 设备侧不写文件、不做网络上报；采集中断只会丢窗口，不会影响游戏运行 [代码] `knife/knife-platform-vita/src/console_worker.rs:46-61`。

### 5.3 采集开销

[历史实测] r4 真机中每 ~5 s 窗口的 `previous_console_us` 为 169.107–309.293 ms，约占墙钟 **3%–6%**；`probe_snapshot_us` 末值 274.009 ms / 2201 帧 ≈ 0.124 ms/帧（历史记录见 `a670193` 的 `doc/archive/16-r4真机瓶颈与编译器扩展缺失.md:108-112`；捕获分辨率 480×270/720×404，不等于终版 960×540）。当前代码仍输出这两个字段 [代码] `vita_entry.rs:195`、`:227`，可用同样方式扣除；[未验证] 终版 960×540 下的开销比例未实测。

## 7. A/B 实验方法

1. **固定包**：同一次构建出的诊断包内切换 `optimization-profile.txt`，不要跨构建比较。切换后必须重启游戏（只在启动读一次）[代码] `vita_entry.rs:342-349`。
2. **对照组**：`baseline`（全关）与 `all`（全开）是最小对照；单功能验证用 `all -功能名`。`baseline` 只关闭可选优化，不复制旧版本的缺陷 [代码] `knife/knife-perf/src/optimizations.rs:54-79`。
3. **固定场景**：用 `sample` 的 `scene`/`pc` 字段筛同一位置；窗口必须是完整 5 s 记录（缺 `sample` 时看 `frame_window`），不要拿半窗口或启动阶段对比。分析器要求 `elapsed_ms` 递增、`over_33ms ≤ over_16ms ≤ frames` [代码] `read-vita-performance.py:71-86`。
4. **固定环境**：分辨率、素材清单（header `asset_manifest_sha256`）、时钟、`build_tag`、`optimization_mask` 必须一致；终版固定 960×540（`scene_size`/`composite_size` 由代码决定）[代码] `vita_entry.rs:70-77`、`:339-340`。**历史捕获是 480×270/720×404，不能与终版数字直接比较。**
5. **不跨作用域相加**：`us` 是 CPU 墙钟且父子/跨线程会重叠；GPU 侧没有 busy 计时，`finish`/`end_scene` 只是 CPU 等待 [代码] `knife/knife-perf/src/lib.rs:1-2`、`vita_audit.rs:69-71`。
6. **扣除采集开销**：比较 `previous_console_us` 与 `probe_snapshot_us`，必要时用同一包 `QUIET=0` 与关闭对比（历史约 3%–6%，见 5.3）。
7. **看结构变化**：先看 `shader_capabilities`/`compact_stream` 是否真的启用，再看计数（如 `copy_ps_snapshot`、`draw_ps`、`upload_*`）是否按预期下降；只有计数与帧时间同向变化才能归因。
