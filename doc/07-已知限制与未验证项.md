# 已知限制与未验证项

适用范围：`perf/render` 基线 `46fc688` 加本地全剧情图库清晰度更新，2026-11-02 整理。当前交付版本为 `540p-46fc688-all-art-20261101`。这里区分当前实现、历史设备记录和本次尚未验证的内容。

## 1. 当前画质包的验证边界

- scene、组 pixel/mask 和 composite 固定 960×540，最终在 960×544 屏幕居中输出；代码只有 native540 一条正式构建档。
- 21,237 个剧情图片条目已从原图重做。全量阶段新增的 21,185 张，经实际游戏归档读取器和 GXT 解码器逐图验证；另有最初 52 张的独立比较记录。
- 241 项 host 测试、ARM 构建、VPK 身份检查属于构建与离线证据。摘要见 [13-native540-art-quality.json](evidence/13-native540-art-quality.json)。
- **当前画质包尚未完成实机画面、帧时间和显存峰值回归。** 增加部分源纹理采样像素会提高单图占用，保持缓存上限不能直接证明帧率不变。

## 2. 历史实测应按版本理解

r2/r3/r4 真机捕获使用 480×270 scene + 720×404 composite；其 FPS、EndScene 和 pass 数只能作为当时的结构证据。当前 960×540 的性能不能由这些数字外推。

[渲染文档](02-渲染与GPU后端.md) 也记录了 2026-11-01 的后续 540p 优化及设备复核，包括流文件探测、音效准备、视频启动和文字缓存。它们发生在本轮全图库素材更新之前，不能代替新包的同场景 A/B。

历史 PS fetch 编译失败同样不能直接描述当前每台设备：实际是否启用需核对该次启动的编译、反射、patch、capability 与 shader 缓存身份，并进行像素比较。不能仅凭开关包含 `ps-fetch` 就宣称路径已接纳。

## 3. 内存与画面边界

- `ATTRIBUTE2=12` 与 256 MiB newlib heap 分别记录在 SFO 和构建收据中；它们不等于所有内存都能给纹理使用。
- 场景、离屏目标与显示保持 540p。源纹理可为长图，GXT 单边不超过 2048，总像素不超过 1,036,800；脚本逻辑尺寸保持原值。
- GPU 源纹理、调色、文字、组缓存、视频帧等各受原预算约束。需要观察真实 native 分配与 pin/退休状态，不能把不同缓存 gauge 简单相加。
- 全剧情、透明边缘、调色、软遮罩、语言条带、读档/快进和长时间连续播放仍需设备覆盖；局部截图或 host 解码通过不能代表全部演出正确。

## 4. 设备与素材前提

- 需要能运行自制应用的 PS Vita，以及 GXM、Display、Audio、Jpeg、AvPlayer 等系统服务。Cg 扩展代码通过 taiHEN 查询并核对模块；不同固件/插件组合仍需设备验证。
- TITLE ID 为 `KNIF00540`，固定中文 ID2。素材、存档、shader 缓存分别位于 `ux0:data/WitchontheHolyNight/` 下的 `assets/`、`saves/`、`shader-cache/`。
- 仅接受 [08-素材与安装](08-素材与安装.md) 所列清单对应的 codec9 包。原始 Switch 数据、旧 codec8/270p 包不能直接混入；素材更改后必须同步内嵌元数据并重编 EBOOT。
- 同 TITLE ID 的升级沿用同一外部存档路径；不要把 `saves/` 当作可再生成的构建缓存。

## 5. 构建与工具限制

- 需要本机 VitaSDK 核心、固定 Rust `nightly-2026-05-28`、CMake、Ninja、Bash、Git 和 Python。Windows 通过 WSL 构建。
- 随仓库提供的 7 个静态库记录了对应 SDK provenance；跨 SDK core 的 ABI/链接兼容性应实际构建验证。
- 离线构建需要已经安装工具链和 Cargo 依赖。源码构建不需要外部游戏素材；运行和素材元数据更新需要匹配数据。
- `read-vita-performance.py` / `test-vita-performance.py` 仍依赖不入库的本地 `vita_audit_log.py` / `render-audit/`。干净检出时这些分析工具不能开箱即用，见 [06](06-性能采集与分析.md)。
- 模拟器集成工具需要另外准备 Vita3K、固件与控制接口；不能用 PC/模拟器耗时作为 Vita 实机速度。
- 已移除依赖过期文档的 Windows ZIP 打包、交付、旧清理和旧素材校验入口。现有工具按 [tools/README.md](../tools/README.md) 分类使用。

## 6. 日志与版本

构建脚本的 release 默认 `KNIFE_VITA_QUIET=1`。当前本地画质包显式使用 `QUIET=0`、`KNIFE_PERF_CONSOLE=1`，因此可经 VitaDeck/CatLog 接收控制台性能窗口，版本身份为 `540p-46fc688-all-art-20261101`。不会自动在素材目录创建 `performance.log`。

比较日志前先核对版本、素材 SHA、渲染尺寸、优化 mask、时钟和采集开关；worker scope 与主线程可重叠，嵌套计时不能直接相加。

## 7. 仓库保留与后续验证

本机仅长期保留当前运行目录与可编辑图片目录。旧素材、回滚资源、临时测试图和重复压缩包已按用户要求清理；旧源码及文档可从 Git 历史查询。清理规则见 [09](09-仓库维护与清理.md)。

后续重点验证：

1. 新画质包的同场景 FPS、work/p50/p95/p99、峰值 MAIN/CDRAM 和缓存淘汰。
2. 镜头平移/放大、透明差分、调色及混合链的最终画面。
3. 快进、读档、跨场景取消、UI 首用、音频连续性和视频切换。
4. 不同固件/插件与存储卡条件下的加载和 shader 接纳情况。

第三方来源与许可证见 `knife/LICENSE`、`knife/vita/vendor/`；本轮保留这些依赖和声明。
