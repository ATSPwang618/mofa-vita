# 已知限制与未验证项

> 适用范围：当前工作树（`perf/render` 提交 `a670193` + 文档重构）。
> 标记约定：**[代码]** 当前实现事实；**[历史实测]** 仓库历史真机捕获（r2/r3/r4，捕获分辨率 480×270/720×404，不等于终版 960×540）；**[未验证]** 无设备/像素证据。
> 本文记录“不能宣称什么、为什么、怎么验证”。优化数据见 [05-优化记录与实测数据](05-优化记录与实测数据.md)。

---

## 1. 性能口径：终版没有 960×540 真机数据

- 终版代码把渲染固定为 **960×540 scene + 960×540 composite**（`knife/knife-render/src/vita.rs:3324-3366` 的 `scene_divisor=1`/`scene_size`/`composite_physical`；`RENDER_W/H=960×540`）。main 时代的 `scene-mode.txt`/多档位运行时降分辨率被移除。
- 仓库内三次真机捕获（r2/r3/r4）均为 **480×270 scene + 720×404 composite**。终版 scene 像素是捕获版的 **4 倍**、composite 约 **1.78 倍**。
- **结论**：r3 的 8.821 FPS、r4 的 9.120 FPS 只能说明优化方向/结构趋势，**不能作为终版性能成绩**；终版 960×540 的 FPS、帧时间分位全部 **[未验证]**。

## 2. 核心着色器路径：PS fetch 未在设备上成立

- r3/r4 真机日志显示 PS 目标颜色读取没有生效：r4 编译输出 0 B、4 条语法错误，`shader_capabilities` 为 0；r4 的组融合虽生效（`group15=1`、scratch 3→0），但 PS 反馈链仍在（重画 91.88% work 在 EndScene）。
- 终版已补 `knife/vita/shader_extensions.c`（调用 `sceShaccCgExtEnableExtensions()`、模块 NID 白名单）并改用 encoded UNORM8/UCHAR4 契约；但**没有新设备日志**证明编译/反射/Register/patch 全通过，也没有像素等价验证。
- 因此以下都不能当作已兑现：PS snapshot 减少、scene 数 32→15→12、EndScene 下降、FPS 提升。验证方法见 [05](05-优化记录与实测数据.md#7-如何在真机上验证终版)。

## 4. 平台与运行前置条件

- **Cg 扩展需要 taiHEN**：`shader_extensions.c` 通过 `taiGetModuleInfo` 校验模块 NID 后才 enable；无 taiHEN 时推断会回退离线 GXP、PS fetch 不可用。文档未把 taiHEN 写成显式安装前提，需实机确认（**[未验证]**）。
- **固件/系统模块**：依赖 SceGxm/SceDisplay/SceAudio/SceJpeg/SceAvPlayer 等平台服务；`libshacccg.suprx` 为随包 Sony PSM 编译器模块，需自行评估分发合规性。
- **性能测量环境**：历史捕获为 444/222/222 MHz、安装 `NoPowerLimits`/`nosleep` 等设备插件以避免降频；这些测试插件**不在仓库**，需自行准备。
- **采集开销**：r4 记录采集本身约 3%–6% 观察开销；正式版默认静音（`KNIFE_VITA_QUIET=1`），测量需 `KNIFE_VITA_QUIET=0` 重建。

## 5. 素材与安装限制

- 只匹配 **r7 native540 codec9** 素材包（`assets/vita-540p-assets.json`，SHA-256 见 [README](../README.md) 与 [08](08-素材与安装.md)）；旧 codec8、原始 Switch 数据、旧 270p 素材（270p 变体已移除，仅存历史）不可直接替换。
- 游戏本体/字体/音视频/汉化资源不入库，必须由使用者自备；编译 VPK 不需要素材，但**运行时需要完整 `assets/`**。
- TITLE ID `KNIF00540`、中文 ID2、固定 540p；同 TITLE ID 安装会覆盖存档目录，注意备份。
- 270p 档位（TITLE ID `KNIF00270`、`assets-540p` feature 关闭分支、`asset_profile_270p.rs`、相关工具与 540p 素材不混用规则）已在本次彻底移除；当前只有 native540 一条素材链。

## 6. 构建与工具链限制

- 仍需要本机 **VitaSDK 核心**（GCC/newlib/平台 stubs/打包工具）与 CMake≥3.20、Ninja、Python≥3.9、Bash、Git；仓库只提供第三方依赖与运行时编译器，不提供 SDK core。
- 7 个静态库与 SDK core **2026.08.1** 绑定（`knife/vita/vendor/dependencies/manifest.json`）；其它 core 版本需实测链接。`libtaihen_stub.a` 只是 import stub，不是设备 taiHEN 运行时。
- `KNIFE_VITA_OFFLINE=1` 时必须有完整 Rust 工具链与 Cargo 缓存；首次安装 Rust/构建默认需要联网。
- Windows 通过 WSL 构建，需 WSL 发行版内有 VitaSDK/Rust/原生工具；`--native` 只适用于 Linux/macOS。
- **性能分析工具在干净检出下不完整**：`read-vita-performance.py`/`test-vita-performance.py` 依赖未入库的 `tools/vita_audit_log.py`、`tools/render-audit/`；归档引用的 `performance/profiles/`、`baselines/`、`implementation-status.json` 也不在库中。复算历史数字需补齐这些本地工具/数据。
- 旧脚本 `tools/package_project.py` 等仍引用已不存在的历史文档路径（旧 `doc/01-项目总览/...`），属于 legacy，不参与当前构建；270p 专属脚本（`create_270p.py`、`package_vita_270p.py`、`write_vita_270p_delivery.py`、`verify-vita-release-270p.mjs`、`vita-270p-assets.mjs` 等）已随变体删除，见 [08](08-素材与安装.md) §5.1。

## 7. 仓库与许可

- 上游 `perf/render` 提交有 7 个 Python 文件以 CRLF 存储却声明 `*.py eol=lf`，新克隆会显示 7 个“修改”；本地可用 `.git/info/attributes` 规避（见报告/仓库约定），建议云端规范化提交。
- `knife/knife/src/game.rs` 仍残留约 7,722 个 CR（混合换行），不影响构建但会影响 diff 行数判读。
- `libshacccg.suprx` 为 Sony PSM 编译器模块（随包分发风险自行评估）；`SceShaccCgExt` 为 GPLv3（构建会把 NOTICE/LICENSE 打进 VPK）；7 个静态库有各自许可证（`vendor/dependencies/licenses/provenance.json`）。
- `doc/` 历史文档已从工作树清理，可从 git 提交 `a670193` 的 `doc/archive/` 恢复；`doc/evidence/` 保留 3 份机器可读证据 JSON。

## 8. 未验证清单（按优先级）

1. 终版 960×540 下的 FPS/work/EndScene/p50/p95/p99（需新捕获，且同 scene/PC、同素材）。
2. PS fetch 是否真正编译/接纳（GXP、反射、patch、capability），以及像素等价（alpha/边缘/rule/haze/soft）。
3. 组融合/文字缓存/stage-prefix/group-batch 的像素等价与命中收益。
4. r5/r6 修正的实际收益（复用帧 batch wait、scene 数）。
5. 启动工作集 DISP 重复解压是否消失（frame523 型约 0.86 s 停顿）。
6. 音频 underrun、CPU grade、消息入口约 0.8 s 等剧情覆盖后的收益。
7. taiHEN/固件差异对 PS fetch 的影响；跨 SDK core 链接。
8. 第三方依赖与编译器模块的许可/分发合规性。
