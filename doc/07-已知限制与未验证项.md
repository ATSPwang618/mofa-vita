# 已知限制与未验证项

1. **重场景不保证20FPS。** r10长日志最重完整窗口约12.75FPS、重绘78.496ms；不能把平均FPS或静态指令比例当作所有场景最低FPS。
2. **默认开启不等于单项验收。** 用户要求hardware-test默认启用Group bounds/Half/Tiled/Blur/Scene2等候选。r9/r10已有实际游玩反馈与日志命中，但没有全部候选逐项ABBA及全游戏RGBA8像素等价证明。
3. **资源失败仍需定位。** r11修复大UI整包NX输出及临时错误缓存；不是所有OOM、碎片化、卡损坏与驱动失败的通用保证。r14已实现无需菜单/纹理上传的自动保护存档，以及实际分配失败后的游戏层回收重试；未宣称恢复界面完全独立或所有内存不足都能恢复。本轮尚无实机长测结果。
4. **r12缺框修复待实机验收。** 六组焦点回归及130项游戏host测试、ARM/VPK检查通过。日志未捕捉到原缺框瞬间的完整状态，不宣称唯一原因已经被实机证明。
5. **专用Shader按合同回退。** rule/soft/group/Haze等组合不满足条件时保留完整处理；不能为覆盖率删效果。DXT在CPU调色等路径仍可能展开RGBA。
6. **模拟器不是实机结论。** 宿主OpenGL黑屏与实机GXM能力不是同一个问题。host数学、原生mock、ARM编译都不能取代设备像素与性能测试。

## 停止推广或已撤回

- stage-effect-r2前缀等改动没有可靠收益，已按实机结果回退；不能把它们列为当前新增收益。现有基础stage-prefix开关与该次失败实验不能混为一谈。
- r4 sparse-coverage保留独立对照、默认关闭；没有扩大到全游戏。
- 降演出分辨率不属于当前优化路线；原生场景/画布保持960×540。
- 丢弃mask/直接flatten组、逐层mask代替最终Group合成在实机导致效果或背景缺失，已废弃；2026-11-06维护已删除对应常量false的不可达实现。正确的Pixel/Mask表面路径保留。
- 任意多层“大Shader融合”、所有透明图改调色板、整包AT9、盲目扩大缓存/堆都不是已交付方案。

发生崩溃时保留版本日志、对应ELF/map与core；相同偏移不应跨版本符号化。见[日志](06-性能采集与分析.md)和[证据目录](evidence/README.md)。
