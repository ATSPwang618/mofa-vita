# 从原版数据制作资产包

设备上 `ux0:data/knife-woh-540p/assets/` 里的文件**不是**随仓库分发的：它们由玩家自己合法持有的
Switch 版游戏数据转换而来。这份文档记录完整链路、每步用什么工具、以及哪些步骤已在
`mofa-vita` 中实际跑通。

> 版权：游戏数据、字体、图像、影片、音频归原权利方。仓库只提供转换工具，不附带任何游戏内容。

## 链路总览

```
A. Switch romfs（用户自备）
      │  原始归档：jallpac.mrg/.hed/.nam、jallpachd、allui、parts、
      │            allscr.mrg、script_text.mrg、witch.bfsar、*.bfttf、movie/ stream/ en/ zc/ shader/
      │
      │  tools/kdu-compact.exe --romfs <romfs> <image-source>
      ▼
B. image-source：每张图解码为 PNG/JPEG + <archive>/manifest.json
      │
      │  python tools/create_compact.py          （重打包为运行时归档 + <archive>.compact.json）
      ▼
C. compact 运行时（*.mrg/.hed/.nam + *.compact.json）
      │
      │  python tools/make-vita-assets.py --compact C --out D
      │     内部：pack_dxt_540（PNG/JPEG → GXT DXT1/DXT5）+ create_native540（清单）
      ▼
D. Vita assets：同容器、纹理换成 GXT + vita-540p-assets.json
```

关键点：**容器格式不变**（仍是 `.hed/.nam/.mrg` 三元组，扇区 0x800），只把条目里的纹理从
BNTX/PNG/JPEG 换成 GXT。所以 Vita 侧读归档的代码与桌面版一致。

## 逐步说明

### A → B：从 romfs 取出图像

```powershell
tools\kdu-compact.exe --romfs <romfs目录> <输出目录>
```

`--romfs` 接受含 `jallpac.mrg` 等原始归档的目录。输出每个归档一个子目录，内含
解码后的 PNG/JPEG 与 `manifest.json`（记录每张图的来源、尺寸、编码）。

### B → C：重打包为运行时归档

```bash
python3 tools/create_compact.py ...      # 见脚本 --help；产物含 <archive>.compact.json
```

`.compact.json` 是转换审计：每个条目在归档中的偏移、尺寸、编码、物理尺寸。
后续 DXT 转换靠它定位，所以这一步不能跳过。

### C → D：转成 GXT 并生成清单

```bash
# 全量（约 3 GB，几十分钟；需要 Windows Python + Pillow）
python tools/make-vita-assets.py --compact <C目录> --out <D目录> --jobs 8

# 冒烟测试：只转 allui 的前 3 张
python tools/make-vita-assets.py --compact <C目录> --out .work/smoke --archives allui --limit 3

# 用项目的 keep-list：这些图保持原编码（渐变/软遮罩类，压缩会毁细节）
python tools/make-vita-assets.py --compact <C目录> --out <D目录> --keep tools/graded-images.txt
```

`make-vita-assets.py` 做三件事：

1. 逐个归档把纹理重写成 GXT：全不透明 → **DXT1**，含 alpha → **DXT5**（`psp2gxt` 封装并自校验）；
2. 复制不参与转换的运行时文件（影片、`witch.bfsar`、字体、脚本、语言表、`shader/` 等）；
3. 调用 `create_native540 --manifest-only` 生成 `vita-540p-assets.json`（逐文件 SHA-256，
   设备启动时据此校验，缺文件会报 `ASSETS REQUIRED`）。

可选 `--nx`：把转换后的条目再用 NXCX(zlib) 包一层，包更小，但每次加载多一次 inflate。

## 实测记录（在 mofa-vita 中跑过）

冒烟测试（`--archives allui --limit 3`）：

```
runtime files copied: 12
allui: {'gxt_dxt1': 2, 'gxt_dxt5': 50, 'kept': 1} in 1.0s
```

单个归档全量（`--archives allui`）：

```
allui: {'gxt_dxt1': 570, 'gxt_dxt5': 461, 'kept': 50} in 15.4s
```

- 转换后的 `allui` 含 1,081 个条目：570 张 DXT1、461 张 DXT5、50 张保留原编码；
- 每个归档旁会写一份 `<archive>.dxt.json` 收据（逐条记录 logical/physical 尺寸、GXT 字节数、
  格式校验结果）。

## 与出货包的差异

- 出货包的 `vita-540p-assets.json` 为 1,581,571 字节，统计 9,565 个文件；由完整链路
  （image-source → compact → GXT）生成。
- 同一个归档从不同上游包转换，字节数会不同（取决于上游是 PNG 还是 JPEG、是否已经过 compact 重编码）。
  判断一致性看 `vita-540p-assets.json` 里的文件清单与哈希，而不是归档总大小。
- `tools/graded-images.txt`（4,164 条）是项目的 keep-list：这些图保留原编码，
  转换时被跳过——复现出货包行为时必须带上它。

## 依赖与空间

| 项 | 说明 |
|---|---|
| Python | 需要 Pillow（`pip install pillow`）；`make-vita-assets.py` 在 Windows Python 3.13 上验证 |
| psp2gxt | vitasdk 自带（`$VITASDK/bin/psp2gxt`） |
| 磁盘 | image-source ≈ 3.5 GB，compact ≈ 4.2 GB，Vita assets ≈ 3.1 GB，另需临时空间 |
| 时间 | 单个 `allui`（1,081 条）约 15 s；全量按纹理数量线性外推为数十分钟（未计时） |

## 在设备上校验

1. 把生成的 `assets/` 整体复制到 `ux0:data/knife-woh-540p/assets/`；
2. 启动；若缺文件会打印 `ASSETS REQUIRED` 与缺失路径；
3. 想确认转换是否生效，开性能日志看 `build_tag`，并用 `doc/04` 的字段确认没有解码/上传瓶颈。
