# 素材与安装

> 适用范围：当前工作树（`perf/render` 提交 `a670193` + 文档重构）。本文面向使用者和素材处理者：素材包契约、设备路径、安装、构建变体、从原始数据制作与更新素材、常见故障。
> 标记约定：**[代码]** 当前源码常量/协议；**[历史实测]** 仓库历史真机捕获（r2/r3/r4，捕获分辨率 480×270/720×404，不等于终版 960×540）；**[未验证]** 仓库内没有设备/像素证据。
> 游戏本体、字体、音视频和汉化资源**不入库**，必须由使用者自备；编译 VPK 不需要素材，但运行时需要完整 `assets/`。版权说明见 §8。

## 1. 素材版本契约

当前引擎只匹配 **r7 native540 codec9** 素材包（根 `README.md`）。契约由素材清单 + 引擎内嵌 profile 双重固定：

| 项 | 值 | 来源 |
|---|---|---|
| 清单文件 | `assets/vita-540p-assets.json`，1,534,379 B | `knife/knife-platform-vita/src/asset_profile_540p.rs:6` |
| 清单 SHA-256 | `4cd6342dc7a97bc702964f89cc72ecfbfdc36455072fc143af10d7f99f57a816` | 根 `README.md`；`asset_profile_540p.rs:2` |
| schema / method | `knife-540p-assets-v1` / `native-540p-encoded-unorm-v2` | `tools/generate_vita_asset_profile_540.py:22-23` |
| colour contract | `encoded-unorm8-v1` | `:24` |
| render / display | `[960, 540]` / `[960, 540]` | `:25` |
| languages | `["en", "zc"]` | `:26` |
| codec 集合 | `{1, 2, 7, 9}`（禁止 8） | `:27` |
| stream 条目数 | 9,470 | `:33` |
| 启动校验规模 | 37 个关键文件、一次读取 4,485,062 B、单 8,192 B 缓冲 | `asset_profile_540p.rs:3-4` |

**容器与编码 [代码]**：素材仍是桌面同款 `.hed/.nam/.mrg` 三元组（扇区 `0x800`，`knife/knife-core/src/format/archive.rs:27`），只是把条目里的纹理换成 GXT。`KIMG` 头 32 B，编码枚举（`knife/knife-core/src/format/compact.rs:8-20`）：

- 1 `Jpeg`、2 `Png`、3 `Bc7Srgb`、4 `Bc7Unorm`、7 `PngUnorm`——仍需 CPU/硬件解码；
- 8 `GxtAlterSrgb`——历史 codec8：预烘焙 Alter 色彩，**当前不匹配**（`assets.rs:1224` 明确报错要求迁移 codec9）；
- 9 `GxtNativeUnorm`——当前包使用的原生块编码，按 UNORM 采样，不再走 Alter 目标（`compact.rs:16-19,79-81`）。

物理分辨率 960×540，逻辑坐标（1920×1080 脚本空间）保留在 `KIMG` 头中；双语文本用语言 strip 在运行时切行。`KATL` 图集与 `NX`（zlib/gzip）压缩仍按原格式读取，不改变归档索引。

`parts` 归档是唯一带本移植自有内容的素材：条目 0 `logo_fix`、1 `caution`，条目 2、3 是开机感谢页（`KIMG` codec7 `PngUnorm`，960×544，黑底全屏绘制）。它们由 `python3 tools/credit-intro/apply_credit_intro.py` 追加（保持前两条逐字节不变），源图与说明见 [tools/credit-intro](tools/credit-intro/README.md)。

**画面契约 [代码]**：场景、组 pixel/mask、UI 合成都固定 960×540，最终居中输出到 960×544 屏幕，上下各留 2 像素（根 `README.md`；`knife-render/src/vita.rs` 的固定 `RENDER/COMPOSITE` 尺寸）。程序不再读取 `scene-mode.txt`，也不接受运行时降分辨率配置。

## 2. 设备目录结构 [代码]

| 路径 | 内容 |
|---|---|
| `ux0:data/WitchontheHolyNight/assets/` | 完整素材包（`vita-540p-assets.json` 在根） |
| `ux0:data/WitchontheHolyNight/saves/` | 正式版存档（`knife-platform-vita/src/storage.rs:17`） |
| `ux0:data/WitchontheHolyNight/shader-cache/` | 运行时编译的 shader 缓存（10 个专用程序，命中则不再加载编译器；`knife/vita/runtime_shaders.c:42,184-185`） |
| `ux0:data/WitchontheHolyNight/` | 性能开关/优化开关根：`perf-enable.txt`、`optimization-profile.txt`（`vita_entry.rs:15,345`；`perf_switch.rs:12-13`） |
| `ux0:data/knife-woh-dev/` | **dev/探针**的独立数据根与存档（`storage.rs:16`） |

素材根路径固定为 `ux0:data/WitchontheHolyNight/assets`（`vita_entry.rs:11`）；原 `assets-540p` feature 切换（关闭时用旧 270p 根 `ux0:data/knife-woh/assets`）已随 270p 变体移除。启动错误屏会打印该路径（`boot_error.rs:8,18`）。

> 540p 正式版的数据根是 `ux0:data/WitchontheHolyNight`（素材、存档、性能开关、运行时 shader 缓存都在其下）。旧版用的是 `ux0:data/knife-woh-540p`，更旧的 shader 缓存位于 `ux0:/data/knife-vita/shader-cache`，新 EBOOT 都不再读取：从旧版升级时把整个旧目录重命名为新名字最省事（素材/存档/开关一次搬完），旧根与旧 shader 缓存目录都可删除，新缓存会在首次启动时重新编译落盘。存档写入走 `create_dir_all`，新根无需预先创建。

`perf-enable.txt` 也可放在 `assets/` 下（`perf_switch.rs:12-13`），内容只接受 `1`（允许 BOM/空白）；正式版默认静音，需显式重建/开关才能输出采集日志（见 [06-性能采集与分析](06-性能采集与分析.md)）。

## 3. 安装步骤 [代码]

1. **构建**（不需要素材）：`python3 tools/build-vita.py --check` 后 `python3 tools/build-vita.py game release`（根 `README.md`）。产物发布到 `release/knife-vita-game-540p.vpk`（`tools/build-vita.sh:80,87,188-197`）。
2. **安装 VPK**：TITLE ID `KNIF00540`，TITLE「Witch on the Holy Night 540p」（`build-vita.sh:85-89`）。
3. **复制素材**：把配套的完整 `assets/` 目录整体复制到 `ux0:data/WitchontheHolyNight/assets/`（根 `README.md`）。缺文件、混包或改过字节都会在启动时被 profile 校验拦下。
4. **启动**：从 LiveArea 启动。当前版本固定使用中文 ID2（`assets.rs:628,649`、`savedata.rs:766`、`vita_entry.rs:322` 的 override），存档写到 `ux0:data/WitchontheHolyNight/saves/`。
5. **更新**：只替换引擎（重装 VPK）不需要重拷素材；素材更新则必须整体替换，并按 §6 重新生成内嵌元数据后重新构建 VPK。数据根改名（`ux0:data/WitchontheHolyNight`）属于引擎侧改动：旧 `ux0:data/knife-woh-540p/` 下的素材与存档需要移动到新根，否则会报素材缺失并读不到存档。

**ATTRIBUTE2 [代码]**：native540 发布包默认 `ATTRIBUTE2=12`（0x0C，启用更大的 MAIN 内存档），由 `build-vita.sh:92-94` 导出，`vita-mksfoex` 写入 `param.sfo`；`check-vita-package.py` 对 `KNIF00540` 默认期望 12。该字段在**安装时**才生效，FTP 热替换 SFO 无效；改包后需覆盖安装。仅做 A/B 时才用 `KNIFE_VITA_ATTRIBUTE2=0|4|12` 覆盖。

**存档注意事项**：当前只有 540p 档位（270p 已移除），正式版数据根/存档根统一为 `ux0:data/WitchontheHolyNight`（`storage.rs:17` 的 `PRODUCTION_SAVE_ROOT`）；安装同 TITLE ID 的新包会落在同一存档目录，升级前建议先备份 `saves/`。

## 5. 从原始数据制作素材 [代码 + 历史链路]

**前提**：用户合法持有的 Switch 版游戏数据（base + 1.02 update NSP）、`prod.keys`、已安装固件；Windows 侧 Python 3.9+（含 Pillow；`make-vita-assets.py` 在 Python 3.13 上验证过）、可用的 `hactool`（`tools/prepare_game.py:19` 期望 `.tools/hactool/hactool.exe`）；`kdu.exe` 由本地 `build-compact.sh --kdu` / `build-windows.sh --kdu` 构建，不进仓库。

链路（工具均在 `tools/`）：

```
A. NSP + firmware ──prepare_game.py──▶ 原始 romfs assets 目录（+ 共享字体）
B. 540p + 汉化    ──create_540p.py───▶ dist/...-Chengkong-540p-x64/assets
C. 运行时归档     ──create_compact.py▶ dist/...-Chengkong-540p-Compact-x64/assets
D. Vita 纹理包    ──make-vita-assets.py（pack_dxt_540→GXT codec8，create_native540→清单）
E. codec9 迁移    ──migrate-vita-native-color.py（codec8→9，重写清单）
F. 内嵌元数据     ──generate_vita_asset_profile_540.py / generate-vita-atlas-index.py / generate-vita-stream-index.py
G. 重新构建 VPK   ──build-vita.py game release
```

逐步说明：

1. **A：从 NSP 准备素材** — `python tools/prepare_game.py --base <base.nsp> --update <update.nsp> --keys <prod.keys> --firmware <firmware目录> --out <assets>`（`prepare_game.py:158-191`）。脚本用 hactool 解出合并 1.02 RomFS，并从固件包里提取三份共享字体（`:20-27,112-155`）；密钥只在参数中传递、不复制不记录（`:1-6,96-109`）。产物附 `doc/assets-provenance.json` 与字体 provenance 缓存。
2. **B：生成 960×540 + 澄空汉化素材** — `python tools/create_540p.py --source <A目录> --mod <汉化MOD目录> --out dist/Witch-on-the-Holy-Night-Chengkong-540p-x64`（`create_540p.py:44-52`）。汉化 MOD 可用环境变量 `KNIFE_TRANSLATION_ROMFS` 指定；MOD 文件集固定为 `allui.mrg/script_text.mrg/zc/arshanghaisonggbpro_lt.otf/zt/SungASC-Medium.TTF`（`:58-61`）。脚本对四个归档按 `(缩放, 语言条带数)` 调 `kdu.exe compact` 重采样（`:18-19,101-121`），并逐归档记录 `asset-build.json`/`doc/540p-assets.json`。也可用 `tools/build-540p.ps1 -PrepareAssets -SourceAssets ... -ModRoot ...` 一键完成（`build-540p.ps1:20-31`）。
3. **C：生成 Compact 运行时归档** — `tools/build-compact.ps1 -PrepareAssets` 依次：构建 Windows Compact 引擎、构建 kdu 工具、`python tools/create_compact.py --jobs ... --ffmpeg ...`、`kdu-compact.exe --romfs <out>/assets verify-streams ...`、`python tools/verify_compact_assets.py`（`build-compact.ps1:33-49`）。输入默认 `dist/...-Chengkong-540p-x64/assets`（`:27`），输出 `dist/...-Chengkong-540p-Compact-x64`（`:44`）。产物含 `<archive>.compact.json` 审计，后续 DXT 转换靠它定位。
4. **D：转换为 Vita GXT + 生成清单** — `python tools/make-vita-assets.py --compact <C>/assets --out <D> --jobs 8 --keep tools/graded-images.txt`（`make-vita-assets.py:40-109`）。`pack_dxt_540` 把 PNG/JPEG 重写为 DXT1（全不透明）/DXT5（含 alpha）并逐条自校验，`--keep` 名单保留原编码（会被调色/软遮罩/语言 strip 的图不能转）；其余运行时文件原样复制；最后用 `create_native540 --manifest-only` 生成 `vita-540p-assets.json`（schema v1、method `native-540p-preserve-logical-v1`）。`--limit/--archives` 可做冒烟，`--nx` 可选再包一层 NX。
5. **E：codec8 → codec9 迁移（当前 r7 必需）** — `python tools/migrate-vita-native-color.py --source <D> --output <E>`（`--probe` 单条试跑、`--refine-existing` 只重做 RGB 拟合、`--jobs 2` 固定有界）。脚本解码 DXT 块、做 inverse Alter、重新压缩 DXT，保留 alpha 块；源清单必须是 `native-540p-preserve-logical-v1`，成功后把清单改为 `native-540p-encoded-unorm-v2`、`codecs=[1,2,7,9]`、`composite=[960,540]`、增加 `color_contract=encoded-unorm8-v1`，并输出 `native-color-migration.json` 收据（`migrate-vita-native-color.py:1-7,173,233`）。**这是第二次有损 DXT 编码**：收据明确 `lossless_recovery:false`、`second_lossy_DXT_encoding:true`，不是还原原始美术。
6. **F：重新生成内嵌元数据**（素材有任何变化都必须做，见 §6），然后 **G** 重新构建 VPK 使改动进入 eboot。

> 说明：仓库里没有官方 r7 素材包，上述顺序依据脚本接口与历史记录（旧链路说明可从 git 提交 `a670193` 的 `doc/archive/` 取回）。`create_540p.py` 的默认输入/输出面向本地 `dist/`；`make-vita-assets.py` 默认输出 `.work/assets`。**用当前脚本从头复现 r7 清单的完整命令未被仓库记录 [未验证]**，实际以清单哈希是否等于 §1 的 SHA 为准。

## 6. 更新素材后的元数据再生成 [代码]

Vita 启动时只读少量内嵌元数据来校验素材（不解压全包）；素材一变，下面三件套必须同步重生成并重新编译 VPK。若改的是开机感谢页美术，先跑 `python3 tools/credit-intro/apply_credit_intro.py`（追加 `parts` #2/#3 并同步清单数字；`--check` 只核对），再执行下表：

| 生成物 | 命令 | 说明 |
|---|---|---|
| `knife/knife-platform-vita/src/asset_profile_540p.rs` | `python3 tools/generate_vita_asset_profile_540.py [--assets <E>/assets] [--check]` | 逐文件 SHA-256（PC 侧全量校验），再为大文件只保留“长度 + 首/末 4 KiB CRC”；生成 37 条启动校验。`--check` 只比较不写（`generate_vita_asset_profile_540.py:71-83`） |
| `knife/knife/data/vita_atlas_index_540p.rs` | `python3 tools/generate-vita-atlas-index.py <assets> knife/knife/data/vita_atlas_index_540p.rs [--check] [--base-assets DIR]` | 只生成 `KATL` 的成员元数据（offset/len/logical/physical/encoding/GXT layout），不写像素（`generate-vita-atlas-index.py:1,62-68`） |
| `knife/knife/data/vita_stream_index_540p.txt` | `python3 tools/generate-vita-stream-index.py <assets>/vita-540p-assets.json knife/knife/data/vita_stream_index_540p.txt` | 从清单取 `stream/` 文件名并排序，生成 `# knife-stream-index-v1 <manifest sha>` + 9,470 行（`generate-vita-stream-index.py:1-15`） |

注意：atlas 索引要求 `<assets>/allui.mrg` 存在且与清单哈希一致，解析时做 NX 边界/KATL/KIMG/GXT 校验；stream 索引只依赖清单，不扫设备目录。生成后先 `--check` 通过再提交，最后重建 VPK（元数据在编译期嵌入）。

## 7. 验证与常见故障

**发布前验证 [代码]**：`python3 tools/build-vita.py --check`（环境只读检查）；构建流程自动跑 `python3 tools/check-vita-package.py <vpk> KNIF00540 --release`（检查 TITLE/ATTRIBUTE2/引擎-only 内容/编译器 SHA/LiveArea 图，`check-vita-package.py:40-90`）；素材侧可用 `python3 tools/verify_current_compact.py`（校验保留的 540p 素材/可编辑图）与 `tools/verify_540p_assets.py`（按 compact 记录对照原始输入）。三件套元数据可用 §6 的 `--check` 重现，保证与工作树一致。

**启动错误屏**：先画 `ASSETS REQUIRED`，再显示失败描述与具体路径（`boot_error.rs:16-29`）。按描述定位：

| 屏幕描述 | 含义 | 处理 |
|---|---|---|
| `MISSING FILE OR FOLDER` | 素材根不存在或清单里的文件缺失 | 确认路径 `ux0:data/WitchontheHolyNight/assets/`，重新完整复制 |
| `WRONG FILE SIZE` | 文件长度不对（复制中断/混入别的包） | 重新复制完整包，不要增量覆盖 |
| `WRONG ASSET VERSION` | 同长度但内容 CRC 不符（错误版本/混包/旧 codec8/未更新 parts 归档） | 换成 §1 清单对应素材（含追加过感谢页的 `parts.hed`/`parts.mrg`/清单） |
| `FILE READ FAILED` | 路径不是普通文件、读取失败 | 检查目录/权限/存储卡 |
| `ENGINE PROFILE ERROR` | 引擎内嵌 profile 本身非法（构建问题） | 重新生成 profile 并重建 VPK |

其他常见问题：

- **码 8（`GxtAlterSrgb`）报错“requires the native-colour asset migration (codec9)”**：装的是旧 codec8 包，需按 §5-E 迁移或换 r7 包（`assets.rs:1224`）。
- **ATTRIBUTE2 未生效/内存档不对**：SFO 只在安装时读取，必须重装 VPK；A/B 时显式设置 `KNIFE_VITA_ATTRIBUTE2` 并核对包。
- **装错旧包**：本版固定 `KNIF00540` 与数据根 `ux0:data/WitchontheHolyNight/`；旧 270p 包（`KNIF00270`）与旧素材根已随变体移除，不要把旧版素材/存档继续放在旧路径或混入新素材包。
- **存档被覆盖/丢失**：同 TITLE ID 会共用存档目录，升级前备份 `saves/`。
- **运行时没有采集日志**：确认 `perf-enable.txt`（内容只有 `1`）且版本不是 `KNIFE_VITA_QUIET=1` 的正式静音包，详见 [06](06-性能采集与分析.md)。

## 8. 素材不入库与版权

- `.gitignore` 明确排除 `dist/`（本地素材）、`.work/`、`/release/`、`*.vpk`、`/saves/`、`/savedata/` 等；仓库只提供工具与生成元数据，不包含游戏内容。
- 游戏数据、字体、图像、影片、音频及汉化资源权利归各自权利方；转换产物仅供持有正版的用户在本机使用。
- 引擎为 MPL-2.0（`knife/LICENSE`）；随包 `SceShaccCgExt` 为 GPLv3，构建会把 NOTICE/LICENSE 打进 VPK（`build-vita.sh:170-180`）；7 个原生依赖与 `libshacccg.suprx` 的许可/分发合规性需自行评估（见 [07](07-已知限制与未验证项.md)）。
