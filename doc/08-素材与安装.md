# 安装与设置

安装包与资源必须属于同一次交付。当前输出使用标准 `ux0` 目录结构，
不再以历史候选包名称区分安装位置。

## 安装和升级

1. 用 VitaShell 安装 `dist/mofa-vita.vpk`，应用 ID 为 `KNIF00540`。
2. 关闭游戏，把 `dist/ux0/` 内的内容按同名目录复制到设备的 `ux0:`。
3. 完整替换资源目录，保留同级的存档、设置和日志，不叠加不同版本的资源。

| 设备路径 | 内容 |
|---|---|
| `ux0:app/KNIF00540/eboot.bin` | 游戏程序，交付目录内副本与 VPK 一致 |
| `ux0:data/WitchontheHolyNight/assets/` | 完整资源，含分卷、`savethumb` 及两个音频 bank |
| `ux0:data/WitchontheHolyNight/` | 存档、设置与日志配置 |

当前资源保留 70% 变体缩放与固定 PVRTC2 / DXT 策略。
语音和音乐分别为 `voice.mrg`、`bgm.mrg`，无需散装 `stream/`。
VPK 不包含游戏资源或 Sony 编译器模块；需要运行时 shader 回退时，
使用设备已有的 `ur0:data/libshacccg.suprx`。

只更新程序可使用 [VitaDeck 工具](../tools/vitadeck/README.md)，但程序内编译的清单不会随
PC 资源文件自动变化。资源变化后须[同步元数据并重建 VPK](03-构建与工具链.md)。

## 清单和验收

```powershell
python prepare-mofa-vita.py --check
python vita_asset_pipeline/build_binding.py --assets dist/ux0/data/WitchontheHolyNight/assets --check
```

第一条完整检查资源，第二条检查它与项目编译元数据的绑定。
交付身份集中在 `dist/ux0/data/WitchontheHolyNight/delivery.json`、
`asset-validation.json` 和 `dist/companion-binding.json`；
项目绑定见 [vita_asset_binding.json](../knife/knife/data/vita_asset_binding.json)。
安装页不重复固定哈希，以免后续交付后继续指向旧版本。

设备启动时的大小/CRC 检查只覆盖启动合同，不等于 PC 全文件 SHA 验收。
旧 `tools/verify_final_delivery.py` 面向历史 103 文件锁；
当前使用来源不同的 logo 与实际清单，应使用上面的新入口。

## 阅读、背板与剧情操作

在支持组合键的标题或剧情界面按 **L+□** 打开设置：
↑↓选择、←→调整、○确认、×或再次按组合键取消。菜单打开时暂停剧情，屏蔽输入穿透。

| 配置文件，位于数据根目录 | 规则 |
|---|---|
| `story-font-size.txt` | 剧情字号 50%–150%，5% 步进，默认 100% |
| `l2-r2-mode.txt` | 0 关闭、1 左右全区、2 上半、3 下半 |
| `rear-touch-debug.txt` | 0/1，默认关闭 |

字号改变重排当前页并保留显示进度，长段落跟随已显示行滚动；菜单和书库字号不随之改变。
取消恢复原设置。确认先关闭菜单，再分别写配置；写盘失败仅告警，
三个文件不是原子事务，持久化应通过重启或读取文件确认。

Vita 书签栏的快退、快进、上一场景和下一场景按钮禁用，
自动播放、存读档书签和语音保留。R 及背板快捷输入策略独立保留，
不能根据灰色按钮推断全部快捷操作都禁用。策略源码为
[story_controls.rs](../knife/knife/src/ui/story_controls.rs)。

资源故障后，仅在明确提示保护成功或日志 `resource_checkpoint.status=saved` 时，
才认为自动槽已写入。“继续游戏”恢复最近有效节点，手动/快速槽不覆盖。
日志与排查见[诊断](06-性能采集与分析.md)，实机验收边界见[限制](07-已知限制与未验证项.md)。
