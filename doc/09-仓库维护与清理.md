## 3. 清理边界

不要删除当前两个资源目录、源码、Cargo 锁文件、vendor 库/头/许可证、生成的 shader/profile/atlas/stream 索引、感谢页源图或实际玩家存档。

旧临时目录只有在确认没有唯一源文件、运行数据、存档及链接/目录联接后才删除。递归操作使用本机同一套 PowerShell 路径处理，先解析绝对路径并确保位于本仓库，禁止用全仓库 `git clean -fdx` 或宽泛通配符清理。

Git 的 `.git/` 保留正常历史。不要为了释放几十 MiB 改写提交历史或强推；没有新的明确推送指令时只修改本地。

## 4. 每次发布后的整理

1. 构建会生成 `.work/vita/game-release-540p/` 和 `release/`。把选定版本的 EBOOT/VPK/收据更新到唯一运行目录，并核对包内 EBOOT 一致性。
2. 素材变化时同步其清单和三个内嵌元数据，再构建配套 EBOOT；资源与引擎必须匹配。
3. 比较新运行包、可编辑图片的清单/哈希，确认唯一版本可用后，删除旧备份、中间图、临时验证资源和重复压缩包。
4. 只保留最新 ELF/map 与小体积验证摘要。构建收据列出的临时文件可以清理，收据保留其构建时身份。
5. 感谢页脚本支持从现有四条目归档读取前两条原始内容；清理旧备份后 `--check` 和更新感谢页仍可执行。

当前工具检查示例：

```bash
python3 tools/check-vita-package.py dist/Witch-on-the-Holy-Night-Chengkong-540p-Vita/knife-vita-game-540p.vpk KNIF00540 --release
python3 tools/generate_vita_asset_profile_540.py --check
python3 tools/credit-intro/apply_credit_intro.py --check
```

profile 检查只读取关键素材；完整数据校验还需按素材清单逐文件比较大小和 SHA-256。可编辑工程的每个归档 `manifest.json` 列出输出文件身份。主机校验不替代实机性能回归。
