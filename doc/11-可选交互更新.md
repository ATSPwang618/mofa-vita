5. 用户追加授权后，引入 `b7d5b51` 的 CDRAM 余量误判修复；排除同一提交中的快进旧帧处理改动。

## 剧情字号（追加接入）

同一 `L + □` 菜单现在有三项：剧情字号、背板映射、背板调试。↑↓ 选择，←→ 调整；字号范围 50%–150%，每次 5%，默认 100%。○ 保存，× 或再次按组合键取消，恢复进入菜单前的字号与背板设置。菜单开启时暂停剧情和屏蔽输入，字号实时预览。

`ux0:data/WitchontheHolyNight/story-font-size.txt` 保存整数百分比；启动读取，缺失或非法值回到100%。仅当字号不同于打开菜单时的值，○才写入字号文件；字号写入失败记录警告并保留菜单，允许重试或取消。背板两项另行写入，三份配置并非原子事务。启动日志打印 `story_font`，预览和保存也记录百分比。

字号改变调用生产文本重新排版，缩放字号、字距、行高、ascent 和 ruby 偏移，保留文本框横向边界与顶边。重新布局保留原段落 extras、读入淡出、已显示字数（限制到新字数）、waiting/visible、slot_flip、随机数和 z 状态；字形抖动沿用原记录。放大后只根据已显示行计算向上滚动量，推进图标同步移动。正常100%保留原排版数值、滚动为0；菜单与书库文字不会随剧情字号放大。

只在字号实际变化时重排，不新增全屏离屏目标，也不放宽字形缓存预算。放大后实际绘制的文字面积可能增加，不能据此承诺零性能开销。极长段落、特殊气泡、ruby/抖动文字及取消预览效果仍需实机确认；自动测试不代替设备像素验收。

本轮使用独立 `-story-font-local` 构建标识，来源仍为 `ux-optimization@8680c46`，没有带入上游同文件的快进旧帧释放改动。见[字号接入收据47](evidence/47-story-font.json)。

## 配置与状态合同

| 项目 | 实现规则 |
|---|---|
| 文件内容 | 整数50～150且为5的倍数，如 `125`；允许首尾空白。`125%`、`149`、空内容等回到100% |
| 读取时机 | 启动时读取一次；运行时在菜单内修改，手动编辑文件需重启 |
| 保存时机 | ○确认且字号改变时写入；×或再次按组合键只恢复内存预览值，不写字号文件 |
| 存档关系 | 字号为应用级偏好，不记录到剧情槽，不改存档格式；读档使用当前字号 |
| 排版度量 | 缩放size/spacing/line_height/ascent/ruby_y；left/right/sx保留，基线调整保持文本顶边 |
| 显示进度 | 重排后将原revealed限制到新order；保留waiting、visible、msg_pc及slot_flip |
| 演出状态 | 使用保存的段落extras与z记录，恢复app RNG和z_cur；匹配类型的字形抖动记录继续使用 |
| 跟随滚动 | 仅字号大于100%时，根据 `order < revealed` 的行计算底部溢出；文字与推进图标使用同一偏移 |
| 输入边界 | 标题/剧情界面识别组合键；单独L/□松开触发，其他界面保留原处理；菜单关闭帧及仍按住的键受抑制 |

源码定位见[架构总览](01-架构总览.md)，日志辨识见[性能采集](06-性能采集与分析.md)。重新排版暂时保留旧字符并生成新字符，有临时CPU内存成本；不将预算不变描述为零开销。

## 背板设置

标题或剧情界面按 **L + □** 打开阅读/背板设置菜单。↑↓ 选择，←→ 修改，○ 保存，× 或再次按组合键取消并恢复原值。菜单打开时暂停剧情并屏蔽输入穿透。单独 L、□ 在这两个界面松开后触发，以区分组合键；其他界面保留原输入处理。

| 模式 | 映射 |
|---|---|
| 0，默认 | 关闭，不逐帧读取背板数据 |
| 1 | 左半边 L2，右半边 R2 |
| 2 | 左上 L2，右上 R2 |
| 3 | 左下 L2，右下 R2 |

映射产生原有 `Pad::ZL/ZR` 输入，仍受各界面的按钮策略控制。它不会重新开启剧情快进、快退或前后场景跳转。背板不可用时记录警告，其余输入继续工作。

配置位于 `ux0:data/WitchontheHolyNight/`：

- `l2-r2-mode.txt`：0–3，缺失或非法时为 0。
- `rear-touch-debug.txt`：0/1，默认 0；只有开启时才绘制触摸诊断。

## PS 图标与资源

提示图集 `help_key_ps` 为 384×256；中文手柄页 `conf_manual0_ps` 的物理尺寸为 960×540，保留 1920×1080 逻辑坐标。均作为 codec-9 DXT5/GXT 内嵌，使用现有延迟上传、回收和重载流程。PNG 只作为可编辑输入，运行时不解码这些 PNG；游戏归档和资源清单无需改写。

两份 GXT 压缩像素载荷分别为 128 KiB、1 MiB，替代对应原图，不代表零开销或已经证明帧率不变。

修改 PNG 后，使用 quality540 同款依赖（Pillow、numpy、ispc_texcomp 1.0.1）生成：

```bash
python3 tools/prepare-vita-ps-help.py help_key_ps
python3 tools/prepare-vita-ps-help.py conf_manual0_ps
```

## 追加修复：CDRAM 余量误判

先执行现有回收、缓存预算和帧级准入检查。只有“缓存预算满足，但原生剩余 CDRAM 读数不足、没有可驱逐纹理”这一特定错误，才允许源图片进入实际驱动分配。正常情况下流程与此前相同；这不扩大任何内存预算，也不将 DXT 展开成 RGBA。

- 立即图片上传、延迟 GXT/DXT 和延迟 RGBA 准备使用同一错误分类。
- 延迟缓存预算超限、无效纹理和其他驱动错误不因本修复放行。
- 离屏渲染目标保持严格准入，沿用原有游戏层回收回调。
- 实际分配失败仍执行已有的有界恢复；无可回收纹理时初次尝试加一次排空后重试，存在闲置纹理时最多再逐个回收 8 个。帧级恢复仍有原有独立限制。
- 未完成准备时不提交半帧，不释放当前帧固定的纹理；真正耗尽时仍可能报资源错误，不能声称彻底消除所有资源失败。

上游注释描述的是 Vita3K 可用空间读数滞后的情形。本次针对该行为做 host 故障注入测试；尚无新增实机证据证明之前的设备错误均由这个原因引起。

## English

This selectively imports rear-touch L2/R2 configuration, PlayStation button artwork and GitHub Actions from `ux-optimization@8680c46`. Story font scaling/reflow/scrolling was subsequently authorized and selectively integrated. Restored skip/rewind, PNG decoder changes and compressed SELF packaging remain excluded. A separately authorized fix now allows image allocation to decide when the reported native CDRAM headroom may be stale, after the existing reclaim/admission path. Cache limits and strict render-target reservations remain enforced.

Press **L + Square** on the title/story screen to open reading/rear-touch settings. Font size defaults to 100%, ranges from 50% to 150% in 5% steps, and is persisted in `story-font-size.txt`. Changing size reflows current text while retaining reveal progress and RNG state; enlarged long passages follow the revealed line. Cancel restores the opening values. Use Up/Down to select, Left/Right to change, Circle to save, and Cross to cancel. Modes: 0 off (default), 1 full left/right halves, 2 upper halves, 3 lower halves. Diagnostics default to off. Individual L/Square actions fire on release in these screens to distinguish the chord. Rear input remains subject to existing disabled story-control rules.

The embedded help textures are offline DXT5/GXT assets; their PNG sources are not decoded at runtime. The Chinese controller page retains the local disabled skip/rewind policy. Device behavior and performance still require hardware verification. No remote push or deployment is performed.
