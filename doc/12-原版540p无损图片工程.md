## 像素尺寸与逻辑尺寸

| 类型 | 物理采样规则 |
|---|---|
| `jallpachd` / `allpachdml` | 高清原图×0.5 |
| `jallpac` / `allpacml` | 普通原图×0.75 |
| 普通UI | 按1080p逻辑密度×0.5；不根据名字中的x数字猜倍率 |
| 原版缩略图 | 按 `THUMSP_TOP` 索引边界识别，保留原尺寸 |
| 规则/灰度控制图、极小或薄控制图、字体图页 | 保留原始采样，按用途另行封装 |
| `BORDER_PARTS` | 完整保留原尺寸和查找数据 |
| 原版两张全屏启动图 | 分别按1280×720或1920×1080归一为960×540 |

960×540是最终画布，不是每一张纹理都必须装入的外框。全屏背景从1920×1080变为960×540；住宅街长图`IMG2331`从2100×2940变为1050×1470。它多出的高度供镜头平移使用，强行压到540高将重新造成放大模糊。

原始逻辑宽高必须留在KIMG/KATL。生产`assets.rs`用逻辑尺寸计算演出四边形；UI也用原坐标计算UV。不能用PNG的缩小尺寸覆盖原始逻辑尺寸、图集坐标或锚点。

所有图从mip0解码，使用一次Lanczos缩放。透明图用浮点预乘alpha过滤并恢复直通颜色；零alpha区域保留过滤的隐藏RGB。输出RGBA8无损PNG，无JPEG/DXT/WebP中转、无调色板量化和额外锐化。无损PNG不能恢复原版BC7/JPEG已经丢失的信息，缩小本身也有采样损失。

## 语言条带合同

读取生产`knife/knife/data/exe_tables_witch.bin`中的84个`ImageInfo.language_strips`标记，而非凭归档名判断。原版四语言顺序ja/en/zc/zt。

与生产`assets.rs`一致：第k段从`floor(k*H/4)`开始，取`floor(H/4)`行。高度155时四段为[0,38)、[38,76)、[77,115)、[116,154)，不能改成等分端点后长度不一的四段。每段独立过滤，避免读到相邻语言颜色。

打包时按清单成员重组物理条带，逻辑整图尺寸仍用原值。现有Vita包只有en/zc两语言；原版中文不等于澄空汉化，不能混用旧`language-profile.txt`、脚本计数、UI别名和启动身份。

## 运行性审计

本次交付是经比例校正的图片母版，**不是整套已经验证可运行的最高画质包**。未修改或打包EBOOT/VPK，未实机验证。

| 2026-11-14运行边界 | 新母版审计结果 |
|---|---|
| 压缩纹理单边≤2048 | 原版四语言重组3,967个超限；选择en/zc后仍3,879个 |
| 延迟DXT路径总像素≤960×1080 | 部分大长图无法直接登记；与PNG解码边界不是同一条件 |
| PNG原生解码宽≤960、高≤1080 | 四语言重组有10,317个纹理不满足尺寸检查 |
| 剧情彩色图整图RGBA离线限额1MiB | 四语言重组15,915个纹理超过现行契约 |

统计按归档纹理计算，包含普通/高清副本及语言整图，不是独立场景数量。`Vita部署检查.csv`中的DXT大小是按当前PoT backing推算的分配，不是设备实测；RGBA整图/单语言尺寸分别列出。R8及查找纹理的建议编码与假设DXT估计也明确分列，不能把所有估算直接相加当作运行峰值。

960×540 RGBA8载荷为2,073,600 B，当前页面计费为2MiB；所以1MiB离线契约本身就装不下这张完整RGBA图。DXT能减小常态采样占用，但CPU调色、raw及语言裁切可能走展开路径。只放宽限制、只改容器后缀或直接替换PNG，不能同时保证清晰度和稳定性。

本次只记录现行限额下的候选尺寸，没有再次对母版套用该限额。若要做运行包：普通图正确编码并保留逻辑坐标；超限长图需要验证分块/可见区域加载或接受逐图降采样；还需重建图集、语言映射和资源身份，测试峰值及高压演出。没有把全部PNG缩到960×540来掩盖这些问题。

相关实现：

- `knife/knife/src/assets.rs`：逻辑尺寸、语言裁切、软裁剪查找表与PNG/DXT选路。
- `knife/knife-render/src/vita.rs`：2048单边、压缩像素上限、行距及分配核算。
- `knife/knife-platform-vita/src/image.rs`：PNG/JPEG原生解码输出尺寸合同。
- `tools/vita_image_metadata.py`及`tools/quality540/limit_runtime_art.py`：当前运行包1MiB整图离线契约。

## 输出和重建

`图片索引.csv`包含原整图尺寸、裁切宽高、目标比例、实际横纵比例；语言图片的原整图高度与输出高度不能直接相除。`Vita部署检查.csv`列逐纹理部署障碍；`manifest.json`固定来源与输出身份；`metadata/scaling-audit.json`记录审计，`metadata/vita-deployment-plan.json`记录逻辑纹理重组。PASS只适用于报告声明的检查。

```powershell
python -B tools/test_export_original_switch_png.py
python tools/export-original-switch-png.py --romfs <新解包RomFS> --source-receipt <source.json> --out <空目录> --jobs 6
python tools/finalize-original-switch-png.py --romfs <新解包RomFS> --out <同一目录> --decoder-check <生产解码器抽样记录> --kdu <宿主kdu.exe>
python tools/repair-original-switch-scaling.py --project <同一目录> --romfs <新解包RomFS> --apply --jobs 6
```

finalizer负责BC3生产解码一致性、BC4插值、原生字体图页、缩略图及混合分辨率启动图。repair负责生产表裁切、特殊查找图、全量文件/像素/原归档SHA和兼容性清单。`--apply`只在源与旧输出哈希匹配时修正；不覆盖用户已编辑的图片。
