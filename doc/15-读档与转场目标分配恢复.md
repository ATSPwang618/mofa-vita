# 读档与转场目标分配恢复

2026-11-03，本地交付版本 `540p-d734b38-targetfix-20261103`。本次针对读档/转场时创建离屏目标失败导致的退出，继续使用现有的离线限额素材。机器可读证据见 [20-save-load-target-recovery.json](evidence/20-save-load-target-recovery.json)。

## 崩溃证据

用户提供的 `psp2core-1793706965-0x0000092a39-eboot.bin.psp2dmp` 与分析时的 `log.txt` 对应 `540p-d734b38-prebudget-20261102`。core 的模块指纹 `0xed8bf386` 与当时 EBOOT 匹配，按模块装载基址还原地址后，停机点为 `_kill_r` 的 `udf #255`：Rust panic 进入 SIGABRT 后主动终止。

core 的 TTY_INFO2 保存了完整 panic：

```text
creating Vita scene target: creating render target old frame
native texture allocation failed after 10 bounded attempts
GXM: effects texture CDRAM allocation: 0x80024309
```

`0x80024309` 是 VitaSDK 的 `SCE_KERNEL_ERROR_NO_FREE_PHYSICAL_PAGE_CDRAM`。触发点是 `Game::render` 创建 `old frame` 时调用不可失败接口；该全屏可写 RGBA8 目标的物理尺寸为 960×540，按原生页计费为 **2 MiB**。素材单张潜在 RGBA 限制为 1 MiB，并不限制这些运行时合成输出。

最后一个性能内存样本比 panic 早约 5 秒；当时 heap headroom 约 89.57 MiB、kernel CDRAM free 为 14 MiB。core 中 CDRAM memblock 共 93 MiB，其中参数缓冲占 16 MiB。不能把早前的空闲数当作分配瞬间的连续空间，也不能仅靠 memblock 名称唯一证明泄漏、碎片来源或每张离屏目标的归属。日志未见存档写入/回读校验失败，具体读入的槽位也未被现有记录完整证明。

## 修复范围

在 `knife/knife/src/game/producer_reuse.rs` 中，已有的 stage/canvas 备用输出可转交给 `old frame`。复用前核对逻辑与物理尺寸，排除当前 stage、scene、canvas 的身份，转交后清零 ring 的占用计数并设置原有的重试间隔。转交只改变所有权，截图仍按原顺序从上一场景复制；不新增纹理分配或额外的像素副本。

在 `knife/knife-render/src/vita.rs` 中，干净的显存分配/准入不足使用独立错误类型标记。必需目标首次失败后，Game 有一次机会释放可选 ring、group/prefix 缓存和当帧未使用的文字缓存；完成原生退休栅栏后，再进行一次有限分配恢复。驱动/退休错误不冒充显存不足，不以更多淘汰循环处理。

每个分配恢复周期沿用原来的上限：一次初始申请、一次完成回收后的重试，以及最多 8 个空闲 deferred 驻留受害者。必需目标最多经过两个周期、一次 Game 可选缓存清理。日志中的 `released_bytes` 是被放弃的 owner 计费量；当前 encoder 或其他读者仍持有的存储，必须等待实际引用和栅栏释放，不能把该字段当成已经回到内核的字节数。

Game 中动态创建的 `old frame`、noise RT40、ghost 双目标、blur、group pixel/mask、菜单捕获/defocus 和 freeze 截图接入 fallible 接口。录制过程中失败会进入与帧准备相同的恢复分支：丢弃尚未提交的 encoder，恢复上一完整 stage/canvas、待完成的 snapshot/freeze 标记及原 noise owner，失效相关 producer/cache 键，然后通过现有资源错误 UI 暂停脚本。即使 old frame 尚未创建，后续暂停帧也不会继续解引用缺失的转场捕获。

菜单/存档的动态背景、书库发光、CG 变体捕获和乐曲鉴赏光效同样改为 fallible 创建。申请失败时跳过相应效果，操作和当前基础内容继续绘制。双目标在全部成功后才写入字段；半途失败的临时目标按原 RAII/原生退休路径释放。

Vita 存档缩略图排在必需目标之后生成。分配失败保留请求；只有该 encoder 成功提交后才发布新缩略图，丢弃的帧不会把未初始化纹理放入预览缓存。正常情况下首次缩略图会在后续 UI 帧显示。

本次变更集中在 9 个 Rust 文件。原生 C/GXM 实现、图层合成算法、960×540 scene/composite、60 FPS pacer、内存预算、存档格式与图片数据保持现有实现。普通帧没有新增完成等待；新增退休等待只发生在分配压力恢复分支。

## 验证

- 首先增加分配失败回归；修改前 `old frame` 的 fallible 分配错误未带 `FramePreparationError`，断言确实失败。记录保存在本机 `.work/vita/target-recovery-20261103/red-target.log`。
- 渲染 host 测试串行 **114 项通过，0 失败**，包含本次新增 8 项：实际申请失败而空闲查询充足、全/半/四分之一目标准入不足、一次清理后的成功和持续失败、非显存驱动错误、退休失败停止重试、备用目标尺寸/别名排除，以及连续 **64 轮** 捕获释放回到同一 native 内存基线。
- 真实 ARM Vita release 构建通过，`KNIF00540`、`ATTRIBUTE2=12`、256 MiB heap、控制台日志开启。VPK 的 21 项内容、ZIP CRC、内置 EBOOT 与同名交付 EBOOT 一致性均通过校验。
- 308 个构建输入和 10 个构建输出的 SHA 全部核对。ELF 包含本次版本号及分配压力/备用目标复用日志字符串。
- 现有素材清单和 **9,564 个资源文件**逐一核对 SHA 与大小，载荷总量仍为 **2,201,729,082 B**。

host 使用严格的 native 记录器，验证分配、所有权与提交边界，不执行 GXM shader，也不测量实机帧率。本次未运行新的实机或模拟器回归，不能把 64 轮 host 测试描述成 64 次实机读档。已提交帧的驱动故障仍按原错误路径处理；这次恢复面向尚未提交帧的动态捕获分配失败，不承诺任意驱动、任意工作集都永不失败。
