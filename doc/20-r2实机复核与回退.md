本页记录当时的回退交付版本 `stage-effect-r2-reverted-20261105`。已按用户要求撤回上一轮 r2 三项生产优化，恢复 r2 之前的运行路径，保留更早的输入、资源恢复、音频缓冲、渲染优化与日志。仅修改本地 `perf/render`，未提交、未推送。后续重场景 op7 候选包见 [21](21-重场景op7专用着色器.md)，本页的回退范围和历史对照不因此改变。

## 为什么回退

新版 `log.txt` 记录的 build 为 `stage-effect-r2-prefix-20261105`，文件 2,186,353 字节，SHA-256 为：

新旧日志的 scene、素材身份、960×540 和时钟设置相同，但输入节奏/动画阶段不完全同步，属于描述性比较。优先比较相同 PC 端点、全重绘的窗口，不拿对白复用占比不同的全局平均值作收益结论。

以上窗口 prefix 均无命中，变化不足以证明有实用提速。最慢的 PC1246 仍是双组路径，31 次 group plan、62 次 group fused，其原本就不经过纯 Stage prefix。

prefix 确实运行了：累计 52 hit、2 miss/2 build，记录减少 172 个 draw，显存峰值 2 MiB；命中仅在 PC1510→1539 和 1539→1545 两段。功能生效不等于达成重场景提速目标，本次撤回理由是收益不足，不是计数未运行。

PC1849、2063 的部分新窗口平均 FPS 更高，但重绘/复用比例与 r1 不同。例如1849包围窗口从186重绘/16复用变为19重绘/269复用，不能归功于本次修改。

新日志收到81个sample及对应完整分类/audit；控制台报告丢25批，另有2条坏JSON、1个缺片payload、一个11/45 bank的不完整audit和一个缺sample的完整audit。后段局部差分有恢复限制，不能据此声称全程无错误。已收到的资源事件无failed、worker_failed=0、设备音频underrun=0；最低CDRAM空闲11 MiB。完整解包/比较在本机 `.work/vita/effect-r2-evaluation/`，紧凑摘要为 [25-stage-effect-r2-rollback.json](evidence/25-stage-effect-r2-rollback.json)。

## 精确回退范围

- `stage_prefix.rs` 恢复整列表的资格限制与列表等长检查，移除 r2 对可写/预烘焙输入及动态后缀的放宽。
- `vita.rs::try_draw` 移除 r2 的 `None + []` 早退，恢复此前的 generation/pass 行为。
- 原生 present 恢复 `kv_gxm_begin(clear)`，撤销 r2 的无 clear 私有入口。
- 删除对应 r2 新测试/runner，恢复原 prefix 负对照；保留此前 r1 测试。原 native present fixture 的双槽 notification 数组修正保留，它只影响 host 测试，不改变游戏可执行路径。
- 继续保持默认控制台日志、版本号、原有 960×540 画布、素材、关闭手动快进与 L 自动播放。

没有使用全仓 reset，原来未提交的用户/前轮修改保留。四个回退生产文件均与 r2 之前版本一致；其它 r1 改动不在这次撤销范围。

## 下一条优化方向

下一步应针对 PC1246 真正执行的混合程序减少像素计算，而非继续扩大 prefix 或纹理缓存。r2 的 frame8077→8108 共31帧，实际提交的 PS 操作计数差分为：

| 操作 | 次数 | 平均/帧 |
|---|---:|---:|
| op1 Add | 59 | 1.90 |
| op6 Dodge | 31 | 1.00 |
| op7 DodgeAlpha | 141 | 4.55 |
| op13 Overlay | 62 | 2.00 |
| op19 Normal | 62 | 2.00 |

合计355次与native `draw_ps`一致。专用ps13仅31次、plain19为62次，余262次走通用PS路径，op7是明确的优先候选。这是draw次数，尚不代表覆盖面积或GPU独占时间。

当前通用shader17的本机加载metadata为primary570；plain sprite22为9、plain PS19/23为25。编译指令数不等于每像素固定执行条数，但说明通用路径包含更多源准备、模式判断与寄存器需求。方案分为：

1. 对这段的 op7 区分 Sprite/Fill/NoAlpha 简单材质与 haze/soft/rule/masked 等复杂材质，记录实际物理覆盖、chosen shader 和次数；复用已有PS op计数，不重复造全局统计。
2. 若简单材质占足够覆盖，只增加一个 op7 专用入口，保留原公式、零alpha返回、DodgeAlpha零分母边界与逐draw UNORM8 pack；失败沿现有shader17/快照路径回退。复杂材质继续原路径。
3. 用数值边界、alpha、Fill/NoAlpha、纹理/目标别名、能力失败和命令路由测试，再在PC1246对照batch wait与work。只在证据支持后扩大到op1/op6或组专用入口。

新shader会有少量程序资源成本，但不需要新的整屏RT或纹理缓存，也不更改分辨率和同步。该方向尚未实现或实机验证，不能承诺20 FPS。另一个候选是按fresh pixel/mask有效覆盖裁剪group composite，其需证明透明区和目标alpha语义，不能直接按矩形边界粗裁。
