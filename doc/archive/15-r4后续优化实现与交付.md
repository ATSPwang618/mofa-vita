# r4 后续优化实现与交付

本轮按 [r3 日志分析的 P0–P6](14-r3真机日志对照与剩余瓶颈.md) 落实后续代码与监控。原始 r2 基线及 r3 捕获保持不变。最终构建身份和检查结果见 [r4-build-verification.json](../performance/r4-build-verification.json)；逐项状态见 [r4-implementation-status.json](../performance/r4-implementation-status.json)。整包 Docker ARM 优化构建、SELF生成与VPK检查已经完成。

“完成”指这些有证据支持的实现、必要检查及 VPK 交付；并非对全游戏、所有硬件状态作出性能上限保证。用户明确由自己安装和采集，本轮未进入真机测试，也未运行 Vita3K。因此 r4 的实测毫秒与 FPS 收益留空，不用 host 检查代替设备结果。

## 为什么本轮先处理这些路径

r3 的 PC246 窗口 work=108.354 ms/帧，EndScene=87.092 ms/帧，加其余命名边界合计95.430 ms/帧。27 次重绘、19 次复用共46帧；231次 PS snapshot 全是 op19，81次 group scratch 未消除，着色器能力为0。对照 r2 208.331 ms/帧的观察差值，不能进一步分摊为各项独立收益。

这使 shader 可用性、删除实际多余 pass、收窄 GPU 等待优先于微调 CPU memcpy。589 B 的更新实际复制16 us、覆写等待57,001 us，须分别处理。资源方面，atlas 误回收有约775–780 ms NX 证据，CPU grade 8次累计3.749921 s；消息入口约0.8 s停顿尚缺分段归因，不凭猜测改脚本行为。

## 启动编译与缓存

包中编译器文件为 `sce_module/libshacccg.suprx`，1,776,523 B，SHA256 `0c58b5d3e1cc47d9837b8c59ab6f3c299bfe7adf55a83f547d553f9fbb776552`。它来自用户本机现有 Hazuki 依赖，保留于忽略目录供构建；没有放入Git。构建可用 `KNIFE_VITA_SHADER_COMPILER` 指定同一身份文件。

启动先查 `ux0:/data/knife-vita/shader-cache/`，缺少或校验失败才加载编译器；顺序18→15→17。缓存ABI3／入口ABI1，绑定完整Cg SHA、完整编译器SHA、程序字节与校验；旧ABI2不会被误用。写入失败保留本次成功的内存程序。命中全部程序时不加载编译器。

成功编译／缓存不等于GPU已经接纳；最终仍看反射、Register、所需输出patch及实际copy计数。失败或不适用的布局继续原snapshot/scratch。本轮不存在新设备GXP／像素验证结果，不把静态合同与ARM编译描述成真机画面已通过。

## 新日志如何作逐项对照

性能日志仍只经 `sceClibPrintf`，每五秒汇总。设备文件写入仅限已授权的启动shader缓存，release关闭DEV诊断文件写入。

- 新 `frame_classes` 分redraw/reuse/other记录work/update/render/wall、EndScene、显式等待、scene、PS/group copy等。wall在下一帧起点结算；该记录的`first_frame/last_frame`才是其区间，通常比当前sample末尾早一帧，不能机械拼到同一个audit分母。
- `worst`增加EndScene、atlas等待、实际重画/复用及复制细项。`end_*`十类互斥，使用同一时间戳，其和等于`end_scene`；各类不可再加总计。RAW/WAR/WAW可能重叠，不能把三类相加当等待scene数。
- 23个最大audit bank仍低于reader的32上限；每行继续编号分片与完整end marker。缺bank的窗口不推导delta；缺一窗后的累计差值不除以后一窗帧数。
- [00–14开关文件](../performance/profiles)保留旧0–10累加控制组，并补dependency-graph/source-rename/grade-cache/stream-index。`all`为默认65535。依赖图与rename要求batch-arena+async-submit；不合法组合拒绝启动，避免默测错组。无配置文件时默认全部启用；旧配置文件存在时按其内容选择。

新捕获可在电脑上运行：

```bash
python3 tools/read-vita-performance.py /path/to/r4-console.txt --console --environment hardware --out /path/to/r4-summary.json
python3 tools/render-audit/compare-hardware.py /path/to/r4-console.txt --item r4-all --scene 1 --pc 246 --out /path/to/r4-vs-r2.json
```

对照上轮可加 `--baseline doc/performance/captures/2026-10-31-r3/capture.txt`。双方实际具备分类数据时才计算类平均差；r2/r3无分类数据会明确返回unavailable。PC是窗口终点标签，不能代替相同输入轨迹；先比较实际每重绘copy／scene与能力，再评估同负载时间。

本轮所有P0–P6的设备提升字段继续为null。拿到新日志后，只填写可由分子／分母和控制配置支持的数值。
