# 2026-10-28 PS Vita 实机启动崩溃：GXM sRGB 输出修复

已定位本次启动崩溃，修正原生 GXM 离屏目标与 fragment shader 的输出配对，并重新构建正式版 VPK。当前结论是“根因有实机 core 与静态指令证据，修复通过主机回归及 ARM 构建”；**修复后的 VPK 尚未在 PS Vita 实机运行验收**。

## 实机异常如何发生

用户提供的异常地址为 `PC=0x811f5266`，系统报告 `Undefined instruction exception`。与此次崩溃对应的旧 ELF 已冻结保存，其 SHA-256 为：

```text
95743fc5ae2d52c85cad6e7389e02e4a31c8a835d1c72d7a2df765eb6a7dabbb
```

RX 段运行时基址为 `0x8100a000`，ELF 链接基址为 `0x81000000`，因此必须减去 `0xa000` 的重定位差，再清除返回地址的 Thumb 标志。不能直接把日志中的模块偏移当作 ELF 地址。

`0x811f5266` 映射到旧 ELF 的 `0x811eb266`，落在 newlib 的 `_kill_r` 中，实际指令为 `udf #255`。调用链包含 `abort`、Rust panic 中止路径。因此“未定义指令”是程序发生错误后主动终止的结果，不能据此认定编译器生成了 Vita 不支持的 ARM 指令。

进一步读取用户桌面的原始 `.psp2dmp`，解压 ELF core 后找到完整 panic 文本：

```text
creating Vita scene target: creating render target stage

Caused by:
    GXM: effects render target setup: 0x805b0003 (0x805b0003)
```

同时可恢复到 Rust 调用位置 `knife-render/src/vita.rs:1181:14`，对应初始场景离屏目标创建时的 `expect`。本次确定的触发点是 GXM 返回 `SCE_GXM_ERROR_INVALID_VALUE`，随后 `expect` 导致中止。现有证据不支持把这一启动异常归因于图片解码、纹理容量或 OOM。

原始 dump SHA-256 为 `98c3a585ac816cfe4192f1ab974d6a2b672b5f3cac426ae681b5886ceb66907e`；解压 core SHA-256 为 `982f19d87f06c2d8b9c4f2272baf354417d15dcb988f92d3d1fbb618591c781d`。文件与旧版 ELF/VPK 保留在本机 `.work/vita/hardware-crash-20261028/`。

## 根因与修正

旧版离屏目标使用 RGBA8 存储，启用了 sRGB gamma，却在 `sceGxmColorSurfaceInit` 中选择了 32-bit 输出寄存器。原生 GXM 对该组合拒绝设置 gamma，返回 `0x805b0003`。

对用户本地的已解密 `libgxm_es4.suprx` 做了静态检查，没有执行或修改系统模块。该样本中 `sceGxmColorSurfaceSetGammaMode` 位于 `0x810194a4`，调用 `0x8100bc4c` 查询颜色格式/输出寄存器组合的 gamma 支持位；表位于 `0x81021ad0`。RGBA8 对应 32-bit、64-bit 的表项分别为 `0x5`、`0x2a`，其第 5 位分别为 0、1。该约束也已加入主机 SDK 测试替身，旧配置可稳定复现拒绝。

修复的配对如下：

| 绘制目的地 | Color surface 输出寄存器 | Fragment program 输出 |
|---|---|---|
| sRGB 离屏 RGBA8 目标 | `SCE_GXM_OUTPUT_REGISTER_SIZE_64BIT` | `SCE_GXM_OUTPUT_REGISTER_FORMAT_HALF4` |
| 线性离屏目标 / 最终显示表面 | `SCE_GXM_OUTPUT_REGISTER_SIZE_32BIT` | `SCE_GXM_OUTPUT_REGISTER_FORMAT_UCHAR4` |

基础 quad、透明混合、离屏拷贝与全部 16 类特效的 9 种混合模式都按绘制目的地选择输出。shader program 缓存增加目的地输出模式这一维度，按需创建，退出时完整释放；切换目标时不会复用输出格式错误的 program。离屏初始化失败时保留最内层 SDK 错误信息。

修改位置为 `knife/vita/gxm_backend.c` 与 `knife/vita/effects_backend.inc`。**64-bit 指的是 GPU 输出寄存器，不是将图像存储改为 RGBA16F。** 480×270 画布仍按 RGBA8、每像素 4 字节储存，CDRAM 对齐后单张为 524,288 字节（512 KiB），画布、图片格式和内存预算均无需扩大。

本机此前使用的 Vita3K 实现没有执行与该原生格式表相同的 gamma 组合检查，这解释了旧包在模拟器中通过启动、却在实机被拒绝的差异。模拟器的 OpenGL/Vulkan 选项不改变 VPK 内直接调用 GXM 的事实。
