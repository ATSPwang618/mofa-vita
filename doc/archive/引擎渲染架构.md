## 0. 一句话结论

引擎（`knife`）完全不知道 Vita 存在：它只输出 **1920×1080 逻辑坐标**的 `Quad`。
平台层 `knife/knife-render/src/vita.rs` 把"逻辑→物理"的换算放在两处——**建目标时的 `div_ceil`** 与**顶点生成时的归一化**；放大交给 GPU 双线性采样。真正决定屏幕尺寸的只有 C 侧三个整数常量。

| 层 | 物理分辨率 | 决定位置 |
|---|---|---|
| 场景/特效链（stage、scene、blur、ghost、group、noise、menu blur） | **480×270** | `knife-render/src/vita.rs:33-34`、`:2288-2293` |
| 文字/UI 合成画布 | **960×540** | `knife-render/src/vita.rs:1216-1220` |
| 电影 | **960×540**（源 960×544 裁切） | `knife/src/movie/vita.rs:36-38` |
| 扫描输出 | **960×544** | `knife/vita/gxm_backend.c:14-15` |

## 1. 帧循环与提交管线

单线程、串行提交、软件节拍 60 Hz；无固定步长、无多帧并行、除 fence 外无异步。

## 2. 逻辑画布 → 物理目标：三个整数决定一切

1. 逻辑画布固定 1920×1080（`knife-render-api/src/lib.rs:5-6`）；Vita 覆盖 `RENDER_W/H = 480/270`（`vita.rs:33-34`），桌面/API 仍为 960/540（`lib.rs:7-8`）。
2. 建场景目标时按整数商缩物理尺寸：
   ```rust
   // vita.rs:2288-2293
   fn scene_size(w, h) -> [u32;2] {
       [w.div_ceil(CANVAS_W / RENDER_W).max(1), h.div_ceil(CANVAS_H / RENDER_H).max(1)]
   }
   ```
   ⇒ 1920×1080 的场景目标物理为 **480×270**（512 KiB，256 KiB 颗粒对齐）。
3. 合成目标单独写死"一半"：
   ```rust
   // vita.rs:1216-1220 —— 注释即产品说明
   /// Keep the expensive scene/effect chain at 270p, then draw text and UI at
   /// the display's 540p content size. Script coordinates remain unchanged.
   fn create_composite_target(w, h) { create_target_sized([w,h], [w.div_ceil(2), h.div_ceil(2)]) }
   ```
   ⇒ canvas 物理 **960×540**（2 MiB，测试断言 `vita_tests.rs:1304`）。
4. 顶点用**逻辑**尺寸归一化（`vita.rs:2228-2234`）：`pos = [x/tw*2-1, 1-y/th*2]`，`tw/th` 是 `target.tex.width/height` 即 1920×1080。光栅器自然写入 480×270。
5. 放大：`blit_target`（`vita.rs:1689-1697`）用铺满 canvas 的 `Blend::Opaque` quad 采样 scene 纹理；render target 以 `linear = true` 创建（`vita.rs:1233`）→ C 侧 `SCE_GXM_TEXTURE_FILTER_LINEAR`（`effects_backend.inc:197-199`）。2× 双线性权重 0.25/0.75 交替，**不取整、不做盒式平均**。
6. viewport 无 scissor（全仓仅 3 处 `sceGxmSetViewport`，零 `SetScissor`）：
   - 显示 pass `gxm_backend.c:399-400` `(480,480,272,-270,0.5,0.5)` ⇒ 只覆盖第 2..541 行，上下各 2 px 保持初始化时的 `0xFF000000`（`:236`）。**黑边就是这么来的**。
   - 离屏 pass `effects_backend.inc:289-290` 满目标。
7. 裁剪是 CPU 侧 Sutherland–Hodgman（`vita.rs:2251-2286`）+ soft-clip LUT（257×18 R8）。

> **脚本坐标本相**：脚本空间是 **480×272**（`knife/src/stage.rs:11-13`）→ 映射到 1920×1080（`stage.rs:18-20`）→ 压到 270 行。即 **272→270 有 0.74% 纵向压缩**，再补 2+2 px 黑边；原机是 480×272→960×544 整数 2×。

## 3. 纹理与显存

Vita 侧没有格式协商，只有三条路：**线性 RGBA8/R8**、**GXT 压缩块直通（PVRTC4/DXT1/DXT5）**、**AvPlayer YUV 直通**。全部进 CDRAM，预算硬编码在 C 侧，超限返回 `KV_BUDGET` 而不是降级。

```
Assets::upload_pixels                        knife/src/assets.rs:930-973
 └─ Renderer::upload_raw                     vita.rs:891-911（BC1/3/7 直接 bail）
     └─ make_texture_inner                   vita.rs:1798-1847
         ├─ native_allocation_bytes（pitch=(w+7)&~7，256 KiB 颗粒）
         ├─ reserve_cdram(peak, cache_growth) vita.rs:1867-1910（LRU 驱逐 deferred 图集）
         └─ kv_gxm_texture_create_ex         effects_backend.inc:173-220
             ├─ block_alloc(cdram)           gxm_backend.c:141-173
             ├─ sceGxmTextureInitLinear(A8B8G8R8 | U8_RRRR)
             ├─ SetMin/MagFilter(linear ? LINEAR : POINT)
             └─ srgb ⇒ sceGxmTextureSetGammaMode(BGR)
```

- 局部更新（字形、soft LUT）：`kv_gxm_texture_update`（`effects_backend.inc:271-284`），先 `sceGxmFinish`+`sceGxmTransferFinish` 再逐行 memcpy。
- 压缩纹理：`GxtTexture::parse` 严格校验 GXT v3（`knife-platform-vita/src/gxt.rs:49-110`），`sceGxmTextureInitSwizzledArbitrary` 直接拷块，**不解码成 ARGB**；上限 2048×2048、文件 ≤16 MiB。
- 当前生产包**不是 DXT 包**：PNG/JPEG 解码后创建 RGBA8。

### 3.1 预算

| 池 | 大小 | 位置 |
|---|---:|---|
| `CDRAM_LIMIT` | 64 MiB − 3 MiB(JPEG 预留) = **61 MiB** | gxm_backend.c:17-18、jpeg_hw.h:7 |
| 实际可用（减参数预留 16 MiB） | **45 MiB** | gxm_backend.c:147-149、214 |
| `MAIN_MAP_LIMIT` | **16 MiB** | gxm_backend.c:18 |
| 颗粒 | CDRAM 256 KiB / MAIN 4 KiB | gxm_backend.c:142 |
| 驻留缓存策略 | `DEFERRED_TEXTURE_BYTES`/`DEFERRED_SOURCE_BYTES` 各 **32 MiB** | vita.rs:43-44 |

超限链路：`block_alloc` 返回 `KV_BUDGET` → `reserve_cdram` 按 `last_used` 驱逐并重查 `kv_gxm_cdram_available`（`vita.rs:1878-1909`；C 侧取 `min(policy_available, kernel size_cdram)`，`gxm_backend.c:548-562`）→ 仍不足则 `bail!`，**该帧整体不提交**，`game.rs:6246-6251` 直接 panic。源码注释："Exceeding either limit is a reported error, never a partial frame submission"（`vita.rs:36-37`）。

### 3.2 驻留账（对齐后实测口径）

| 项 | 字节 | 备注 |
|---|---:|---|
| 显示 buffer ×2 | 2 MiB ×2 | 960·544·4 |
| canvas | 2 MiB | 960·540·4，测试断言 delta 恰 2 MiB |
| scene 目标 | **512 KiB/个** | 常驻 8~12 个（stage/scene/old/blur/ghost×2/group×3/menu/noise） |
| 字体页 | 1 MiB/页 ×2 | 1024² R8 |
| soft LUT | 256 KiB | 4 626 B → 1 颗粒 |
| **choice_text / choice_glow** | **8 MiB ×2** | `create_target(1920,1080)`，`choice.rs:698-700` |

> `choice_text`/`choice_glow` 是当前 CDRAM 账里**最大的单项**（16 MiB），也是"改分辨率前应先修"的第一项。

## 4. 图片解码

```c
// image_decode.c:543-559
PNG 签名 → decode_png()            // gray 1/2/4 → 8，GRAY/GRAY_ALPHA → RGB
FF D8    → kv_jpeg_hw_try() ? OK : decode_jpeg()   // SceJpeg 硬解优先，失败回退 libjpeg-turbo
```

- SceJpeg 硬解窗口：输入 ≤512 KiB、临时 CDRAM 预留 3 MiB、一次一个操作（`jpeg_hw.h:5-8`）；失败必须释放全部临时块且**不发布半成品**（`jpeg_hw.h:16-18`）。回退原因分类计数（`image_decode.h:33-42`）。
- 尺寸/预算上限：960×1080、encoded 32 MiB、工作区 4.25 MiB（`image_decode.h:7-11`）。
- 单线程 worker：`BoundedWorker::new(8, 2)`（pending 8 / ready 2，线程名 `knife-image`，`image_worker.rs:75-99`）；预取窗口 32（`image_worker.rs:9`、`vita_image_cache.rs:68`）；投机解码上限 encoded 2 MiB / RGBA 1 MiB（`assets.rs:131-133`）；每帧至多 1 个投机上传（`assets.rs:691-701`）。
- 预取策略（`game.rs:5956-6018`）：预览首项 → 3 个近未来动画时刻 → `pc..pc+24` 内 `STCH/SCH2` 变体名，`wanted.truncate(32)`。

## 5. 特效与着色器

16 个片元入口 × 9 种混合 × 2 种输出精度，全部**离线预编译**成 GXP 字节数组嵌入二进制，运行时只做 patcher。

- 生成链：`knife/vita/shaders/effects.cg` → `tools/compile-vita-effects.ps1` → `knife/vita/shaders/generated/effects.h`（179 KB，GXP magic `0x47585000`）。
- 初始化 `effects_initialize`（`effects_backend.inc:25-78`）：patcher（256 KiB + 64 KiB USSE + 1 MiB USSE）、注册 `vs_main` + 16 个 fs、校验 8 个顶点属性与 4 个 sampler。
- `effects_program(shader, blend)` 惰性 patch 并缓存 `[16][9][2]`（`effects_backend.inc:84-105`）；`output_mode` 由目标是否 sRGB 决定 `HALF4`/`UCHAR4`（`gxm_backend.c:117-119`）。
- **每 quad 一次 draw**：`uQuadHx/uQuadHy` 是每 quad uniform，无法批处理。
- render target 是**惰性附件**：首次 `begin_target` 才 `sceGxmCreateRenderTarget`，bake 后 `kv_gxm_texture_seal` 释放 attachment 只留像素（`effects_backend.inc:133-172`）。
- 呈现：`fs_present` = `srgb_encode(pow(rgb, 2.2))`（`effects.cg:307-315`），生产固定 shader 12 + blend 5（`effects_backend.inc:453`）。

## 6. 文字

**结论：文字本身已经是 540p 原生**，不是从 270p 放大来的。

- 页尺寸 `VITA_PAGE_SIZE = 1024`（`text/atlas.rs:5-6`），一页恰 1 MiB（`atlas.rs:69-72`）。
- 翻页：页满新建、旧页降为 `previous`；`get()` 先查当前页再查上一页（`atlas.rs:26-55`），保证排队中的旧 quad 仍能取到纹理。
- 光栅化基准 `BASE_SIZE = 40.0`（`text.rs:109`，`text.rs:388-419`）。
- 关键比例：60 逻辑 px 的字在 canvas 上占 **30 物理 px**，而位图是 40 px ⇒ **0.75× 缩小**，等效 1.33× 超采样。所以当前文字"够清晰"；要更锐应提高 `BASE_SIZE`（页容量按面积 ÷4，页仍 1 MiB）。

## 7. 音频

两个线程边界：**混音线程**（`knife-audio`，48 kHz / 960 帧一块）与 **AudioOut worker**（阻塞 `sceAudioOutOutput`，不占 GXM 线程）。

| 常量 | 值 | 含义 |
|---|---:|---|
| `FRAMES` / `SAMPLE_RATE` | 960 / 48 000 | 20 ms/块 |
| `QUEUE_BLOCKS` | 4 | 生产端 sync_channel 深度 |
| `POOL_BLOCKS` / `POOL_BYTES` | 6 / 23 040 B | 复用池，零分配提交 |
| `PRIME_BLOCKS` / `PRIME_TIMEOUT` | 2 / 40 ms | 启动预充 |
| `EDGE_FRAMES` | 128 | 欠载/恢复淡入淡出 |

欠载判定只在"活动流 + 已播过 + 非暂停 + 非结束"时计 `underruns`（`audio_output.rs:285-299`）；队列满在 producer 侧直接 `QueueFull`，不阻塞不分配。混音 clamp ±1 并统计裁切（`knife-audio/src/vita.rs:480-522`）。Opus 直连 libopus 静态库，强制 48 kHz（`vita_opus.rs:6-35`）。

## 8. 视频：唯一的 1:1 原生层

SceAvPlayer 产出 **`YVU420P2_CSC1`** GPU 纹理（`movie_gxm.inc:5-14`），不经 shader 做色彩转换，**不缩放，只裁切**。

```
movie_geometry::read_file  MP4 boxes → stsd/avcC → SPS → crop/visible/SAR   movie_geometry.rs:76-138, 238-282
movie_view::resolve        → VideoPresentation{visible_w/h, uv[4], aspect}    movie_view.rs:28-57
movie/vita.rs:33-44        断言 visible == 960×540 且 16:9 ±0.02
game.rs:3906-3915          Quad::rect(tex, [0,0,1920,1080]) + with_uv_rect(uv)
```

典型 `crop_bottom = 4` ⇒ `v1 = 540/544`：**960×544 编码 → 取 540 行 → 1:1 铺满内容区**。
硬上限 `KV_MOVIE_MAX_VIDEO_WIDTH 960`/`HEIGHT 544`（`movie_player.c:25-26`）。音频只接受 48 kHz 单/双声道 s16（`movie_player.c:580-581`）。

## 10. 读代码时值得单独记住的四件事

1. **本工程没有"960×540 内部分辨率"**：存在的是"270p 场景 + 540p 合成 + 544 扫描输出"。
2. **并非所有 UI 都是 540p**：Witch 专用多目标合成层仍用 `create_scene_target`（⇒270p）再放大——系统菜单 `ui/witch/menu.rs:385`、存读档 `ui/witch/save.rs:856`、音量/光晕 `ui/witch/sound.rs:798`、CG 转场 `ui/witch/cg.rs:751`、图鉴光晕 `ui/witch/archive.rs:884`。这与"540p 文字/UI"的口径有出入，是清晰度的真实短板。
3. **`savemedia` 不存在**：存档侧只有 `save.rs`/`savedata.rs`/`save_tables.rs` + 平台 `storage.rs`（`MAX_SAVE_BYTES = 8 MiB`）。
4. **`create_texture_ex` 上限 2048**（`gxm.rs:215`、`effects_backend.inc:176`），简单路径 ≤960 宽（`gxm.rs:138`）。960 宽刚好卡在简单路径上限。
