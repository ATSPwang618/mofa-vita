## 3. VPK 如何生成

没有自定义打包器，全部走 VitaSDK CLI：

```
knife.elf --vita-elf-create--> knife.velf --vita-make-fself -s--> eboot.bin
                                                            param.sfo --vita-mksfoex
eboot.bin + param.sfo + sce_sys/ + LICENSE --vita-pack-vpk--> knife-vita-game-270p.vpk
```

VPK 只有 8 个条目：`eboot.bin` 8,453,834 / `sce_sys/param.sfo` 912 / `icon0.png` 494 / `pic0.png` 1,523 / `livearea/contents/{bg.png 1,381, startup.png 650, template.xml 254}` / `LICENSE` 17,098。`eboot.bin` 是 SELF（magic `SCE\0`，`check-vita-package.py:47-48`）。

**title id 唯一真源**：`tools/build-vita.sh:83`。其余位置都是校验或复制：`check-vita-package.py:50-54`、`vita-build-receipt.py:60`、`verify-vita-release-270p.mjs:114`、`finalize_vita_audio_clarity.py:72,153`。

`check-vita-package.py` 额外断言：`APP_VER`、`ATTRIBUTE2=0`、release 时 `TITLE` 含 `270p` 且不含 `DEV`、LiveArea 三图必须是**索引色 PNG** 且尺寸 128×128 / 840×500 / 280×158。

## 4. 资源三件套

| 脚本 | 输入 | 输出 | 幂等性 |
|---|---|---|---|
| `create_270p.py` | `dist/…-540p-Compact-x64/assets` | `dist/…-270p-Vita/assets`：6 归档 + `<n>.270p.json` + `vita-270p-assets.json`(v1) | **条件幂等**（收据命中即复用；`.mrg` 已存在则拒绝） |
| `restore_vita_ui_clarity.py` | 540p 基线 `allui.*` + 当前 270p `allui.*` | 重写 `allui.mrg/hed`、`allui.270p.json`(v2)、manifest(v2) | **不可重跑**（staging 目录 `exist_ok=False`） |
| `generate_vita_asset_profile.py` | `assets/vita-270p-assets.json` | `knife/knife-platform-vita/src/asset_profile_270p.rs` | 确定性；`--check` 只比对 |

算法要点：

- `create_270p.py:71` 物理尺寸 `ceil(/2)`，**逻辑尺寸原样保留**；语言条带分别缩放（`:74-79`）；JPEG `quality=88, subsampling=2`，PNG 不量化；非图像条目原样搬运；未改文件用 `os.link` 硬链接（`:263-266`）。
- `restore_vita_ui_clarity.py` 目标 = `max(当前, min(基线, ceil(logical/2)))`，上限 960×540/条带（`:32-43`）；已经够密的小图**保留原编码字节**（`:69-73`），不从 270p 放大冒充恢复。

### 4.1 必须成套替换的四件

| 文件 | 生成者 | 内容 |
|---|---|---|
| `allui.mrg` | restore（重写） | NXCX 压缩的 KIMG/KATL 图集 |
| `allui.hed` | restore | `<IHH>` 扇区表 + 终止填充 |
| `allui.270p.json` | restore（v2，`ui-selective-native-half-v1`） | 每条目/每纹理的 before/physical/logical/strips/codec/sha |
| `vita-270p-assets.json` | create_270p(v1) → restore(v2) | 9,570 文件清单 + 6 归档统计 + `ui_policy` |

**为什么必须成套**：

1. VPK 内嵌 profile 钉住 `allui.mrg`（首尾 4 KiB CRC）、`allui.hed`、`allui.nam` 与**整个 manifest 的 CRC32**（`asset_profile_270p.rs:6,14-16`）⇒ VPK 与 manifest 必须同批产出。
2. manifest 又钉 `allui.270p.json` 的 sha256 ⇒ 少换一件即清单不符。
3. 启动校验 `asset_check::check_assets`（`vita_entry.rs:167`）：**37 条 FileSpec、只读 4,110,058 字节、单缓冲 8192 B**，失败进 `boot_error`。

当前资源身份：9,570 + manifest = **9,571 文件**、**1,981,353,024 B**；6 归档 / 33,898 条目 / **34,847 纹理**；238 张恢复、805 张原字节。

## 7. 已知坑（逐条）

1. **缓存路径污染**：`KNIFE_VITA_CACHE` 复用会让 `CMakeCache.txt` 记住旧源码绝对路径；换目录重建必须给独立缓存。
2. **输入身份门禁**：`create_270p` 比对源 mrg 与 540p 审计；`restore` 比对 540p 基线与现有四件；`generate` 比对 manifest 全量 sha；`vita-270p-assets.mjs` 逐文件 sha。手改任何字节都会硬失败。
3. **不要二次缩小**：源必须是 540p 基线；`restore` 在已达原生密度时保留原始编码字节。
4. **`restore` 不可重跑**：`.work/vita/audio-ui-clarity-20261028/{staged-assets,previous-assets}` 用 `exist_ok=False`。
5. **拒覆盖是设计**：`package_vita_270p`、`create_270p`、`package_project` 都拒绝覆盖既有产物。
6. **改资源必须重跑 profile 并重建 VPK**：profile 通过 `include!` 编进二进制（`asset_check.rs:61`）。
7. **写死计数**：`stream == 9470`（`generate:39`）、34,847 纹理、182 源文件、238/805。资源稍变即断言失败。
8. **硬链接共享**：`create_270p` 对未改文件 `os.link`，就地编辑会污染 540p 基线；`vita-270p-assets.mjs` 用 `dev+ino` 拒绝。
9. **`--offline --locked`**：加依赖需先在线更新锁文件。
10. **用户绝对路径混入脚本**：`finalize_vita_audio_clarity.py:135,154` 引用桌面与私有 checker 路径，换机复现前必须替换。
11. **`python3`（WSL）与 Windows `python -X utf8` 是两条链**。
12. **dist 的 `eboot.bin` 不是脚本自动复制的**：`finalize` 只复制 VPK；复现时别漏。
13. **过时脚本别照抄**：`write_vita_270p_delivery.py` 断言 `physical_canvas == [480,270]`，与当前收据冲突（v2 时代产物）。
