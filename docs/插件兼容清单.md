# 插件兼容清单

本清单维护当前注册名称、实现入口和已知差异，按插件归属组织，不记录开发批次。

本清单记录已经接入、正在尝试兼容，以及用户明确指定但尚未接入的插件。目标是支持大部分游戏所需的实际行为，保持跨平台，并以 PSV 流畅运行为约束；不追求复刻所有历史操作系统接口。

整体职责与资源寿命见[软件设计与架构](软件设计与架构.md)。表内状态保留已有实现记录，真实游戏效果需要独立验证。

## 统计与状态口径

- 默认 PC 插件组保留 **61 个已注册的 DLL 兼容目标**，每个名称都有对应 `.tpm` 入口；`.dll` 与 `.tpm` 不重复计数。
- 已注册目标包含共享实现、引擎类映射和仅加载兼容，**不表示 61 个插件已全部完成行为对齐**。例如 `motionplayer.dll` 与 `emoteplayer.dll` 共用一个提供者。
- 已注册清单之外，`binaryStream`仍是独立待实现目标。
- Vita 不启用可选的 `sqlite` 特性：SQLite 默认 VFS 所需的 Unix 接口尚未适配。其余注册名称不等于 Vita 绘图能力已全部接入；当前已通过完整引擎/GLES2 链路验证 extrans 的七种转场，扩展绘图与真机性能状态见架构文档。

| 状态 | 本文件中的含义 |
|---|---|
| 已有实现 | 已注册且有业务实现；不等于逐 API、全部输入和全部游戏均已验证 |
| 平台适配 | 已注册，通过共享引擎/宿主实现实际能力；平台支持与旧接口差异仍需分别判断 |
| 共享实现 / 引擎类映射 | 入口复用已有提供者或引擎类，不重复计算一套实现 |
| 仅加载兼容 | 明确只保留参考中的空表面；不能视为实现了插件名字所暗示的功能 |
| 弃用兼容 | 保留约定的脚本行为，不提供已排除的旧原生机制 |
| 未接入 / 待判定 | 尚无同名插件注册，不能因为有相邻引擎能力就标记完成 |

## extNagano 转场

注册 `3duniversal / blurfade / scanline / zoomfade / rgbfade / spin / flutter / book / imagewipe / honeyturn / morphing / multiripple`，`.dll` 与 `.tpm` 共用提供者。参考 wamsoft/extNagano 的公开还原版（4b403e2）；以效果可用和跨平台性能为目标，不承诺与原 x86 DLL 逐像素一致。

- 共用引擎的 time、自更新、时钟 callback、取消、完成换页及插件寿命管理。活动转场或排队帧未释放时不能卸载插件。
- `imagewipe`、`3duniversal` 的 rule 支持资源名或 Layer 快照，RGBA 规则只加载一次，不转成灰度。像素处理留在 GPU，查找表及临时纹理使用现有预算。
- 旋转按列预计算；morphing 支持 before/after 数值 Array，最多 256 个三角形，CPU 按行解析覆盖范围，GPU 二分查找，避免每像素遍历全部三角形。零面积三角形按未覆盖区域处理，越界采样限制在图像内。
- flutter 使用斜向折页、背面着色、透明度和阴影近似；honeyturn 使用六角形分区及方向顺序；multiripple 使用固定的分散波源与近似波形/时间分布，callback 使用引擎统一的时钟接口。
- 3duniversal 支持 RGB/HSB 规则、速度/加速度及短别名、反弹参数。GPU 逆向采样近似原来的正向像素散布，遮挡重叠和空洞边缘可能不同。
- blurfade 保留横纵模糊量、指数、type、prerender 参数。type=0 使用固定 5×5 采样近似平均模糊，type=1 为粗网格插值；prerender=1 按需计算，避免在 PSV 缓存大量整屏帧，prerender=2 采用间隔为 2 的半径档位。

`tests/fixtures/nagano.tjs` 覆盖 12 种实际桌面 GPU 效果及换页/寿命；GLES 测试比较单纹理和分块纹理结果，包括模糊跨块邻域。这些不等同于 PSV 实机性能或整部游戏通关验证。

### 解析、编码与旧平台差异

- **expat**：使用 quick-xml 词法读取并适配原版非命名空间模式；构造目标、调用目标及实例自身回调遵循原优先级。parseStorage 经 VFS 和 IO 队列读取 UTF-8，回调回到同一 VM；加载和解析取消会释放状态，不吞回调异常。支持普通/默认/展开默认处理器、实体引用及内部标记替换、CDATA、注释、PI、DTD 内部实体与默认属性。原注册名是 `currentByteCount`，手册的 `currentButeCount` 是笔误。
- **XML 边界**：输入与累计实体展开各限 16 MiB、元素深度 256、实体深度 16，属性/实体集合有限；位置逐步计算，不按每一行分配索引。未完整复刻 Expat DTD 语法校验、参数实体展开和全部错误码/精确报错位置；外部实体不访问网络或系统文件。默认回调和文本分块可以不同，实体内位置不保证逐字一致。这是已有解析能力的具体差异，不再是空插件。
- **qrcode**：按源码支持版本 0 自动或 1–40 固定/扩容，纠错不会擅自升级，指定掩码为 0–7，-1 自动；空内容/容量不足/越界选项返回原错误字符串且不改变图像。成功只调整图像尺寸并写入不透明黑白像素。编码后端为 [qrcodegen 1.8](https://docs.rs/qrcodegen/1.8.0/qrcodegen/struct.QrCode.html)；不复刻原窄字符缓冲区截断，非 ASCII 使用 UTF-8 ECI，分段/自动掩码与原 Psytec 编码器不保证逐模块相同。
- **fftgraph**：按原 Ooura DST 定义用 RustFFT 计算，不引入原 C/Win32 代码。频谱状态在每个引擎内共享；不足 2048 个样本时整窗清零。保留两种样式的频带、颜色、回落和峰值时序；LCD 不整除的边缘保留原像素。非法尺寸/除数明确报错，单图至多 4096×4096 且总像素不超过 4194304。CPU 负责固定长度变换和局部图样，GPU 负责上传后的区域复制，省区图保留；尚无 PSV 真机帧率结论。
- **旧平台兼容**：注册表和 OLE/ActiveX 按无原生能力路径提供表面，不将不可用标记为执行成功。依赖系统安装信息、COM 自动化或 ActiveX 浏览器作为唯一玩法入口的作品仍不兼容。krmovie 的名字可加载，但不代表原 DirectShow 特有控制和过滤器已对齐。


### minizip 的实现范围与差异

- 依据原版 main.cpp（原版源码参考）、storage.cpp（原版源码参考） 和 manual.tjs（原版源码参考） 接入全部公开方法。读入源走 VFS；压缩、解压和打开归档使用已有 IO 队列，写入目标为宿主本地可写文件。
- 写入支持创建、覆盖、追加、压缩级别 0–9/默认级别，以及传统 ZipCrypto 密码；非字符串密码按原版忽略，空密码按原版空窄字符串行为不加密。追加保留已有条目的密码及压缩标志。
- `Unzip.list` 返回原版字段及 Date 对象，尺寸/CRC 保留原接口的 32 位整数转换。域名区分大小写，文件查找沿原 Windows 参考采用 ASCII 不区分大小写；挂载失败先移除旧挂载。卸载后已有流/读计划和 Unzip 对象仍持有资源，旧挂载函数不能重新激活已卸载的介质。
- 流按需解压、独立游标；向后 seek 重启该条目的解码器，不保留整份解压结果。目录分配前检查索引数量和字节预算，条目/输出及挂载集合沿宿主存储预算限制；压缩和解压按 16 KiB 块检查取消。
- 跨平台文本采用逐条目 UTF-8 标志，无标志文件名及密码采用 CP932；不依赖宿主 ANSI 代码页，也不复刻原版以首条目决定整个包编码的缺陷。CRC/截断失败不会伪报解压成功，提取失败保留已有目标文件。
- **已知差异**：ZIP 后端不支持写入重名条目（`Zip.add` 返回 false）；读取已有重名包时同名条目由后端合并，不能保证原版的逐条列举/首条匹配行为。输出不支持脚本自定义的可写存储介质。以上不标成全部输入均已对齐，也不把未做的原版运行差分或 PSV 真机性能计作通过。

## 文件转换、图像与转场差异

以下保留原兼容记录中影响使用的差异，具体参数以对应实现入口为索引。

- **base64**：`Base64.encode` 读取 VFS 文件；未找到返回 void，丢弃结果时不读取文件。`decode` 实际写入目标，只有需要结果时计算 MD5；采用旧查表规则而不是跳过空白。空串输出空文件，非法末组或超范围码元受控报错，取消可留下已写入前缀。
- **extrans**：提供 wave、mosaic、turn、rotatezoom、rotatevanish、rotateswap、ripple 七种转场。ripple 沿参考便携 C 路径插值 RGB、输出 alpha 为 0，与原 MMX 路径有差异；效果需要宿主支持相应内核。活动方法、转场和在途帧持有卸载租约。算法及表格许可位于 [extrans](../crates/krkr-plugins/src/extrans/LICENSE.txt)。
- **layerExImage**：六个 Layer 方法使用公共图像处理路径；与内置 doBoxBlur、layerExFilter 和 filter 分开，不按相近名称替换算法。
- **layerExMovie**：复用引擎视频服务和有序图像写入，媒体格式与播放能力取决于已安装后端。
- **layerExSave**：保存和像素工具使用整个主图，不自动 update；`isBlank` 沿参考只检查蓝通道，`getAverageColor` 返回旧顺序 0xBBGGRRAA。PNG 编码字节流不保证与旧编码器一致，TLG 标签统一 UTF-8。后台保存使用快照图层，cancel 保留完成通知，stop 撤销通知；IO 失败进入标准异常路径。部分查询/修改仍使用有预算的 GPU 读回与 CPU 分片算法。许可位于 [layer_save](../crates/krkr-plugins/src/layer_save/LICENSE.txt)。

## 魔法使之夜效果插件

依据用户提供的原DLL静态核对，不把旧patch.tjs空方法作为行为标准。`layerExYADraw.dll`提供`Layer.YAdrawLine(x0,y0,x1,y1,color=0xff000000,antialias=1,fade=0)`和`drawFocusLines(cx,cy,cmin=50,cmax=100,lmin=25,lmax=50,emin=2000,emax=2000,color=0xff000000)`：c为内半径、l为线条数、e为外半径，fade为渐隐距离。保留原整数线栅格、16.16抗锯齿及原clip包含端点的规则；同次调用一次GPU命令，分块索引缩小每个像素需要检查的线段数。渐隐不解释成线宽。

`layerExFilter.dll`提供以下五个Layer方法。它与`layerExImage.noise/light`、`filter.dll`全局函数分别注册。

- `drawNoise(monocro=true,under=0,upper=255,seed=System.getTickCount(),left=0,top=0,width=realWidth,height=realHeight,holdalpha=false)`：保留LCG常量、行内打包/尾部推进和各分支Alpha规则；不按帧数替换seed。GPU直接生成，不保留Alpha时不复制目标图片。
- `doContrast(level=0)`：限制到[-127,127]，按原256项整数映射修改RGB，保留Alpha。
- `initHazeCopy(slot,wavesX,wavesY,powers)`：每个引擎独立十个槽位；每轴最多32组[频率,相位,幅度]，默认X为[[1,0,1]]，Y缺省关闭。每表16384个固定点样本，由后台队列生成并计入现有预算。原DLL条件始终选择空槽，传入slot不复用旧槽；须保存返回值并显式释放。无结果接收者、槽位已满报错。
- `uninitHazeCopy(slot)`：释放对应槽位，返回是否释放；无效/空槽返回false，缺参数报错。
- `hazeCopy(slot,source,sleft=0,stop=0,rad=0,delta=7,per=10,linear=true,dleft=0,dtop=0,dwidth=realWidth,dheight=realHeight,boundWidth=realWidth,boundHeight=realHeight)`：原整数相位/位移、首尾行限制和可选水平8位插值，直接复制RGBA；linear不是透明混合。整次效果只提交一批逐行映射，无CPU图像读回。

原DLL的hazeCopy入口会释放powers，故该二进制的强度曲线不参与绘制；此行为已据初始化/绘制共同调用的0x10012120核对。合法源图内跨行地址按原规则读取；越界地址裁剪、单行只写一行，不重现越界内存读写。源目标同图时GPU使用采样快照，不保证原CPU就地覆写的反馈顺序。浮点正弦/三角函数不承诺与x87逐位相同；默认参数、整数及GPU实现仍需游戏实测。PSV绘制宿主尚未实现，这些公共协议不等于已经通过PSV性能验收。

`filter.dll`已独立注册全部14个全局函数：`Smudge`、`Blur`、`Lens`、`InitLens`、`ReleaseLens`、`Noise`、`Contrast`、`initHaze`、`doHaze`、`endHaze`、`Stretch`、`Vortex`、`fillXor`、`dithering`。图层/选项通过普通属性读取；Lens表及热浪槽属于当前引擎，初始化/释放均有实现。Smudge/Blur按原八邻域多遍处理，Blur的非零type保留原不改像素行为；Noise采用该DLL自己的LCG和打包/尾部/Alpha规则。Stretch保留`opa`、默认源尺寸减一及缩放采样分支；Lens/Vortex/热浪走GPU，波形表由已有后台队列生成。fillXor/dithering保留原像素写入忽略top而update仍报告请求top的差异；原极小尺寸失控循环和越界地址不复现。源目标同图采用受管快照；GPU浮点、三角函数与原x87不承诺逐像素相同。

`layerExParticle.dll`已注册27个方法、53个属性和4个类型常量，四类模式均有业务实现：Vector、Rotate、AccelRotate、Blink。`init*Particle(start,max,rate,...)`建立图层独立状态，`updateParticle(dt)`按毫秒推进并生成/回收粒子；区域、中心、18组范围的成对setter及min/max属性、数量/类型/生成率、反转、operateMode、图集和初始化器均已接入。原拼写`Varidation`保留；`RotateOmegaMax`、`BlinkMax/Time/Count`等别名共享对应数值字段。Angle/AngleOmega的单独属性setter不重算已缓存的随机范围宽度，成对setter重算，遵循原DLL区别。保留共同存活条件及Blink计数虽保存却未参与原死亡判定的行为。

`particleImage`引用实际Layer，以`tag`（缺失时`orgTag`）的`divideArea`读取图集，支持四整数数组的数组及斜杠分隔字符串。`particleInitializer`在同一VM内以目标Layer为this调用：Vector/Rotate返回7项、AccelRotate返回8项、Blink返回5项。数值布局沿原模式读取，Blink第4项是直接透明度变化率。默认路径不逐粒子往返VM；自定义回调才进入续体，异常照常传播。随机生成器使用原LCG及消耗顺序，当前引擎首次更新以受管tick计数初始化，因此不保证与原DLL加载时seed相同。

绘制读取`afx/afy/left/top/zoomx/zoomy/rotate`，缺省锚点取底层图片中心，Layer旋转为度、粒子角度为弧度；按原槽位倒序、最近邻采样与半像素坐标绘制，先清除上次粒子区域。整批使用Sprites协议，GPU按32×32区域索引处理有序矩形与图集，复用引擎整数混合函数，不为每个粒子分配纹理或读回像素。数值状态、图集、清除区域和提交数据使用现有预算；图像处理按实际图片尺寸，独立于Layer显示尺寸。

明确适配差异：`assignParticle`完整深拷贝模式参数、运动状态、图集及脚本引用，图像仍是受管引用；原DLL只复制基类字段并留下派生运动内存未初始化，不复制该缺陷。`uninitParticle`释放持有的引用与预算；负容量明确报错，缩容能回收年龄为零的粒子。源目标图集同图使用帧前快照，无法复现CPU逐次覆写的反馈顺序。以上插件经过编译、Clippy与WGSL静态检查，尚未进行游戏或原DLL动态差分，不标为效果完全一致或PSV可运行。

旧补丁中的粒子空方法、近似滤镜和空集中线可能覆盖原生实现。使用原生插件时应避免这类重复替换；游戏专用解密仍由独立 xp3filter.tjs 提供。
